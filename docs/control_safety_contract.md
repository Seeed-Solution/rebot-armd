# Control and safety contract / 控制与安全契约

## Scope / 范围

This document describes the software contract visible in the current source tree. It is not a hardware acceptance report. No physical arm test is claimed; behavior also depends on a trusted control network, correct wiring, fresh telemetry, and an external emergency-stop circuit.

本文记录当前源码可验证的软件契约，不构成实物验收报告。当前未进行实物测试；行为还取决于可信控制网络、正确接线、新鲜遥测和外部急停回路。

## Control path / 控制路径

- Observation remains available through `GET /api/v1/observation` and its schema endpoint.
- Actuator authority belongs to the WebSocket connection that acquires the lease. Use `acquire_lease`, then periodic `heartbeat`, then strictly increasing `request_id` `command` messages carrying `generation` and the current `epoch_id`.
- A successful command returns `command_ack`; lease loss, stale epoch, missing generation, or safety rejection returns `command_reject`. `estop` is accepted without a lease and advances the safety epoch.
- REST actuator routes (`torque`, `heartbeat`, `motion/*`, and `clear_fault`) return a structured lease error and do not execute the action. This is intentional: a caller-supplied client ID cannot prove WebSocket connection ownership.
- Every observation carries `lease_holder`: the `client_id` label the current holder sent with `acquire_lease` (empty string when it sent none), or `null` when no valid lease is held. It is informational; authority stays with the connection.
- Operator session of a socket: the `Authorization: Bearer` header or `rebot_op` cookie of the upgrade request, replaced at any time by `{"type":"auth","token":<token from POST /api/v1/auth/unlock, or null>}`, answered with `auth_ack` (`role`, `auth_enforced`, `expires_in_s`). The token is checked on every privileged command, so expiry and `auth/lock` take effect on open sockets. The cockpit uses it after unlock and lock instead of reconnecting, which would drop the lease (`tests/test_operator_auth.rs` `ws_auth_message_switches_the_operator_session_without_reconnecting`).
- A voluntary `release_lease` (or closing the socket) while torqued stops motion, and then the lease watchdog runs as for an expired lease: after `lease_timeout_ms` without an owner's heartbeat the arm parks at the resting pose and cuts torque, or holds and latches `Fault(WatchdogTimeout)` (`tests/test_watchdog_park.rs` `released_lease_while_torqued_parks_the_same_way`). The cockpit therefore releases an idle lease only when torque is off (see "Cockpit lease" in the README).

- 观测通过 `GET /api/v1/observation` 及 schema 接口提供。
- 执行器权限属于取得租约的 WebSocket 连接。流程为 `acquire_lease`、周期性 `heartbeat`、带 `generation` 和当前 `epoch_id` 且 `request_id` 严格递增的 `command`。
- 成功返回 `command_ack`；租约丢失、epoch 过期、缺少 generation 或安全策略拒绝时返回 `command_reject`。`estop` 不需要租约，执行后会推进安全 epoch。
- REST 执行器路由（`torque`、`heartbeat`、`motion/*`、`clear_fault`）返回结构化租约错误，不执行动作。
- 每帧观测带 `lease_holder`：当前持有者在 `acquire_lease` 中发送的 `client_id` 标签（未发送时为空字符串），无有效租约时为 `null`。仅供显示，权限仍属于持有连接。
- 连接的操作员会话：取自升级请求的 `Authorization: Bearer` 头或 `rebot_op` cookie，可随时用 `{"type":"auth","token":<POST /api/v1/auth/unlock 返回的 token，或 null>}` 替换，回复 `auth_ack`（`role`、`auth_enforced`、`expires_in_s`）。每条特权命令都会重新校验 token，过期和 `auth/lock` 对已打开的连接同样生效。驾驶舱解锁和锁定后用它代替重连（重连会丢失租约）。
- 力矩开启时主动 `release_lease`（或关闭连接）会先停止运动，之后按租约过期处理：`lease_timeout_ms` 内没有持有者心跳时，机械臂回到停靠位并断力矩，或保持位置并锁存 `Fault(WatchdogTimeout)`。因此驾驶舱只在力矩关闭时释放空闲租约。

## Driver capability boundary / 驱动能力边界

The observation fields `driver_capabilities`, `enable_state`, and `feedback_valid` are authoritative. `Unknown` means that fresh hardware confirmation is unavailable; it is not equivalent to `Disabled`. The bundled drivers declare different feedback and enable capabilities. In particular, Damiao default `POS_VEL` does not send gravity torque feed-forward; gravity output requires MIT capability and the configured gravity model. The gravity-compensation mode below switches J1–J6 to MIT only while it is on. The source does not claim four physical driver integrations have been accepted.

观测中的 `driver_capabilities`、`enable_state`、`feedback_valid` 是实际边界。`Unknown` 表示没有新鲜硬件确认，不等于 `Disabled`。各驱动反馈和使能能力不同。达妙默认 `POS_VEL` 不发送重力力矩前馈；只有 MIT 能力和重力模型均满足时才允许重力输出。下文的重力补偿模式只在开启期间把 J1–J6 切到 MIT。源码不宣称四款驱动已完成实物验收。

When enable confirmation is unavailable or remains `Unknown`, automatic disable, fault clearing, and service exit are rejected; this includes the non-Damiao drivers whose `enable_feedback` capability is false. The API remains available for observation and recovery decisions. Normal stop holds the commanded/measured pose and does not home the arm or force-kill the service. Ordinary `home` remains a motion command; automatic `unload`/park is rejected before planning when `supports_automatic_unload` is false.

当使能确认不可用或仍为 `Unknown` 时，自动失能、清故障和服务退出会被拒绝；这包括 `enable_feedback` 为 false 的非达妙驱动。API 保持可用以便观测和恢复决策。普通 stop 保持当前指令/测量位置，不回零，也不强杀服务。普通 `home` 仍是可用的运动命令；当 `supports_automatic_unload` 为 false 时，自动 `unload`/park 会在规划前拒绝。

## Timing and calibration defaults / 时序与标定默认值

- The control loop has an 80 ms overrun/stall protection deadline; a late tick latches a safety hold instead of advancing an old trajectory.
- Separately, the Damiao enable handshake polls for up to 80 ms for confirmed motor state.
- Feedback freshness checks use a 250 ms limit in the supervisor and bundled serial/CAN drivers.
- `FollowingErrorPolicy` defaults to `max_error_rad = 0.5` and `persistence_ms = 500`.
- The Damiao profile sets `max_jerk = 50.0`; it is a soft preference and does not override braking or position limits. Other default profiles leave it unset.
- These are software defaults, not measured industrial timing guarantees.

- 控制循环有 80 ms 的超期/停滞保护期限；tick 过晚时锁存安全保持，不继续推进旧轨迹。
- 另有独立的达妙使能握手确认轮询上限 80 ms。
- supervisor 及内置串口/CAN 驱动的反馈新鲜度上限为 250 ms。
- `FollowingErrorPolicy` 默认 `max_error_rad = 0.5`、`persistence_ms = 500`。
- 达妙 profile 设置 `max_jerk = 50.0`；这是软偏好，不覆盖制动和位置约束，其他默认 profile 不设置该值。
- 这些是软件默认值，不是工业时序保证。

## Planned speed, workspace and actions / 规划速度、工作空间与动作

- `planned_max_velocity` (rebot-dm 0.45 rad/s, default unset) caps every joint except the 7-DOF gripper for planned motion: jog, home, presets, park (including watchdog park) and high-level actions. It keeps the Damiao POS_VEL lag (≈ v / 1.5 rad, `POSVEL_LAG_GAIN`, measured 2026-11-09: J3 trailed 0.458 rad at 0.7 rad/s) below the 0.5 rad following-error bound; `validate()` rejects a cap whose expected lag reaches the bound. Servo streaming has its own speed and lead caps (see "Servo streaming guard" below); stream braking keeps the joint limits.
- `speed_cap` (optional profile section, `linear_mps`, `angular_rps`, `joint_velocity_scale` in (0, 1]) lowers planned motion further: Cartesian actions use min(request, cap); the joint speed cap above (or the joint limit when `planned_max_velocity` is unset) is multiplied by `joint_velocity_scale` for every joint except the 7-DOF gripper, for jog, home, presets, park and actions. It is not changeable at runtime and is published as `schema.speed_cap`.
- The watchdog park budget is max(10 s, deceleration + planned park duration + 0.8 s settle hold + 3 s), counted in control-loop time; see "Unload settle" below.
- The tracking-error fault names the joint: `Persistent joint tracking error: joint N cmd … meas … rad`. Observations carry `commanded_positions`.
- `observation.fault` is null, or `{code, message, recoverable}` while the state is Fault or EStop; each trigger site records its code through the single `SafetyManager::latch(kind, detail)` entry point (`FOLLOWING_ERROR` for the tracking fault, `CONTROL_DEADLINE` for a tick later than 250 ms, `WATCHDOG_TIMEOUT`, `BUS_LOSS`, `THERMAL_TRIP`, `INVALID_TELEMETRY`, `DRIVER_WRITE_FAILED` for a failed output write or an unconfirmed torque disable, `HARDWARE_FAULT`, `ENABLE_FAILED`, `SERVO_NO_BRAKE`, `HANDOVER_UNSETTLED`, `GRAVITY_COMP_FAILED`, `COLLISION` (collision guard escalation), `ESTOP`, `JOINT_LIMIT`, `OTHER`). Every detector calls `latch` unconditionally (never skipping when another fault is already active), every latch (new kind or repeat of the same kind, including E-stop) advances `epoch_id`, and the fixed-size record keeps every latched kind until `clear_fault` resets it all at once for the exact current epoch.
  - **Fault severity order** (highest to lowest, governing `observation.fault.code`, `observation.fault.message`, and displayed `SafetyState`): `ThermalTrip` > `BusLoss` > `CollisionLatched` > `JointLimit` > `Other` (non-recoverable codes) > `Estop` > `Other` (recoverable codes: `CONTROL_DEADLINE`, `HANDOVER_UNSETTLED`) > `WatchdogTimeout`. Diagnostic hardware/safety faults keep display precedence over `ESTOP` so the operator retains visibility of the underlying hazard while `ESTOP` stays latched in the record (enforcing `recoverable = false` and two-stage clear `Fault -> EStop -> Idle`); `ESTOP` outranks recoverable faults.
  - **Recoverability (`SafetyManager::recoverable`)**: worst-of across the entire latched record (including sticky non-recoverability across multiple `Other` details) — true only when every recorded kind and detail is recoverable (`WATCHDOG_TIMEOUT`, `CONTROL_DEADLINE`, `HANDOVER_UNSETTLED`). Observation, WebSocket operator-auth gating, and recovery paths all consult `SafetyManager::recoverable()`; clearing a fault still requires `clear_fault`.
  - **Clear gate (`SafetyManager::clear_check`)**: every clear path (legacy `clear_fault`, RT executor `clear_fault`, MIT expiry recovery, and E-stop clear) evaluates `SafetyManager::clear_check` FIRST before any motor reset or other side effect (a motor fault reset is permitted only after every other recorded kind's condition passes, followed by re-evaluating `clear_check`; MIT expiry recovery evaluates its final check on feedback received after recovery). Every recorded kind is evaluated, failing closed on any unknown kind bit:
    - `ThermalTrip`: below `max_temperature - THERMAL_CLEAR_MARGIN_C` for the required cooldown duration; cooldown accrues only while temperature feedback is fresh, and stale or unavailable temperature feedback resets the cooldown timer.
    - `BusLoss`: fresh feedback from every motor.
    - `WatchdogTimeout`: fresh heartbeat from the active lease holder, or no active lease (an expired lease counts as no lease).
    - `JointLimit` (manual recovery when out of limits): measured joint positions must be back within `[min - 0.01, max + 0.01]` rad (`JOINT_LIMIT_CLEAR_MARGIN_RAD`), with no driver limit conflict. Even with torque off when the arm rests beyond a soft limit plus `0.01 rad`, armd does not allow a software clear that could subsequently enable at an out-of-limit pose; `clear_fault` keeps refusing and the refusal message names the offending joint, its measured position, and its configured limits so the operator knows to move it back within limits by hand before retrying `clear_fault`.
    - `CollisionLatched` / `Estop` / `Other`: fresh feedback, fault-free hardware status, and known enable state.
- `observation.residual_torques` (J1..J6 measured torque minus the gravity model at the measured pose) is published when the profile has a gravity model and the driver reports torque; the model is evaluated every tick regardless of gravity output. The residual itself raises no fault; the collision guard (below, off by default) uses it.
- Cartesian workspace (`workspace` + `kinematics`; applies when the profile has at least `arm_dof` joints, the arm joints of its kinematic model: 6 for the built-in model, the chain's joint count for a URDF chain): the end_link origin, the 8 gripper-envelope corners and the optional camera point must stay above `floor_z_m`, inside the box and within `max_reach_m` of the shoulder axis. A servo target, or any of the 21 planner samples of a jog / home / preset, is rejected with `422 WORKSPACE_VIOLATION` when it violates and is worse than the start; moving out of a violation is allowed. Park is exempt from the floor, box and reach limits (only logged) but not from keep-out boxes: a park whose path enters a box is not started; an explicit park returns `WORKSPACE_VIOLATION`, a watchdog park holds position and latches `WATCHDOG_TIMEOUT`. Keep-out boxes (`workspace.keepout_boxes` plus the runtime list from `/api/v1/workspace/keepout`, at most 16 in total; the runtime list only adds boxes) are part of the same rule: the depth of a check point inside a box counts as a violation, reported as `keepout '<name>'`. With keep-out boxes, joint-space trajectories and servo / braking steps get a conservative sweep check: over an interval each check point moves at most L = sum over arm joints of (bound on the joint's travel) x (link lengths from that joint to the tip plus the largest check-point offset); the interval is clear when, for every point and box, the Euclidean distances to the box at the two ends sum to more than L, else it is split at its midpoint (an interval with L <= 0.1 mm is accepted, the depth tolerance). A trajectory may add at most 4000 FK evaluations (else `WORKSPACE_VIOLATION`), a servo or braking step at most 64 per tick (else the recoverable hold). Boxes a check point is already inside at the start keep the sample rule (moving out is allowed). The schema publishes `workspace` (with the boxes in force) and `camera_mount`. A `--config` profile without these fields runs without the check and logs a warning at startup.
- Actions (`docs/agent_action_api.md`): `move_to`, `move_relative` and `gripper` over the WS lease; every observation carries `action`. Servo frames during an action return `409 MOTION_BUSY`. Action paths slow down when lag exceeds 0.38 rad and end as `TRACKING_STALL` after 1 s at 0.45 rad, so a blocked action path ends before the generic tracking fault would latch.

- `speed_cap`（可选 profile 段，`linear_mps`、`angular_rps`、`joint_velocity_scale` ∈ (0, 1]）进一步限制规划运动：笛卡尔动作取 min(请求值, 上限)；上述关节限速（未设 `planned_max_velocity` 时为关节限位）对除 7 轴夹爪外的关节乘以 `joint_velocity_scale`，适用于 jog、home、预设、收纳与动作。运行时不可修改，发布在 `schema.speed_cap`。
- `planned_max_velocity`（rebot-dm 为 0.45 rad/s，默认不设）限制除 7 轴夹爪外所有关节在规划运动中的速度：jog、home、预设、收纳（含看门狗收纳）和高层动作，使达妙 POS_VEL 滞后（约 v / 1.5 rad，2026-11-09 实测：0.7 rad/s 时 J3 滞后 0.458 rad）低于 0.5 rad 跟随误差阈值；预计滞后达到阈值的配置会被 `validate()` 拒绝。servo 流式控制有单独的限速与领先量上限（见下文“流式控制保护”）；流式制动仍用关节限位。
- 看门狗收纳时限为 max(10 s, 减速时间 + 规划时长 + 0.8 s 稳定保持 + 3 s)，按控制循环时间计；见下文“收纳稳定判定”。
- 跟踪误差故障信息包含关节号与指令/实测值；观测数据包含 `commanded_positions`。
- `observation.fault` 为 null，或在 Fault / EStop 时为 `{code, message, recoverable}`，所有检测器统一通过 `SafetyManager::latch(kind, detail)` 记录故障（跟踪误差为 `FOLLOWING_ERROR`，控制周期超过 250 ms 为 `CONTROL_DEADLINE`，输出写入失败或卸力未确认为 `DRIVER_WRITE_FAILED`，碰撞保护升级为 `COLLISION` 等，完整列表见上文英文部分）。检测器不在已有故障时跳过锁存，每次锁存（新增类别或重复锁存同一类别，包括急停）均推进 `epoch_id`；固定大小的故障记录保留所有已锁存的故障类别，直至携带精确当前 `epoch_id` 的 `clear_fault` 通过检查后一次性清空。
  - **故障严重度顺序**（由高到低，决定 `observation.fault.code`、`observation.fault.message` 与显示的 `SafetyState`）：`ThermalTrip` > `BusLoss` > `CollisionLatched` > `JointLimit` > `Other`（不可恢复故障码）> `Estop` > `Other`（可恢复故障码：`CONTROL_DEADLINE`、`HANDOVER_UNSETTLED`）> `WatchdogTimeout`。硬件/安全诊断故障在显示上高于 `ESTOP`，以便操作员持续看到根本故障，同时 `ESTOP` 仍保留在锁存记录中（强制 `recoverable = false` 及两阶段清除 `Fault -> EStop -> Idle`）；`ESTOP` 高于可恢复故障。
  - **可恢复性（`SafetyManager::recoverable`）**：对整条锁存记录取最差结果（包括多个 `Other` 详情的不可恢复粘性标记）——仅当记录中每一类及每一条详情均可恢复（`WATCHDOG_TIMEOUT`、`CONTROL_DEADLINE`、`HANDOVER_UNSETTLED`）时为 true。观测、WebSocket 操作员鉴权与恢复路径均统一调用 `SafetyManager::recoverable()`；清除故障仍须调用 `clear_fault`。
  - **清除校验（`SafetyManager::clear_check`）**：所有清除路径（旧路径 `clear_fault`、RT 执行器 `clear_fault`、MIT 超时恢复及急停清除）均在任何电机复位或其他副作用之前**最先**调用 `SafetyManager::clear_check`（仅当其余所有已记录类别的条件均已通过时，才允许发送电机故障复位并随后重新执行 `clear_check`；MIT 超时恢复的最终校验基于恢复完成后收到的新反馈）。逐一核对记录中所有类别，未知类别位一律 fail-closed 拒绝清除：
    - `ThermalTrip`：所有关节温度低于 `max_temperature - THERMAL_CLEAR_MARGIN_C` 且满足冷却持续时间；冷却时间仅在温度反馈新鲜时累计，温度反馈过期或不可用时立即重置冷却计时器。
    - `BusLoss`：全部电机具备新鲜反馈。
    - `WatchdogTimeout`：活动租约持有者具备新鲜心跳，或当前无活动租约（已过期的租约视同无租约）。
    - `JointLimit`（越界时须人工复位）：实测关节位置须回到 `[min - 0.01, max + 0.01]` rad（`JOINT_LIMIT_CLEAR_MARGIN_RAD`）以内且无驱动限位配置冲突。即使力矩已关闭、机械臂停在软限位加 `0.01 rad` 之外，armd 也不允许软件清除（避免在越界位姿下重新使能）；`clear_fault` 持续拒绝，并在拒绝消息中明确标出越界关节名称/编号、当前实测位置与配置限位，方便操作员先手动将关节移回限位内后再重试 `clear_fault`。
    - `CollisionLatched` / `Estop` / `Other`：保持新鲜反馈、无硬件故障状态与已知使能状态规则。
- `observation.residual_torques`（J1..J6 实测力矩减实测位姿下的重力模型力矩）在 profile 有重力模型且驱动报告力矩时发布；重力模型每个周期都计算，与是否输出重力补偿无关。残差本身不触发故障；碰撞保护（见下文，默认关闭）使用它。
- 笛卡尔工作空间（需 `workspace` 与 `kinematics`；profile 关节数不少于 `arm_dof`（运动学模型的臂关节数：内置模型为 6，URDF 链为其关节数）时生效）：end_link 原点、夹爪包络 8 个角点及可选相机点须高于 `floor_z_m`、位于包围盒内且距肩轴不超过 `max_reach_m`。servo 目标或 jog / home / 预设轨迹的 21 个采样点越界且比起点更差时返回 `422 WORKSPACE_VIOLATION`；从越界位姿向外移动允许。收纳不受地面、包围盒与距离限制（只记日志），但受禁入盒限制：路径进入禁入盒的收纳不会开始；显式收纳返回 `WORKSPACE_VIOLATION`，看门狗收纳保持位置并锁存 `WATCHDOG_TIMEOUT`。禁入盒（`workspace.keepout_boxes` 加上 `/api/v1/workspace/keepout` 设置的运行时列表，合计最多 16 个；运行时列表只能增加禁入盒）属于同一规则：检查点进入盒内的深度计为越界，报告为 `keepout '<name>'`。有禁入盒时，关节空间轨迹与 servo / 制动步做保守的扫掠检查：在一个区间内任一检查点的移动不超过 L = Σ（关节行程上界 ×（该关节到末端的连杆长度和 + 最大检查点偏移））；对每个检查点和禁入盒，若区间两端到盒的欧氏距离之和大于 L，该区间安全，否则在中点二分（L ≤ 0.1 mm 的区间按深度容差接受）。每条轨迹最多追加 4000 次 FK（否则 `WORKSPACE_VIOLATION`），每个 servo / 制动周期最多 64 次（否则进入可恢复的保持状态）。起点已有检查点位于其中的禁入盒仍按采样规则检查（向外移动允许）。schema 公开 `workspace`（含当前生效的禁入盒）与 `camera_mount`。未配置这些字段的 `--config` profile 不做检查，启动时告警。
- 动作接口见 `docs/agent_action_api.md`。动作运行时 servo 帧返回 `409 MOTION_BUSY`；动作路径在滞后超过 0.38 rad 时降速，0.45 rad 持续 1 s 结束为 `TRACKING_STALL`。

## Servo streaming guard / 流式控制保护

armd bounds every servo stream itself, whatever the client (cockpit, MCP, scripts). A target the arm cannot reach is shaped or refused; it never latches a Fault by itself. Only a joint that moves away from a still command (pushed, or a motor fault) latches the tracking Fault. Code: `src/supervisor.rs` `tick` (servo step and tracking check) and `servo`.

- **Speed cap (always on).** Profile field `servo_max_velocity`: one entry per joint (rad/s, `null` = no cap). The servo step uses min(entry, joint limit `max_velocity`). B601-DM: J1–J3 0.45 rad/s (measured trackable), J4–J6 1.5 rad/s, gripper `null`. The 7-DOF gripper (index 6) is always exempt. A profile without the field keeps the joint limits, as before.
- **Lead cap (always on, every profile).** Profile field `servo_max_lead_rad` (default 0.2; `validate()` requires 0 < lead < `following_error.max_error_rad`). For every joint except the 7-DOF gripper, the stepper target in the direction of travel is limited to measured ± lead: moving up, target = min(target, measured + lead); moving down, target = max(target, measured − lead). The jerk-limited stepper then slows the command; the commanded position is never set directly. Applies only with torque on and feedback younger than 100 ms (the same gate as the tracking check). With the POS_VEL lag of ≈ v / 1.5 rad, a 0.2 rad lead bounds a lagging joint at about 0.3 rad/s, so on B601-DM J1–J3 the lead cap usually acts before the 0.45 rad/s speed cap. A lead-capped joint does not count as arrived, so the stream stays active.
- **Blocked → recoverable hold (servo streaming only).** While a servo target is active, a joint is blocked when either (a) |cmd − meas| > `following_error.max_error_rad` for `persistence_ms`, or (b) it is lead-capped and its measured position moves less than 0.01 rad over `persistence_ms` (pressing against an obstacle). armd then ends the stream (`servo_target = None`), sets commanded = measured for J1–J6 with torque on (the gripper command is kept so a held object is not released), sets `motion_limit` = `blocked` and logs a warning. No Fault is latched; the next valid servo frame or motion command is accepted normally. If, while holding with commanded = measured, the error again exceeds the bound for `persistence_ms`, the tracking Fault latches as before (`Persistent joint tracking error: joint N ...`).
- **Unchanged:** planned motion (jog, home, presets, park) uses `planned_max_velocity`; action paths keep their own lag handling (`TRACKING_STALL`); gravity compensation has its own checks. The hold-still tracking Fault is unchanged.
- **`motion_limit` in the observation.** `null`, or `{ "reason": "speed" | "lead" | "joint_limit" | "workspace" | "blocked" | "power" | "torque" | "gripper_force", "joint": <0-based index or null>, "since_ms": <observation clock, ms, when this limit started> }`. Set only while the limit shapes the motion and cleared 300 ms after it last applied (`blocked` stays until the next accepted command, torque off or a stop; `torque` stays while the torque hold lasts, see "Torque guard"; `power` while the power governor slows motion or its hold lasts, see "Power budget"). One reason at a time, by priority torque > power > blocked = gripper_force > joint_limit > workspace > lead > speed. `joint_limit`: a servo frame outside the joint limits (still rejected with `SoftLimitExceeded`) or a target held at a limit the command has reached. `workspace`: a servo frame rejected by the workspace check (still `422 WORKSPACE_VIOLATION`). `speed` / `lead`: the respective cap shaped this tick's servo step.
- **Motor error codes.** Every observation carries `motor_errors`: per joint `null` or `{ "code": <u8>, "name": "..." }` (Damiao state codes 8–14: Overvoltage, Undervoltage, Overcurrent, MOS Overtemperature, Rotor Overtemperature, CAN Communication Loss, Overload); empty when the driver reports no motor state. A change is logged once per joint (warn on a new code, info when it clears). While torqued, a code still latches the existing hardware Fault.

- **限速（始终开启）。** profile 字段 `servo_max_velocity`：每个关节一项（rad/s，`null` 表示不限）。servo 步进取该值与关节限位 `max_velocity` 的较小值。B601-DM：J1–J3 0.45 rad/s（实测可跟随），J4–J6 1.5 rad/s，夹爪 `null`。7 轴夹爪（索引 6）始终不受限。未配置该字段的 profile 沿用关节限位。
- **领先量上限（始终开启，所有 profile）。** profile 字段 `servo_max_lead_rad`（默认 0.2，须满足 0 < lead < `following_error.max_error_rad`）。除 7 轴夹爪外，步进目标在运动方向上限制为实测位置 ± lead；由加加速度受限的步进器平滑减速，不直接改写指令位置。仅在力矩开启且反馈新于 100 ms 时生效。按 POS_VEL 滞后约 v / 1.5 rad 计，0.2 rad 领先量使滞后关节约 0.3 rad/s，因此 B601-DM 的 J1–J3 通常先触发领先量上限。
- **受阻 → 可恢复保持（仅 servo 流式）。** servo 目标有效期间，关节满足 (a) |指令 − 实测| > `max_error_rad` 持续 `persistence_ms`，或 (b) 处于领先量上限且实测位置在 `persistence_ms` 内变化小于 0.01 rad（顶住障碍物）时判为受阻：结束流式（`servo_target = None`），J1–J6 指令设为实测位置并保持力矩（夹爪指令不变，避免松开已夹物体），`motion_limit` 设为 `blocked` 并记 warn 日志。不锁存 Fault；下一条有效 servo 帧或运动命令照常接受。保持期间（指令 = 实测）误差再次超阈值持续 `persistence_ms` 时，仍按原逻辑锁存跟踪误差 Fault。
- **不变：** 规划运动用 `planned_max_velocity`；动作路径保留 `TRACKING_STALL`；重力补偿有自己的检查。
- **观测中的 `motion_limit`：** `null` 或 `{ "reason": "speed" | "lead" | "joint_limit" | "workspace" | "blocked" | "power" | "torque" | "gripper_force", "joint": 关节索引（从 0 起）或 null, "since_ms": 开始时刻（观测时钟，ms） }`。仅在限制正在作用时设置，最后一次作用 300 ms 后清除（`blocked` 保持到下一条被接受的命令、断力矩或停止；`torque` 在力矩保持期间一直保留，见「力矩保护」；`power` 在功率调速器降速或其保持期间保留，见「电源功率预算」）。同一时刻只报一个，优先级 torque > power > blocked = gripper_force > joint_limit > workspace > lead > speed。越出关节限位的 servo 帧仍以 `SoftLimitExceeded` 拒绝并报 `joint_limit`；工作空间拒绝仍返回 `422 WORKSPACE_VIOLATION` 并报 `workspace`。
- **电机错误码：** 每帧观测带 `motor_errors`：每个关节为 `null` 或 `{ "code", "name" }`（达妙状态码 8–14）；驱动不报告电机状态时为空数组。状态变化时每个关节只记一次日志。力矩开启时出现错误码仍按原逻辑锁存硬件 Fault。

## Episode replay / 片段回放

Action `replay` (`docs/agent_action_api.md#replay--回放`, code `src/replay.rs`). It moves the arm only through the action executor, so the rules of the other actions apply.

- **Before motion.** The whole episode is checked before the action starts; a failed check moves nothing: joint count, finite and ordered data, at most 600 s, every frame within the joint soft limits, per-joint speed of the recording at the chosen playback speed (0.5 or 1.0) at most the planned-motion limit (`planning_limits()`; 0.45 rad/s on rebot-dm, so a recording above 0.9 rad/s on any arm joint is refused at 0.5x), every resampled frame (one per control tick) under the workspace rule of planned motions, and the keep-out sweep between frames. A recording that is too fast is refused with `REPLAY_TOO_FAST` naming the joint and the highest playback speed that passes; armd does not clip it. Episodes are read from the episode directory only (`<dir>/<id>.parquet`, id `^[A-Za-z0-9_-]{1,64}$`).
- **Busy rules.** Refused while a recording runs or is being saved, during gravity compensation, during a collision hold, while another trajectory, servo stream or motion runs (`MOTION_BUSY`), and in E-stop, Fault or when not armed. While a replay runs, servo frames and other actions are refused as for every action (jog, preset, home and park supersede it); keep-out changes are `MOTION_BUSY`.
- **Approach.** A joint-space quintic from the commanded pose to the first frame at the planned-motion limits, checked like a jog.
- **Following.** The commanded position is the recording at the playback time; the playback time advances with the lag-aware rate of planned paths (slows from 0.38 rad lag on J1–J6, stops at 0.45 rad, below the 0.5 rad following-error bound). A rate at or below 0.1 for 1 s ends the replay as `TRACKING_STALL` with commanded = measured and torque on (no Fault). The following-error Fault, collision guard, E-stop and stop apply as for other actions. The servo stream guard (lead cap, `blocked` hold, `motion_limit`) applies to servo streams only; for a replay the lag-aware rate and `TRACKING_STALL` take its place.
- **Gripper.** Replayed with `gripper: true` under the stall latch rule of servo / jog (a command further into a latched stall is held, a reversal releases it); held at its command with `gripper: false`. J7 is excluded from the lag rate and the following-error check, as for other motions.
- **Ending.** Stop (`STOPPED`), E-stop (`ESTOP_ACTIVE`), collision trip (`COLLISION`), Fault (`FAULT`), watchdog (`WATCHDOG`), superseding motion (`SUPERSEDED`) and lease loss (`LEASE_LOST`) end the action; on lease loss armd also stops the replay reference. The arm then brakes from the replay speed with the stream braking limits and holds with torque on (TRACKING_STALL and collision trip hold the measured pose).
- **Storage.** `--episodes-dir` (default `/userdata/rebot-teleop/episodes` when `/userdata` exists, else `./data/episodes`, `off` disables recording and replay). A client `output_path` must name `<id>.parquet` directly inside the directory. Starting and saving a recording are refused at 500 files or 200 MB (`EPISODES_FULL`); a refused save keeps the recording.
- **Simulation result** (`tests/test_replay.rs`, first-order servo with a 50 ms time constant, recorded peak 0.30 rad/s, not hardware): commanded = recording within 1.2e-7 rad; measured distance to the recorded path 0.0022 rad at 0.5x and 1x; measured minus recording at the same recording time 0.009 rad at 0.5x, 0.018 rad at 1x.

动作 `replay`（`docs/agent_action_api.md#replay--回放`，代码 `src/replay.rs`）只通过动作执行器驱动机械臂，其他动作的规则同样适用。

- **运动前。** 动作开始前检查整个片段，任何一项不通过都不运动：关节数、数据有限且时间有序、时长不超过 600 s、每帧在关节软限位内、录制在所选回放速度（0.5 或 1.0）下各关节速度不超过规划运动限速（`planning_limits()`；rebot-dm 为 0.45 rad/s，因此任一臂关节超过 0.9 rad/s 的录制在 0.5x 下被拒绝）、每个重采样帧（每控制周期一帧）满足规划运动的工作空间规则，帧间做禁入盒扫掠检查。速度过快返回 `REPLAY_TOO_FAST`，给出关节和可通过的最高回放速度，armd 不对录制削峰。片段只从片段目录读取（`<dir>/<id>.parquet`，id 为 `^[A-Za-z0-9_-]{1,64}$`）。
- **忙碌规则。** 录制进行或保存中、重力补偿中、碰撞保护中、其他轨迹 / servo 流 / 运动进行中（`MOTION_BUSY`），以及急停、故障、未使能时拒绝。回放进行中，servo 帧和其他动作按所有动作的规则被拒绝（jog、预设、home、park 会取代它）；修改禁入盒返回 `MOTION_BUSY`。
- **接近。** 以规划运动限速用关节空间五次多项式从指令位姿移动到第一帧，检查与 jog 相同。
- **跟随。** 指令位置为回放时刻的录制值；回放时刻按规划路径的滞后自适应速率推进（J1–J6 滞后 0.38 rad 开始减速，0.45 rad 停止，低于 0.5 rad 跟随误差阈值）。速率 ≤ 0.1 持续 1 s 结束为 `TRACKING_STALL`，指令设为实测位置并保持力矩（不进入 Fault）。跟随误差 Fault、碰撞保护、急停与停止与其他动作相同。servo 流保护（领先量上限、`blocked` 保持、`motion_limit`）只作用于 servo 流；回放由滞后自适应速率与 `TRACKING_STALL` 承担对应作用。
- **夹爪。** `gripper: true` 时按 servo / jog 的卡滞锁存规则回放（锁存期间继续向卡滞方向的指令保持不动，反向指令解除锁存）；`gripper: false` 时保持当前指令。与其他运动一样，J7 不计入滞后速率与跟随误差检查。
- **结束。** 停止（`STOPPED`）、急停（`ESTOP_ACTIVE`）、碰撞（`COLLISION`）、故障（`FAULT`）、看门狗（`WATCHDOG`）、被新运动取代（`SUPERSEDED`）、租约丢失（`LEASE_LOST`）结束动作；租约丢失时 armd 同时停止回放参考轨迹。之后机械臂按流式制动限值从回放速度制动并带力矩保持（`TRACKING_STALL` 与碰撞触发时保持实测位姿）。
- **存储。** `--episodes-dir`（`/userdata` 存在时默认 `/userdata/rebot-teleop/episodes`，否则 `./data/episodes`；`off` 关闭录制与回放）。客户端的 `output_path` 必须指向该目录下的 `<id>.parquet`。目录达到 500 个文件或 200 MB 时拒绝开始和保存录制（`EPISODES_FULL`）；保存被拒绝时录制保留。
- **仿真结果**（`tests/test_replay.rs`，时间常数 50 ms 的一阶伺服，录制峰值 0.30 rad/s，非实机）：指令与录制之差 ≤ 1.2e-7 rad；实测到录制路径的距离 0.5x 与 1x 均为 0.0022 rad；同一录制时刻实测减录制 0.5x 为 0.009 rad，1x 为 0.018 rad。

## Collision guard / 碰撞保护

Contact detection from `observation.residual_torques` with a protective stop. It is not a certified safety function (no safety-rated hardware, no validated stopping performance) and does not replace the e-stop. **The default thresholds are placeholders until they are measured on a real arm**, so the guard is off unless the profile or the runtime setting enables it. Thresholds must come from a rebot-sysid measurement of the arm; on a B601-DM at the folded home pose the residuals measured J1 ±1.1, J2 ~1.2, J3 ~7.0–7.5, J4 ~2.2 (4.4 during a J4 move), J5 ~0.9 N·m. The B601-DM kit profile (and `rebot_dm()`) sets `thresholds_nm` 2.0, 1.19, 2.82, 1.43, 0.87, 0.28 N·m from one rebot-sysid session at two poses (2026-11-11, ±0.08 rad) with `enabled: false`; they need validation at more poses before the guard is enabled (kits/recamera-b601dm/docs/README.md). Joints in `collision.rest_exempt_joints` (six booleans, J1..J6; when absent, the joints listed in `resting_pose.support_torque_limits`) are not watched (no trip, not part of the auto-resume check) while every joint is within `resting_pose.position_tolerances` of home: they rest on their support. B601-DM: J2, J3, J4 (at the folded pose the real arm shows about 7.5 N·m residual on J3 and 2.1 N·m on J4, 0.4 N·m on J4 once lifted; 2026-11-12). The list only affects detection; the torque-off check keeps `support_torque_limits`. Code: `src/collision.rs`, called from `tick` after the residuals and before the motion reference is stepped. Per tick it costs O(6) and allocates nothing.

- **Profile section `collision`** (every field optional): `{"enabled": false, "thresholds_nm": [6.0, 6.0, 6.0, 2.5, 2.5, 2.5], "persist_ticks": 4, "clear_ratio": 0.5, "resume_after_s": 2.0, "max_auto_resumes": 3, "escalate_window_s": 60}`. `validate()` requires positive thresholds, `persist_ticks` 1..=1000, `clear_ratio` in (0, 1), `resume_after_s` in (0, 600], `max_auto_resumes` < 16, `escalate_window_s` in (0, 86400].
- **Runtime setting** (lease): WS command `/api/v1/safety/collision` `{"enabled": bool?, "sensitivity": "low"|"medium"|"high"?}`; sensitivity scales the profile thresholds ×1.5 / ×1.0 / ×0.7. `GET /api/v1/safety/collision` returns the effective config with the scaled thresholds. The setting is written atomically to `ARMD_COLLISION` (default `/userdata/rebot-teleop/collision.json`) and replaces the profile's `enabled` at the next start. Enabling without a gravity model or torque feedback returns `422 UNSUPPORTED`.
- **Detection.** Active only when the guard is enabled and available (capability `collision_guard`: profile gravity model, 6/7-DOF, driver reports torque), torque is on, the state is Armed or Moving, gravity compensation is off (hand-guiding produces residuals by design), no re-arm or disable is pending, the park settle phase is not running, and `residual_torques` is non-null. A trip is |residual_j| > threshold_j for `persist_ticks` consecutive ticks on any joint J1..J6 (the gripper is not monitored). The residual is measured torque minus the static gravity model; it includes inertial and friction torque during motion, which the placeholder thresholds have not been checked against.
- **Protective stop (not a SafetyState change).** The running action fails with code `COLLISION` and a message naming the joint and the residual; trajectory, servo stream, macro action and park end; J1–J6 hold commanded = measured with torque on (the gripper keeps its command so a held object is not released). While the hold lasts, jog, home, presets, park, servo frames and actions are rejected with `409 COLLISION_HOLD`; entering gravity compensation is allowed and ends the hold, so the arm can be taken by hand. E-stop, `/api/v1/motion/stop`, `clear_fault`, torque off (under the existing resting-pose rules) and the collision setting still work. A lease watchdog expiry during a hold does not park; it latches `WATCHDOG_TIMEOUT` with torque held.
- **Auto-resume.** When every |residual_j| < `clear_ratio` × threshold_j continuously for `resume_after_s` (control-loop time), the hold ends by itself. E-stop, a Fault, torque off, gravity compensation or switching the guard off end the hold at once; those paths have their own way back to motion.
- **Escalation.** The (`max_auto_resumes` + 1)-th trip within `escalate_window_s` (observation clock) latches Fault with code `COLLISION` (`recoverable: false`) through `SafetyManager::latch`, including when another Fault or E-stop is already active while torque stays on (protective auto-resume holds still end on Fault/E-stop); torque stays on at the measured pose and a person must `clear_fault`. Trip times are kept across `clear_fault`, so another trip inside the same window escalates again.
- **Observation `collision`**: null while the guard is disabled or unavailable, else `{"active", "joint" (1-based or null), "residual_nm", "threshold_nm", "since_s", "resume_in_s", "trips_in_window", "enabled": true, "sensitivity"}`; the trip fields are null when no hold is active. The black box records this field (omitted while it is null), so a hold appears in the 5 Hz torqued samples; each trip also logs a warning.
- **Needs measurement on a real arm:** residual noise at rest and during planned motion per joint (inertial and friction terms), the threshold per joint and sensitivity, `persist_ticks` against the detection delay, and whether `resume_after_s` 2 s suits a person removing an obstacle.

基于 `observation.residual_torques` 的接触检测与保护性停止。它不是经过认证的安全功能（无安全等级硬件，停止性能未验证），不能替代急停。**默认阈值在真机实测前只是占位值**，因此除非 profile 或运行时设置开启，否则保护关闭。阈值须来自 rebot-sysid 对该机械臂的测量；B601-DM 在折叠的 home 位姿实测残差为 J1 ±1.1、J2 约 1.2、J3 约 7.0–7.5、J4 约 2.2（J4 运动时 4.4）、J5 约 0.9 N·m。B601-DM 套件 profile（以及 `rebot_dm()`）的 `thresholds_nm` 为 2.0、1.19、2.82、1.43、0.87、0.28 N·m，来自一次 rebot-sysid 测试、两个姿态（2026-11-11，±0.08 rad），`enabled: false`；启用前须在更多姿态下验证（kits/recamera-b601dm/docs/README.md）。所有关节都在 home 的 `resting_pose.position_tolerances` 内时，`collision.rest_exempt_joints`（6 个布尔值，J1..J6；缺省时取 `resting_pose.support_torque_limits` 中列出的关节）中的关节（靠在支撑上）不参与检测，也不参与自动恢复判断。B601-DM 为 J2、J3、J4（真机在收纳位 J3 残差约 7.5 N·m、J4 约 2.1 N·m，抬起后 J4 约 0.4 N·m；2026-11-12）。该列表只影响检测；断力矩检查仍用 `support_torque_limits`。代码：`src/collision.rs`，在 `tick` 中残差计算之后、运动参考步进之前调用；每周期 O(6)，不分配内存。

- **profile 段 `collision`**（字段均可选）：默认值同上。`validate()` 要求阈值为正、`persist_ticks` 1..=1000、`clear_ratio` ∈ (0, 1)、`resume_after_s` ∈ (0, 600]、`max_auto_resumes` < 16、`escalate_window_s` ∈ (0, 86400]。
- **运行时设置**（需租约）：WS 指令 `/api/v1/safety/collision` `{"enabled": bool?, "sensitivity": "low"|"medium"|"high"?}`，灵敏度把 profile 阈值乘以 1.5 / 1.0 / 0.7。`GET /api/v1/safety/collision` 返回含缩放后阈值的生效配置。设置原子写入 `ARMD_COLLISION`（默认 `/userdata/rebot-teleop/collision.json`），下次启动时替换 profile 的 `enabled`。无重力模型或无力矩反馈时开启返回 `422 UNSUPPORTED`。
- **检测条件：** 保护已开启且可用（能力 `collision_guard`：profile 有重力模型、6/7 轴、驱动报告力矩），力矩开启，状态为 Armed 或 Moving，重力补偿关闭（拖动示教本身产生残差），无待完成的重新使能或卸力，不在收纳稳定阶段，`residual_torques` 非空。任一关节 J1..J6 连续 `persist_ticks` 个周期 |残差| > 阈值即触发（夹爪不检测）。残差为实测力矩减静态重力模型，运动中包含惯性与摩擦力矩，占位阈值未针对这些项验证。
- **保护性停止（不改变 SafetyState）：** 正在执行的动作以 `COLLISION` 失败，消息含关节号与残差；轨迹、servo 流、宏动作与收纳结束；J1–J6 指令设为实测位置并保持力矩（夹爪指令不变）。保持期间 jog、home、预设、收纳、servo 帧和动作均返回 `409 COLLISION_HOLD`；可以进入重力补偿，进入时保持结束，便于用手接管机械臂；急停、`/api/v1/motion/stop`、`clear_fault`、断力矩（按现有静止位规则）和碰撞设置仍可用。保持期间租约看门狗到期不执行收纳，而是保持力矩并锁存 `WATCHDOG_TIMEOUT`。
- **自动恢复：** 所有关节 |残差| < `clear_ratio` × 阈值连续保持 `resume_after_s`（控制循环时间）后，保持自动解除。急停、Fault、断力矩、重力补偿或关闭保护会立即结束保持。
- **升级：** `escalate_window_s`（观测时钟）内第 `max_auto_resumes` + 1 次触发通过 `SafetyManager::latch` 锁存 Fault，故障码 `COLLISION`（`recoverable: false`），即使力矩保持期间已有其他 Fault 或急停处于锁存状态也会照常升级锁存（自动恢复保护性保持仍会在进入 Fault/急停时立即结束）；力矩保持在实测位置，须人工 `clear_fault`。触发时间在 `clear_fault` 后保留，同一时间窗内再次触发会再次升级。
- **观测字段 `collision`：** 保护关闭或不可用时为 null，否则为 `{"active", "joint"（从 1 起或 null）, "residual_nm", "threshold_nm", "since_s", "resume_in_s", "trips_in_window", "enabled": true, "sensitivity"}`，无保持时触发相关字段为 null。黑匣子记录该字段（为 null 时省略），每次触发另记 warn 日志。
- **需真机测量：** 各关节静止与规划运动中的残差噪声（惯性与摩擦项）、各关节阈值与灵敏度档位、`persist_ticks` 与检测延迟的关系、`resume_after_s` 2 s 是否适合人工移除障碍物。

## Torque guard / 力矩保护

Stops pushing when a joint's measured torque stays near the motor's limit. Code: `src/torque_guard.rs`, called from `SupervisorInner::tick` after the collision guard and before the motion reference is stepped. It is not a certified safety function.

Incident that motivated it (real arm, 2026-11-12, black box at 5 Hz): the wrist was driven down; J4 (DM4310, TMAX 10 N·m) stopped at −1.60 rad against a physical stop or self-contact (soft limit ±π). Within 0.4 s its torque went −2.0 → −6.8 → +8.8 → +9.5 N·m with no position change. About 0.4 s later all seven motors stopped replying at once (feedback age 198 ms, then BusLoss), came back Disabled (a motor power reset) and the arm dropped; the reCamera USB gadget re-enumerated in the same second. Leading hypothesis (not verified): the stall current, or regeneration from the torque reversal, disturbed the shared 24 V supply. The servo blocked hold (< 0.01 rad progress for 500 ms at the lead cap) had not triggered in that time.

- **Profile section `torque_guard`** (absent = off; missing fields take these defaults): `{"enabled": true, "ratio": 0.85, "persist_ms": 100, "joints": [true, true, true, true, true, true]}`. The threshold of joint j is `ratio` × `damiao_ranges[j].t_max` (the motor's torque mapping range TMAX). `validate()` requires `ratio` in [0.3, 0.95], `persist_ms` in 1..=2000, and `damiao_ranges` when enabled.
- **B601-DM (`ArmConfig::rebot_dm()`, kit profile): `ratio` 0.60**, i.e. J1–J3 16.8 N·m (TMAX 28), J4–J6 6.0 N·m (TMAX 10), `persist_ms` 100. 0.60 was chosen on 2026-11-12 for the supply in use, a Mean Well LRS-150-24 (24 V 6.5 A; its overload hiccup was measured at ~8.5 A). 0.85 (J1–J3 23.8 N·m, J4–J6 8.5 N·m) is the value intended with the recommended LRS-350-24 (14.6 A).
- **Gravity margin (simulation, gravity model only).** Over a 13-point grid per joint of J2..J6 inside the joint limits, the largest model gravity torques are J2 16.35 N·m (97 % of 16.8, arm stretched: J2 0, J3 −2.618, J4 −0.524), J3 7.79, J4 2.16, J5 0.78 N·m (`tests/test_torque_guard.rs`). The measured torque adds the POS_VEL control effort, friction and any payload, so at 0.60 a fully stretched arm holding a payload can reach the J2 threshold. Needs measurement on the real arm.
- **Watched:** each J1..J6 listed in `joints` (the gripper joint never: it has its own stall handling, and gripping an object is a normal stall), with torque on, state Armed or Moving, position control (not gravity compensation, which clamps its own feed-forward torques), no re-arm or disable pending, a driver that reports torque (capability `torque_guard`), and feedback younger than 100 ms. Planned motion, actions, replay, park trajectories and servo streams are all watched. Not watched: the unload settle phase (the arm rests on its supports at the resting pose and torque is cut at its end).
- **Trigger:** |measured torque_j| ≥ threshold_j on consecutive control ticks whose summed tick period reaches `persist_ms`; at 50 Hz that is the 5th consecutive sample, 80–100 ms after the torque crossed the threshold (depending on where in a tick period it crossed). A sample below the threshold resets the count. The sign may change in between (|τ| is compared).
- **Action (not a SafetyState change, no Fault, torque stays on):** the running action fails with code `TORQUE_LIMIT` and a message naming the joint, the torque and the threshold (`Torque limit on joint 4: 10.00 N·m at or above 6.00 N·m (60% of 10.0 N·m) for 100 ms`); trajectory, servo stream, macro action, replay and park end; J1–J6 hold commanded = measured (clamped to the limits) with zero commanded velocity and acceleration, except the held joint, which is commanded `TORQUE_HOLD_BACKOFF_RAD` (0.005 rad) back from its measured position in the relieving direction (opposite to the torque sign) so that it does not keep pressing at the trip torque; a repeated trip on the same joint and sign never backs off further than 0.005 rad from the first trip position (no creep under a load that does not relax), and a joint pushed back further than that by the load is held where it is. The gripper keeps its command; `motion_limit` = `{reason: "torque", joint, since_ms}`; one warn log line with the joint, torque, threshold, command and measurement (a repeated trip with no action running logs at debug). A watchdog park stopped by a trip logs `Watchdog park stopped by the torque guard on joint N (...)`, keeps torque on at the backed-off pose and latches Fault `WATCHDOG_TIMEOUT`; a watchdog park whose resting pose lies in the push direction of a hold is not started (`not parking (torque hold on joint N: the resting pose lies in the push direction)`), same hold and fault. Torque is not cut in either case: the arm is not at its rest pose and would drop.
- **While the hold lasts** (push direction = sign of the measured torque at the trip): a servo frame or jog / joint_move / home target that moves the held joint past the hold position in the push direction is clamped to the hold position for that joint (the other joints follow the command; the frame is not rejected); targets that keep the joint at the hold position or move it the other way (reducing the load) pass unchanged. So the cockpit joysticks, joint jog and servo clients can always back out. Cartesian actions, macros and replay are not clamped; if they push into the stop again, the guard trips again after `persist_ms`, and any motion that commands the held joint more than `TORQUE_PUSH_IN_RAD` (0.002 rad) past the trip position trips at once; they fail with `TORQUE_LIMIT`. A torque still at or above the threshold during the hold with no motion running (e.g. a person pushing the arm) trips again after `persist_ms` and holds the new measured position.
- **Retreat allowance.** A motion whose target moves the held joint away from the load (park, home, the watchdog park, joint_move / jog, servo, Cartesian, macro, replay) is not tripped on the held joint while all of these hold: at most `TORQUE_RETREAT_WINDOW_S` (1.5 s, control-loop time) since it started; |torque| ≤ max(|torque at the trip|, threshold) + `TORQUE_RETREAT_MARGIN_RATIO` (0.10) × threshold; the commanded position does not turn back toward the load by more than 0.001 rad from the furthest retreat; the measured position follows the commanded retreat within `TORQUE_RETREAT_LAG_RAD` (0.01 rad) beyond the lag at its start; a motion runs. When any of these fails, the allowance ends for that hold and the normal rule applies, with the time already spent at or above the threshold counted (a torque that rose, or stayed high for 1.5 s, trips on the next tick). The other joints stay fully watched. Numbers: 1.5 s is the shortest planned park; 0.10 × threshold (1.68 N·m on J1–J3, 0.6 N·m on J4–J6) is a rise a relaxing load does not show; 0.01 rad lag ends the allowance for a joint that does not come back. Not measured on a real arm.
- **The hold ends** when the held joint's measured position is at least 0.05 rad (`TORQUE_HOLD_RELEASE_RAD`) from the hold position and its |torque| is below the threshold, or at once on torque off, E-stop, a Fault or gravity-compensation entry. `motion_limit` is cleared with it.
- **Observation / discovery:** capability `torque_guard` (capabilities version 8), `schema.torque_guard` = `{"ratio", "persist_ms", "thresholds_nm": [per joint, null = not watched], "release_rad"}`, and the `torque_limit_hold` entry in `GET /api/v1/safety/describe`. The black box records `motion_limit` and `torques` in the 5 Hz torqued samples.
- **Simulation results** (`tests/test_torque_guard.rs`, ideal position servo with a stiff stop, not hardware): servo stream into a J4 stop held 80 ms after the first sample at or above 6.0 N·m (5th sample), torque below 3 N·m after the hold; J4 incident ramp −2 → +9.5 N·m over 400 ms at a fixed position: threshold reached at 280 ms, trip at 360 ms, before 9.5 N·m (reached at 400 ms). 2026-11-21 incident model (J2 blocked at 0.033 rad by an elastic contact of 650 N·m/rad from 0): trip at 23.3 N·m; backed-off hold 17.0 N·m (still above 16.8); the park from the hold falls below the threshold after 0.18 s and ends with torque off after 2.3 s without a re-trip; the watchdog park after a lease loss ends with torque off after 2.3 s, no fault; a J4 saturation during the retreat trips after 5 ticks; a constant 17.8 N·m during a 3 s retreat trips at 1.54 s; a replay into the obstacle trips (persist rule while the contact loads the joint, push-in rule at trip position + 0.002 rad when it does not).
- **Incident 2026-11-21 (office B601-DM, armd log):** a joint_move from the folded rest pose drove J2 +0.12 rad into an elastic obstacle; the guard tripped at 20.14 N·m (cmd 0.098, meas 0.033 rad) and held the measured pose. The obstacle kept |τ2| near 20 N·m while held. The SDK park (back toward 0) failed `TORQUE_LIMIT`: the park quintic moves only a few mrad in its first 100 ms, so the held joint stayed above the threshold for `persist_ms` and tripped again. The lease expired 10 s later; the watchdog park was tripped the same way, the trip's motion stop cleared the park (`pending_normal_unload`), and the park supervision logged `Watchdog park interrupted (safety state Armed)` (the torque guard does not change the safety state) and latched `WATCHDOG_TIMEOUT`. The retreat allowance, the back-off and the watchdog handling above are the fix.
- **Needs measurement on a real arm:** the torque each joint reports while holding and moving with payload, the time from stall to a supply disturbance with the 6.5 A supply, and whether 100 ms at 0.60 trips before it; the torque noise while holding against a load (against the 0.10 retreat margin) and whether 0.005 rad of back-off lowers the held torque.

在关节实测力矩持续接近电机上限时停止继续施力。代码：`src/torque_guard.rs`，由 `SupervisorInner::tick` 在碰撞保护之后、运动参考步进之前调用。它不是经过认证的安全功能。

起因（真机，2026-11-12，黑匣子 5 Hz）：手腕向下运动时 J4（DM4310，TMAX 10 N·m）在 −1.60 rad 顶到物理限位或自碰撞（软限位 ±π）。0.4 s 内力矩 −2.0 → −6.8 → +8.8 → +9.5 N·m，位置不变。约 0.4 s 后 7 个电机同时停止应答（反馈龄 198 ms，随后 BusLoss），恢复后状态为 Disabled（电机掉电复位），机械臂下落；同一秒 reCamera USB gadget 重新枚举。主要假设（未验证）：堵转电流或力矩反向时的回馈扰动了共用的 24 V 电源。这段时间内 servo 受阻保持（领先量上限下 500 ms 内进展 < 0.01 rad）未触发。

- **profile 段 `torque_guard`**（缺省 = 关闭；缺少的字段取以下默认值）：`{"enabled": true, "ratio": 0.85, "persist_ms": 100, "joints": [true, true, true, true, true, true]}`。关节 j 的阈值为 `ratio` × `damiao_ranges[j].t_max`（电机力矩映射范围 TMAX）。`validate()` 要求 `ratio` ∈ [0.3, 0.95]、`persist_ms` 1..=2000，开启时必须有 `damiao_ranges`。
- **B601-DM（`ArmConfig::rebot_dm()`、套件 profile）：`ratio` 0.60**，即 J1–J3 16.8 N·m（TMAX 28），J4–J6 6.0 N·m（TMAX 10），`persist_ms` 100。0.60 于 2026-11-12 按当前电源 Mean Well LRS-150-24（24 V 6.5 A，过载打嗝实测约 8.5 A）选定；0.85（J1–J3 23.8 N·m，J4–J6 8.5 N·m）是配推荐电源 LRS-350-24（14.6 A）时的预期值。
- **重力余量（仿真，仅重力模型）：** J2..J6 在关节限位内每关节取 13 点网格，模型重力力矩最大值为 J2 16.35 N·m（16.8 的 97 %，手臂伸直：J2 0、J3 −2.618、J4 −0.524）、J3 7.79、J4 2.16、J5 0.78 N·m（`tests/test_torque_guard.rs`）。实测力矩还包括 POS_VEL 控制力、摩擦和负载，因此 ratio 0.60 时完全伸直并带负载可能达到 J2 阈值。需真机测量。
- **检测条件：** `joints` 中列出的 J1..J6（夹爪关节始终不检测：它有自己的堵转处理，夹住物体本身就是堵转），力矩开启，状态为 Armed 或 Moving，位置控制（重力补偿不检测，它自行限制前馈力矩），无待完成的重新使能或卸力，驱动报告力矩（能力 `torque_guard`），反馈新于 100 ms。规划运动、动作、回放、收纳轨迹和 servo 流都检测。不检测：收纳稳定阶段（机械臂在静止位靠在支撑上，阶段结束即断力矩）。
- **触发：** |实测力矩_j| ≥ 阈值_j 的连续控制周期累计周期时长达到 `persist_ms`；50 Hz 时为第 5 个连续采样，即越过阈值后 80–100 ms（取决于在周期内何时越过）。任一采样低于阈值即重新计数。中途符号可变（比较 |τ|）。
- **动作（不改变 SafetyState，不锁存 Fault，力矩保持）：** 正在执行的动作以 `TORQUE_LIMIT` 失败，消息含关节号、力矩和阈值；轨迹、servo 流、宏动作、回放和收纳结束；J1–J6 指令设为实测位置（限位内）并保持力矩，指令速度、加速度清零；触发关节例外，其指令为实测位置朝卸载方向（力矩符号的反方向）后退 `TORQUE_HOLD_BACKOFF_RAD`（0.005 rad），避免持续以触发力矩顶住；同一关节同一符号重复触发时，相对首次触发位置的总后退不超过 0.005 rad（负载不松时不会持续后移），被负载推回超过此距离的关节在当前位置保持。夹爪指令不变；`motion_limit` = `{reason: "torque", joint, since_ms}`；记一行 warn 日志（关节、力矩、阈值、指令、实测；无动作运行时的重复触发记为 debug）。看门狗收纳被触发打断时记 `Watchdog park stopped by the torque guard on joint N (...)`，在后退后的位置保持力矩并锁存 Fault `WATCHDOG_TIMEOUT`；静止位位于保持施力方向时不启动看门狗收纳（`not parking (torque hold on joint N: the resting pose lies in the push direction)`），同样保持并锁存。两种情况都不断力矩：机械臂不在静止位，断力矩会下落。
- **保持期间**（施力方向 = 触发时实测力矩的符号）：servo 帧或 jog / joint_move / home 目标若使该关节越过保持位置继续朝施力方向运动，该关节目标被限制在保持位置（其他关节照常执行，帧不被拒绝）；保持不动或朝反方向（减小负载）运动的目标原样通过。因此摇杆、关节点动和 servo 客户端总能反向移出。笛卡尔动作、宏动作和回放不做限制；若再次顶向限位，`persist_ms` 后再次触发；任何运动使该关节指令越过触发位置 `TORQUE_PUSH_IN_RAD`（0.002 rad）以上时立即触发；均以 `TORQUE_LIMIT` 失败。保持期间无运动且力矩仍 ≥ 阈值（例如有人推机械臂）时，`persist_ms` 后再次触发并保持新的实测位置。
- **退出豁免：** 目标使保持关节离开负载的运动（收纳、home、看门狗收纳、joint_move / jog、servo、笛卡尔、宏动作、回放），在以下条件全部满足时不因该关节再次触发：开始后不超过 `TORQUE_RETREAT_WINDOW_S`（1.5 s，控制周期时间）；|力矩| ≤ max(|触发力矩|, 阈值) + `TORQUE_RETREAT_MARGIN_RATIO`（0.10）× 阈值；指令位置相对已达到的最远退出位置折返不超过 0.001 rad；实测位置跟随指令退出，滞后比开始时多不超过 `TORQUE_RETREAT_LAG_RAD`（0.01 rad）；运动仍在进行。任一条件不满足时该保持的豁免结束，按常规规则判定，已在阈值以上的时间照计（力矩上升或 1.5 s 内一直偏高时下一周期即触发）。其他关节照常检测。取值依据：1.5 s 为最短规划收纳时长；0.10 × 阈值（J1–J3 1.68 N·m，J4–J6 0.6 N·m）是负载松开过程中不会出现的上升量；0.01 rad 滞后用于结束不能退回的关节的豁免。未经真机测量。
- **保持结束：** 该关节实测位置离开保持位置至少 0.05 rad（`TORQUE_HOLD_RELEASE_RAD`）且 |力矩| 低于阈值；或断力矩、急停、Fault、进入重力补偿时立即结束。`motion_limit` 同时清除。
- **观测与发现：** 能力 `torque_guard`（能力版本 8），`schema.torque_guard` = `{"ratio", "persist_ms", "thresholds_nm"（每关节，null 表示不检测）, "release_rad"}`，以及 `GET /api/v1/safety/describe` 的 `torque_limit_hold` 条目。黑匣子 5 Hz 力矩开启采样记录 `motion_limit` 和 `torques`。
- **仿真结果**（`tests/test_torque_guard.rs`，理想位置伺服加刚性限位，非实机）：servo 流顶到 J4 限位，首个 ≥ 6.0 N·m 采样后 80 ms（第 5 个采样）进入保持，保持后力矩低于 3 N·m；J4 事故斜坡（固定位置，400 ms 内 −2 → +9.5 N·m）：280 ms 越过阈值，360 ms 触发，早于 400 ms 达到 9.5 N·m。2026-11-21 事故模型（J2 在 0.033 rad 受阻，弹性接触自 0 起 650 N·m/rad）：23.3 N·m 触发；后退保持 17.0 N·m（仍高于 16.8）；从保持开始收纳，0.18 s 后力矩低于阈值，2.3 s 后断力矩完成，无再次触发；租约丢失后的看门狗收纳 2.3 s 后断力矩完成，无 Fault；退出期间 J4 饱和 5 个周期后触发；3 s 退出期间力矩恒为 17.8 N·m 时 1.54 s 触发；回放顶向障碍物时触发（接触仍加载时按持续规则，不加载时在触发位置 + 0.002 rad 按顶入规则）。
- **事故 2026-11-21（办公室 B601-DM，armd 日志）：** 从折叠静止位执行 joint_move，J2 +0.12 rad 顶到弹性障碍物；保护在 20.14 N·m 触发（指令 0.098，实测 0.033 rad）并保持实测位置。保持期间障碍物使 |τ2| 维持在约 20 N·m。SDK 收纳（回到 0）以 `TORQUE_LIMIT` 失败：收纳五次多项式轨迹前 100 ms 只移动几 mrad，保持关节在阈值以上持续 `persist_ms`，再次触发。10 s 后租约过期，看门狗收纳同样被触发，触发时的停止运动清除了收纳（`pending_normal_unload`），收纳监督记 `Watchdog park interrupted (safety state Armed)`（力矩保护不改变安全状态）并锁存 `WATCHDOG_TIMEOUT`。上述退出豁免、后退保持和看门狗处理即为修复。
- **需真机测量：** 各关节带负载保持与运动时的实测力矩，6.5 A 电源下从堵转到电源扰动的时间，以及 0.60 / 100 ms 能否在此之前触发；顶住负载保持时的力矩噪声（对照 0.10 退出余量），以及 0.005 rad 后退能否降低保持力矩。

## Gripper force limit / 夹爪力限制

Bounds the force the gripper applies while closing. Code: `SupervisorInner::tick` (stall state machine, `gripper_lead_cap`) and `GripperMotion` in `src/motion.rs`. Not a certified safety function; the thresholds are not calibrated on a real arm.

Incident (office B601-DM, rc10, 2026-11-20, black box 5 Hz): a grasp of a toy banana commanded J7 (open −5.7 rad, closed 0.0) on a ramp to closed, the command ~0.23 rad ahead of the measured jaw. From contact at about −1.75 rad the J7 torque read 0.36 → 0.85 → 1.8 → 3.1 → 5.0 N·m (at −0.50 rad) while the jaw kept moving at ~1 rad/s; then 0.26 N·m at −0.20 rad (a finger broke) and the jaw ran to closed (`NOT_HOLDING`). The stall latch (|τ| ≥ 0.444 N·m with |v| < 0.10 rad/s for 6 ticks) never set because the jaw kept moving; the torque guard does not watch the gripper.

- **Profile `gripper_policy`** (all optional; absent = off): `max_close_torque_nm`, `contact_torque_nm` (must be below the cap), `max_lead_rad`, `stream_contact_speed_rad_s`. B601-DM (`GripperPolicy::rebot_dm()`): 1.0 N·m, 0.6 N·m, 0.35 rad, 0.3 rad/s. `close_speed_rad_s` (default 0.3 rad/s, (0, 2]): J7 speed of the closes armd plans itself (grasp, place and sequence closes and closing moves, every closing stroke of `gripper_calibrate`); a gripper action keeps its own `speed`. The cap is 2.2× the free-close peak; contact is 1.3× the free-close peak.
- **Torque cap:** |τ_gripper| above `max_close_torque_nm` on fresh feedback on one tick (`GRIPPER_FORCE_CAP_TICKS` = 1; it was 2, which let one impact sample pass) while the jaw is driven closed (command, target or commanded velocity in the closing direction), or the torque pushing open (signed) above it while the jaw is driven open, latches the stall whatever the jaw speed: command, target, servo target and the whole-arm J7 hold are set to the measured position. Every mode reads that latch: gripper actions, grasp, servo streams (teleop, policies), joint motions, replay; gravity compensation sends the same J7 command. It releases as the stall latch does (|τ| below 0.2223 N·m for 6 ticks, or a command away from the stall), except under a servo stream or live policy: there it releases only when a frame's gripper target is at least 0.05 rad (`GRIPPER_FORCE_RELEASE_MARGIN_RAD`) more open than the hold, or when the stream ends (no frame for the 200 ms motion-frame timeout) or an action takes over. Low torque does not release it there: on a rigid object the hold at the measured jaw reads about 0 N·m, and the former release let the stream squeeze again (sim rig, stiffness 10 N·m/rad: 1.34 N·m every 19 ticks). While the stream still closes, the latched grip ramps back in to 0.6 × cap and holds there; each step is sized from a contact stiffness estimate (from the trip, raised by each step's observed Δτ/Δq) so the predicted torque stays at or below 0.6 × cap, at most 0.25 rad/s. Every new over-cap episode counts a trip; the third on one contact ends the ramping and stops the stream. Stop, E-stop, fault, torque off and loss of the stream's lease end the stream's gripper state and hold J7 at the measured jaw. Observation: `motion_limit` = `{reason: "gripper_force", joint: 6}` while held, `gripper.force_limited`, `gripper.force_limit_trips` (count since start); one warn log line per trip. No Fault, the action is not failed.
- **Grasp close** (`gripper` close with `grasp`, grasp macro): contact is |τ| ≥ the learned free-motion baseline + margin for 3 ticks (after the jaw moved 0.05 rad; `contact_torque_nm` until a baseline is learned, see agent_action_api.md "Free-motion torque baseline") or the command ≥ 0.30 rad ahead while the jaw closes slower than 0.3 × the requested speed, for 2 ticks. The torque cap does not depend on the baseline. From the contact the command closes at 0.3 rad/s to contact + `squeeze_rad` and is taken back there if it ran ahead; the squeeze hold never passes it. When the jaw comes to rest at least `squeeze_rad` / 2 past the contact with |τ| below `contact_torque_nm` (the object turned or slid in the jaws, for example a box closed on across its corners), the contact is dropped and the jaw closes on at 0.3 rad/s until the next contact; not when the stop is already `closed_rad`. After a cap trip the squeeze starts at the measured position and presses in (`squeeze_rad` over half of `settle_ms`) until |τ| reaches 0.6 × cap; a squeeze above the cap holds the measured jaw and presses in again on that ramp (before: backed off toward 0.8 × cap, which kept pressing and overshot the cap on stiff objects). Holding verdict unchanged.
- **Lead cap:** with torque on and fresh feedback the J7 command is at most `max_lead_rad` ahead of the measured jaw in the closing direction, applied after every writer of the tick. Opening is not bounded.
- **Stream contact regulator** (servo streams and live policies; profile `gripper_policy.stream_contact_speed_rad_s`, B601-DM 0.3 rad/s, the grasp contact speed; needs `contact_torque_nm` and torque feedback): contact is |τ| ≥ `contact_torque_nm` (the learned baseline + margin once learned; the regulated torque below is then that value clamped to [`contact_torque_nm`, `contact_torque_nm` + 0.10 N·m]), or |τ| ≥ the stall threshold (0.444 N·m, raised by the learned closing baseline by at most 0.15 N·m) with |v| < 0.10 rad/s, on fresh feedback while the stream closes. From the contact the closing J7 command is limited (applied with the lead cap, `motion_limit` `gripper_force`): while |τ| < `contact_torque_nm` the limit moves at most `stream_contact_speed_rad_s` × dt past the last written command; at or above it the lead over the measured jaw is scaled by `contact_torque_nm` / |τ|. For a linear contact this sets the next sample to `contact_torque_nm` whatever the stiffness; the overshoot is one creep step (stiffness × 0.006 rad at 50 Hz). The ordinary stall hold does not latch while the regulator runs. Ends when the jaw opens 0.05 rad past the contact point, when it closes 0.1 rad on with |τ| below half of `contact_torque_nm` (the object gave way), or when the stream ends. Not bounded: the first torque sample at contact, stiffness × the POS_VEL lag at that moment (≈ v / 4.5 rad on the rig); only `max_lead_rad` bounds it. Gripper actions keep their own contact handling. Sim rig, 30 fps stream at 1 rad/s onto a rigid block, stiffness 3 / 10 / 30 N·m/rad: impact sample 0.64 / 2.13 / 6.38 N·m, after it at most 0.60 / 0.64 / 0.71 N·m, no re-squeeze over a 5 s hold (before: 0.90 / 2.31 / 6.92 N·m after the impact and 2 / 17 / 22 re-squeeze cycles).

## Power budget / 电源功率预算

Estimates the motor supply current from motor feedback, slows or holds motion to stay inside the supply rating, and time-scales planned motions with the URDF dynamics. Code: `src/power.rs` (estimate, governor), `src/dynamics.rs` (inverse dynamics), `src/power_plan.rs` (planning). **The arm has no current or voltage sensor: every current here is an estimate from datasheet motor parameters, not a measurement, and the parameters have not been validated on the arm.** It is not a certified safety function and does not replace a supply with headroom.

Motivation: the B601-DM in use runs on a Mean Well LRS-150-24 (24 V, 6.5 A rated; datasheet overload protection 110–140 % of rated, hiccup mode; a teardown measured the trip at ~8.5 A; no peak rating). The reBot BOM recommends an LRS-350-24 (14.6 A). In the 2026-11-12 incident (see "Torque guard") J4 stalled at 9.5 N·m and ~0.4 s later all motors lost power, consistent with the supply tripping into hiccup.

- **Profile section `power_budget`** (absent = off: no estimate, no governor, no planning step; missing fields take the defaults below; `joints` has no default):

  ```json
  "power_budget": {
    "enabled": true, "supply_rated_a": 6.5, "supply_trip_a": 8.5, "v_bus": 24.0, "base_w": 4.0,
    "k_cu": 1.5, "efficiency": 0.8, "filter_s": 0.25,
    "joints": [{"kt_nm_per_a": 2.015, "r_phase_ohm": 0.72, "idle_w": 0.5, "viscous_nm_s": 0.0, "coulomb_nm": 0.0}, "... one entry per joint, gripper included"],
    "governor": {"enabled": true, "soft": 0.8, "hard": 0.95, "floor_scale": 0.25, "persist_ms": 100, "recover_ms": 300, "down_per_s": 5.0, "up_per_s": 0.5},
    "planning": {"enabled": true, "fraction": 0.75, "min_scale": 0.2, "sample_dt_s": 0.02, "max_samples": 400}
  }
  ```

  `validate()`: `supply_trip_a` ≥ `supply_rated_a` > 0; `v_bus` in [5, 60]; `k_cu` in [0.5, 3]; `efficiency` in (0.3, 1]; one `joints` entry per joint with `kt_nm_per_a` > 0; 0.2 < `soft` < `hard` ≤ 1.2 and `hard` × `supply_rated_a` < `supply_trip_a`; `planning.fraction` in [0.1, `soft`].
- **Model, per joint j** (τ measured torque at the output, ω measured velocity):

  ```text
  P_j   = max(0, τ_j·ω_j) / efficiency + k_cu · (τ_j / kt_j)² · r_phase_j + idle_w_j
  I_bus = (Σ_j P_j + base_w) / v_bus
  regen = Σ_j max(0, −τ_j·ω_j) · efficiency
  ```

  Mechanical power fed back (τ·ω < 0) is not credited: the supply cannot sink it and it raises the bus voltage; it is reported as `regen_w`. Copper loss is counted in full while regenerating (conservative). `k_cu` = 1.5 is the three-phase copper loss 3/2 · I² · R with I the phase-current amplitude and R the per-phase resistance; if the datasheet currents are RMS values the factor would be 3 (not verified). `efficiency` 0.8 covers drive and gearbox losses on the mechanical power (assumed, not measured).
- **B601-DM defaults (`ArmConfig::rebot_dm()`, kit profile)**: supply LRS-150-24, `supply_rated_a` 6.5, `supply_trip_a` 8.5 (teardown measurement), `v_bus` 24 (nominal; the bus voltage is not measured), `base_w` 4 (reCamera, assumed), `idle_w` 0.5 per motor (assumed; the driver idle power is not in the datasheet).

  | joints | motor | `kt_nm_per_a` | `r_phase_ohm` | datasheet source |
  |---|---|---|---|---|
  | J1–J3 | Damiao DM-J4340P-2EC (40:1), armd TMAX 28 N·m | 2.015 | 0.72 | 40 N·m peak at 19.85 A phase; peak supply current 16.0 A |
  | J4–J7 (J7 gripper) | Damiao DM-J4310-2EC (10:1), armd TMAX 10 N·m | 0.625 | 0.58 | 12.5 N·m at 20 A phase with OC 0.98 (11 N·m / 16 A at the default 0.8); peak supply current ≈ 15.4 A |

  For the recommended LRS-350-24 set `supply_rated_a` 14.6 and `supply_trip_a` to its trip current (datasheet range 110–140 % of 14.6 A = 16.1–20.4 A; ~18 is a placeholder, not measured); the governor and planning fractions then apply to 14.6 A.
- **Incident calibration point.** J4 9.5 N·m stalled, J2 2.4 N·m, J3 3.2 N·m holding, J1 0.2, J5 0.3, J6 0.1, J7 0.2 N·m, all at rest: the model gives **8.88 A** (J4 alone 8.40 A), at or above the ~8.5 A trip. J4 stalled alone reaches 6.5 A at 8.17 N·m and 8.5 A at 9.39 N·m (`tests/test_power_budget.rs`). This only shows that the model is not far below the one known overload; it does not validate the parameters.
- **Filtering.** Every control tick with fresh (< 100 ms), valid torque feedback: `fast_a` is a first-order low-pass of the per-tick value with a 40 ms time constant (2 ticks at 50 Hz), the governor input; `bus_a` one with `filter_s` (0.25 s), the displayed value. `peak_a` is the highest `fast_a` over the last ~5 s (10 buckets of 0.5 s); the diagnostics add a 60 s window and the maximum since start. Stale or invalid feedback: no estimate (`valid: false`), the filters restart. Cost: O(joints), no allocation; 28 ns per tick on the build host (aarch64, release, single-threaded; 67–82 ns with other tests running in parallel). The reCamera SG2002 (C906, 1 GHz) is not measured; assuming it is 20–50 times slower, 0.6–4 µs per tick.
- **Governor** (position control: servo streams, jog / joint_move, home, move_to_pose, Cartesian actions, grasp / place sub-motions, replay, park). With r = `fast_a` / `supply_rated_a`:
  - Speed scale target 1 for r ≤ `soft`, linear down to `floor_scale` at r = `hard`; the applied scale follows it by at most `down_per_s` / `up_per_s` per second. `SupervisorInner::motion_time_scale()` is the one value every reference reads each tick: joint quintics, Cartesian paths and replay advance their time at dt × scale (their velocities scale with it); servo streams scale the velocity cap (`servo_max_velocity` / limits) but never below what the joint can brake to within one tick, so the jerk-limited stepper stays feasible, and keep the acceleration limit (braking is not weakened). The speed cap, lead cap, path lag scaling and joint limits keep working on top; the scale only lowers speeds. The gripper is not scaled. The watchdog park budget counts reference time.
  - `motion_limit` = `{reason: "power", joint: null}` while the scale is below 1 and a motion runs.
  - **Hold:** r ≥ `hard` for `persist_ms` (control-loop time) while a motion runs and at least one heavy joint (≥ 25 % of the joints' load above idle) is commanded in the direction of its torque (τ · v_cmd > 0, pushing). The running action fails with `POWER_LIMIT` (message with the estimate and the joint), trajectory / servo stream / macro / replay / park end, J1–J6 hold the measured pose with torque on (`hold_measured_pose`, the gripper keeps its command), `motion_limit` = `{reason: "power", joint}`, one warn log line. No Fault, `safety_state` unchanged.
  - **Moving towards lower load is not blocked.** While the hold lasts, servo frames and jog / joint_move / home targets that move a joint that was pushing at the trip further in its push direction (sign of its torque) are clamped to the hold position for that joint; targets that keep it or move it the other way (yielding, which lowers that joint's torque) pass. Holding still above `hard` does not trip: stopping cannot lower a static (gravity or contact) load; it is logged once, the scale stays at the floor and motions that yield still run. Planned motions started during a hold go through the planning step (below) and the trip rule.
  - **Recovery:** the hold ends when `bus_a` stays below `soft` × rated for `recover_ms`, or at once on torque off, stop, E-stop, a Fault or gravity compensation. The scale then rises at `up_per_s`.
  - **Gravity compensation (hand guiding):** estimated and published, never scaled or held; r ≥ `hard` is logged once per session. Slowing a hand-guided arm is not possible (the person moves it) and holding it would switch modes under the hand; no safe action was found.
  - Transitions (slowing starts / ends, hold, static overload) are logged once each.
- **Planning** (before a planned motion starts: jog / joint_move, home, move_to_pose, park, the replay approach (under the API command's lock, like their workspace check); Cartesian paths of move_to / move_relative and of grasp / place sub-motions (`plan_cartesian`) and replay playback (`replay::plan`), both on the blocking planner thread without the lock; never in the control tick). The trajectory is sampled at `sample_dt_s` (at most `max_samples`); per sample the rigid-body torques come from recursive Newton–Euler (`src/dynamics.rs`, τ = M(q) q̈ + C(q, q̇) q̇ + g(q) from the URDF masses, centres of mass and inertia tensors; the built-in B601-DM model uses the embedded URDF) and, for the motion slowed uniformly by s (duration / s), τ(s) = s² τ_dyn + g + `viscous_nm_s` · s · q̇ + `coulomb_nm` · sign(q̇), ω = s q̇, then the power model. Limit L = `fraction` × rated, or the static load at the start pose + 5 % of rated when that is higher (a move from a pose that already exceeds the budget is refused only if it adds load). Peak ≤ L: runs as planned (`power_scale` 1). Otherwise the largest s in [`min_scale`, 1] whose peak ≤ L is found by bisection (the lower end is always verified, so the result fits; resolution 1e-3) and the motion is slowed: quintics are re-planned with duration / s (from rest this is an exact time scaling; with a start velocity it is not, so the result is re-checked and lowered by 10 % steps), paths and replay get duration / s. If even `min_scale` does not fit, the request is refused with `POWER_BUDGET` (422) and a message with the estimate, the time in the motion and the static load there; park is never refused (it runs at `min_scale` and the governor still applies). The action record carries `power_scale` (the smallest of a macro's sub-motions) and `expected_duration_s` includes the slowing. Friction defaults to 0 (not identified). The fraction 0.75 lies below `soft` 0.8 so that a plan that fits does not make the governor act.

## Torque state after a bus loss / 总线丢失后的力矩状态

In Fault or EStop with torque on, when every motor again reports fresh feedback (younger than 250 ms) and the driver's enable state is Disabled (Damiao: every fresh feedback / 0xCC refresh reply has state 0, `DamiaoArmDriver::enable_state`), armd records that the motors are off: `is_torqued` = false, re-arm needs the full enable handshake, motion is stopped and commanded = measured. The Fault stays latched until `clear_fault`; `clear_fault` then leaves torque off and torque-on works as usual. One warn log line: `Motors report Disabled with fresh feedback in Fault(BusLoss): torque is off ...`. Motivation: on 2026-11-12 the motors came back Disabled after BusLoss and armd kept `is_torqued: true`. Code: `SupervisorInner::sync_torque_state_after_stop` (`src/supervisor.rs`). Not applied during gravity compensation (its exit path owns the motor modes) or while a disable is pending. Motors that come back Enabled: unchanged (torque on, Fault kept). ## Safety self-description / 安全自描述

`GET /api/v1/safety/describe` (no lease; capability `safety_describe`) returns the limits, stops and faults of the running armd as JSON. Code: `src/safety_describe.rs`. Every value is read from the loaded profile, the runtime keep-out and collision settings, or the constant the control code uses (`BUS_LOSS_TIMEOUT`, `CONTROL_DEADLINE`, `PREEMPT_COOLDOWN`, `THERMAL_CLEAR_MARGIN_C`, `WATCHDOG_PARK_*`, `UNLOAD_SETTLE_HOLD`, `MAX_LINEAR_MPS`, `MAX_ANGULAR_RPS`); `tests/test_safety_describe.rs` checks them against those sources. Strings are fixed English identifiers or sentences; clients translate them.

- `describe_version` 1; `device`: `armd_version`, `follower` (the `--follower` name), `profile_version`, `dof`, `joint_names`.
- `timing`: `control_hz`, `lease_timeout_ms`, `heartbeat_recommended_ms` (150, at most a quarter of the lease timeout), `bus_loss_timeout_ms`, `tick_deadline_ms`, `preemption_cooldown_ms`, `following_error` `{max_error_rad, persistence_ms}`.
- `limits`: `joints` `[{name, min, max, max_velocity, max_acceleration}]`, `planned_max_velocity`, `servo_max_velocity`, `workspace` (null without the workspace check), `keepout_boxes` (the boxes in force, each with `source` `profile` / `runtime`), `keepout_source` (`profile` / `runtime`) and `keepout_rule`, `speed_cap`, `action_speed_max` `{linear_mps, angular_rps}` (the action maximum lowered by `speed_cap`).
- `stops`: `e_stop`, `watchdog`, `bus_loss`, `control_deadline`, `following_error`, `thermal`, and `collision_protective_stop` only when the capability `collision_guard` is true. Each has `trigger`, `effect`, `lease_required` (false for all: e-stop needs no lease, the others are automatic), `invalidates_commands`, `fault_code` and `clear` (the recovery steps of that fault code). Effects: `hold_position_torque_on`, `stop_then_torque_off` (thermal), `cancel_motion_hold_torque_on` (collision; `clear` is `["auto_resume"]`). `watchdog.effect` is the outcome for this config: `park_then_torque_off` when the profile has a resting pose and the driver reports velocity, torque and enable state, else `hold_and_fault`; `outcomes` names both, `park_budget` gives `min_ms`, `margin_ms`, `settle_hold_ms`, `settle_grace_ms`. `following_error.servo_stream_effect` is `servo_blocked_hold`. `thermal.available` is false when the driver reports no temperature; `clear_below_c` = `max_temperature_c` − 5.
- `faults`: one entry per fault code `{code, recoverable, recovery, auto_clear}`, `auto_clear` false for all. Recovery steps: `clear_fault`, `torque_on`, `wait_cooldown`, `restore_bus`, `remove_obstruction`, `inspect_message`, `clear_fault_again` (`HARDWARE_FAULT`: the first `clear_fault` sends a motor reset). `FaultCode::ALL` is generated from the enum, and the recovery table is an exhaustive `match`, so a new code does not compile until it is described.
- `hardware`: `physical_estop` (profile field `hardware.physical_estop`, default false), `torque_off_on_fault` false, `notes` (profile `hardware.notes` when set; default: no wired emergency stop (omitted when `physical_estop` is true); motor behaviour on a physical CAN loss depends on the motor's own timeout, unverified; thermal trip and a completed watchdog park turn torque off, every other stop holds torque). `not_a_safety_function` true.

`GET /api/v1/safety/describe`（无需租约；能力 `safety_describe`）以 JSON 返回当前 armd 的限值、停止方式与故障。代码：`src/safety_describe.rs`。所有值都取自已加载 profile、运行时禁入盒与碰撞设置，或控制代码使用的常量（`BUS_LOSS_TIMEOUT`、`CONTROL_DEADLINE`、`PREEMPT_COOLDOWN`、`THERMAL_CLEAR_MARGIN_C`、`WATCHDOG_PARK_*`、`UNLOAD_SETTLE_HOLD`、`MAX_LINEAR_MPS`、`MAX_ANGULAR_RPS`）；`tests/test_safety_describe.rs` 逐项与这些来源比对。字符串为固定英文标识或句子，由客户端翻译。

- `describe_version` 为 1；`device`：`armd_version`、`follower`（`--follower` 名称）、`profile_version`、`dof`、`joint_names`。
- `timing`：`control_hz`、`lease_timeout_ms`、`heartbeat_recommended_ms`（150，不超过租约超时的四分之一）、`bus_loss_timeout_ms`、`tick_deadline_ms`、`preemption_cooldown_ms`、`following_error` `{max_error_rad, persistence_ms}`。

## Unload settle / 收纳稳定判定

A normal unload and the watchdog park plan a trajectory to the resting pose (at least 1.5 s, also from rest), then cut torque only after the settle check passes (`src/supervisor.rs` `step_unload_settle`):

- **Static conditions, every tick:** fresh feedback, enable state `Enabled`, no stop state, each joint within its `position_tolerances` of home, total deviation within `max_total_deviation`, J2 / J3 support torque within `support_torque_limits`. Any failure restarts the hold.
- **Hold:** the static conditions hold for 800 ms (`UNLOAD_SETTLE_HOLD`, measured from the first to the latest sample).
- **Stationary over the hold window, per joint:** position span (max − min) ≤ 4 mrad (`UNLOAD_STILL_POSITION_SPAN_RAD`; average speed ≤ 0.005 rad/s); mean velocity over the window and over its last 300 ms (`UNLOAD_STILL_RECENT`) within the resting-pose velocity limit (J1–J3 0.005, J4–J7 0.015 rad/s); every sample ≤ 4 × that limit (`UNLOAD_STILL_VELOCITY_PEAK_FACTOR`; J1–J3 0.02 rad/s).
- **Why not per-sample velocity:** Damiao velocity has no zero code. At VMAX 10 (J1–J3) raw 2047 / 2048 decode to ∓0.00244 rad/s and raw 2046 / 2049 to ∓0.00733 rad/s, so the 0.005 rad/s limit accepts only the two centre codes; the same two codes as the former 0.015 limit at the old VMAX 30 decoding (both admit |raw − 2047.5| < 1.024). Until 2026-11-09 the settle required 40 consecutive ticks with every sample within the limit, and one sample of ±1.5 LSB restarted it. In `tests/test_park_settle_noise.rs` (rebot-dm, DamiaoArmDriver over mock CAN, Gaussian velocity noise on J1–J3 clipped at ±3 LSB, torque noise σ 2 LSB, 20 seeds), the settle after the trajectory took:

  | Velocity noise σ (LSB) | 0 | 0.3 | 0.5 | 0.75 | 1.0 | 1.5 | 2.0 |
  |---|---|---|---|---|---|---|---|
  | Per-sample rule: settled within 20 s | 20/20 | 20/20 | 6/20 | 0/20 | 0/20 | 0/20 | 0/20 |
  | Per-sample rule: median / max (s) | 0.80 / 0.80 | 0.80 / 1.40 | 9.00 / 17.12 | — | — | — | — |
  | Window rule: settled within 20 s | 20/20 | 20/20 | 20/20 | 20/20 | 20/20 | 20/20 | 20/20 |
  | Window rule: median / max (s) | 0.80 / 0.80 | 0.80 / 0.80 | 0.80 / 0.80 | 0.80 / 0.80 | 0.80 / 0.80 | 0.80 / 0.80 | 0.80 / 0.94 |

  The noise level of the real motors at rest is not measured; the settle report below shows which condition blocks on hardware.
- **Torque off:** after the window check the torque-off path re-checks the static conditions on the current sample; the per-sample velocity check is replaced by the window check only on this path. `set_torque(false)` from the API still uses the per-sample check.
- **Settle report:** a settle pending longer than 1.8 s logs `Unload settle pending for N s: …` once per second, listing every failing condition per joint with its value and limit (for example `joint 2 torque 7.40 Nm (limit 7)`, `joint 1 velocity peak 0.0415 rad/s (limit 0.02)`, `joint 3 moved 0.0061 rad in 0.8 s (limit 0.004)`).
- **Watchdog park budget**, in control-loop time (the sum of tick `dt`): max(10 s, deceleration + planned duration + 0.8 s + 3 s). Deceleration is max over joints of |measured velocity| / planning acceleration; the planned duration already starts from the commanded velocity of a jog in progress. The log prints `Watchdog park budget …` when the park starts. Example: planned 9.43 s (the 2026-11-09 incident, inferred from its 12.43 s deadline), J3 at 0.45 rad/s with 5 rad/s² → 0.09 + 9.43 + 0.8 + 3 = 13.32 s, previously 12.43 s.
- **Settle grace:** when the budget runs out with the trajectory finished and every static condition met (only the stationary check pending), the park gets 5 s more once (`WATCHDOG_PARK_SETTLE_GRACE`, warning with the blocker). Otherwise, and when the grace runs out, torque is held and `Fault(WatchdogTimeout)` latched; a blocked arm or one above the support-torque limit gets no grace.

正常卸载与看门狗收纳先规划到收纳位的轨迹（至少 1.5 s，从静止开始也是如此），稳定判定通过后才断力矩（`src/supervisor.rs` `step_unload_settle`）：

- **静态条件，每个 tick 检查**：反馈新鲜、使能状态为 `Enabled`、不处于停止状态、各关节与收纳位偏差在 `position_tolerances` 内、总偏差在 `max_total_deviation` 内、J2 / J3 支撑力矩在 `support_torque_limits` 内。任一失败则保持计时重新开始。
- **保持**：静态条件持续 800 ms（`UNLOAD_SETTLE_HOLD`，从首个样本到最新样本计时）。
- **保持窗口内静止，逐关节**：位置跨度（最大 − 最小）≤ 4 mrad（`UNLOAD_STILL_POSITION_SPAN_RAD`，平均速度 ≤ 0.005 rad/s）；整个窗口和最近 300 ms（`UNLOAD_STILL_RECENT`）的平均速度不超过收纳位速度限值（J1–J3 0.005、J4–J7 0.015 rad/s）；每个样本 ≤ 该限值的 4 倍（`UNLOAD_STILL_VELOCITY_PEAK_FACTOR`，J1–J3 为 0.02 rad/s）。
- **不再逐样本判速度的原因**：达妙速度没有零值编码。VMAX 10（J1–J3）时原始值 2047 / 2048 解码为 ∓0.00244 rad/s，2046 / 2049 为 ∓0.00733 rad/s，0.005 rad/s 限值只接受中间两个编码；与旧的 VMAX 30 解码下 0.015 限值接受的两个编码相同（两者都是 |raw − 2047.5| < 1.024）。2026-11-09 之前稳定判定要求连续 40 个 tick 每个样本都在限值内，一个 ±1.5 LSB 的样本就重新计时。`tests/test_park_settle_noise.rs`（rebot-dm，DamiaoArmDriver 接 mock CAN，J1–J3 速度加高斯噪声并截断在 ±3 LSB，力矩噪声 σ 2 LSB，20 个随机种子）中轨迹结束后的稳定用时见上表（Per-sample rule = 旧规则，Window rule = 新规则；settled within 20 s = 20 s 内完成的次数，median / max = 中位数 / 最大值）。电机静止时的实际噪声水平尚未测量；下文的稳定报告日志会给出实机上卡住的条件。
- **断力矩**：窗口判定通过后，断力矩路径对当前样本复查静态条件；只有这条路径用窗口判定代替逐样本速度判定。API 的 `set_torque(false)` 仍逐样本判速度。
- **稳定报告**：稳定判定超过 1.8 s 未完成时，每秒记录一次 `Unload settle pending for N s: …`，逐关节列出所有未满足的条件及数值和限值（例如 `joint 2 torque 7.40 Nm (limit 7)`、`joint 1 velocity peak 0.0415 rad/s (limit 0.02)`、`joint 3 moved 0.0061 rad in 0.8 s (limit 0.004)`）。
- **看门狗收纳时限**，按控制循环时间（各 tick `dt` 之和）计：max(10 s, 减速时间 + 规划时长 + 0.8 s + 3 s)。减速时间取各关节 |实测速度| / 规划加速度的最大值；进行中的 jog 的指令速度已包含在规划时长中。收纳开始时日志输出 `Watchdog park budget …`。例：规划 9.43 s（2026-11-09 事件，由其 12.43 s 期限推得），J3 0.45 rad/s、加速度 5 rad/s² → 0.09 + 9.43 + 0.8 + 3 = 13.32 s，原为 12.43 s。
- **稳定宽限**：时限用完时若轨迹已结束且静态条件全部满足（只剩静止判定未通过），收纳一次性延长 5 s（`WATCHDOG_PARK_SETTLE_GRACE`，记录 warning 及卡住的条件）。否则，或宽限也用完时，保持力矩并锁存 `Fault(WatchdogTimeout)`；被卡住或超过支撑力矩限值的机械臂不获宽限。

## Damiao mapping ranges / 达妙电机映射范围

Damiao motors map the 16-bit position and 12-bit velocity / torque fields of feedback and MIT frames onto ±PMAX, ±VMAX and ±TMAX (registers 21–23). The B601-DM motors report (read 2026-11-09, request `[id, 0, 0x33, rid, 0, 0, 0, 0]` on `0x7FF`, reply `[id, 0, 0x33, rid, value LE]` on `0x10 + id`): J1–J3 CTRL_MODE 2, PMAX 12.5, VMAX 10, TMAX 28; J4–J7 CTRL_MODE 2, PMAX 12.5, VMAX 30, TMAX 10. The rebot-dm profile sets these as `damiao_ranges`; feedback is decoded and MIT frames are encoded per joint. Before this, every motor was decoded with 12.5 / 30 / 18: J1–J3 velocity read 3× the real value, J1–J3 torque 0.643× and J4–J7 torque 1.8×. Thresholds tuned on those readings were converted (table below).

- **Startup range check.** When `armd` mounts the rebot-dm driver it reads registers 10, 21, 22 and 23 from each motor before anything can enable them (register reads do not change the enable state; no enable frame is sent). Up to 20 ms per motor: about 7 × (4 frames + reply) when all answer, at most 140 ms with all seven silent. The result is published in every observation as `driver_range_check` (`status` `passed` | `mismatch` | `unverified`, `message`, `duration_ms`, and per joint `joint`, `motor_id`, `status`, `ctrl_mode`, `reported` [PMAX, VMAX, TMAX] or null, `configured`).
  - `mismatch`: a motor reports a different range. Logged as an error; every enable (`/api/v1/torque`, arm) fails with a hardware fault naming the joints until the profile's `damiao_ranges` matches the motors and `armd` is restarted.
  - `unverified`: a motor did not answer. Logged as a warning; the configured ranges are used. The check is read again before each enable and becomes `passed` (or `mismatch`) once every motor answers.
  - A joint whose CTRL_MODE is not POS_VEL (left in MIT by an interrupted session) is marked unconfirmed; the enable handshake writes POS_VEL to it first.
  - Gravity compensation is refused with `DRIVER_RANGE_MISMATCH` / `DRIVER_RANGE_UNVERIFIED` unless the check passed. The MIT range readback before the first switch to MIT is skipped for joints the startup check verified.

**Threshold migration (2026-11-09).** Every use of measured torque or velocity was checked. ## Gravity compensation (hand-guiding) / 重力补偿（拖动示教）

Status: implemented and tested against a simulated arm (`tests/test_gravity_comp.rs`, `tests/test_gravity_comp_api.rs`, `tests/test_damiao_mode_switch.rs`). Verified on the reBot B601-DM (exit paths held the arm within 1.5 mrad; a 30 s hand-guided recording gave 1509 frames; results in the README). Code: `src/gravity_comp.rs`; parameters: `ArmConfig.gravity_comp` (`GravityCompPolicy`, set for rebot-dm, `None` elsewhere = unsupported).

- **Control law.** J1–J6 run in Damiao MIT mode with kp = 0, damping `damping_kd` and feed-forward τ = clamp(URDF gravity torque × `scale`, ±`torque_limits_nm`). The gripper stays in POS_VEL at its commanded position.
- **Mode switch (Damiao).** The control mode is register 10 (CTRL_MODE: 1 = MIT, 2 = POS_VEL), written in RAM with a `0x7FF` frame `[id_l, id_h, 0x55, 10, value u32 LE]`; MIT frames go to CAN ID = motor ID, POS_VEL frames to `0x100 + ID`. The motor is not disabled for the switch. The layout follows Damiao's DM_CAN reference library; register reads were confirmed on the B601-DM (2026-11-09) and the writes work in the verified gravity-compensation mode switch. Sequence per joint: write CTRL_MODE, then the hold frame in the new mode immediately after it on the bus, then wait up to 50 ms for the write acknowledgement (`[id_l, id_h, 0x55, 10, value]` on the feedback ID). An unacknowledged joint is switched back and held with both a POS_VEL and an MIT frame; a joint that still cannot be confirmed keeps receiving both frames on every write and latches a fault. Before the first switch to MIT the driver reads PMAX / VMAX / TMAX (registers 21–23) and refuses the mode when they differ from that joint's configured range (`damiao_ranges`; rebot-dm: J1–J3 ±12.5 rad, ±10 rad/s, ±28 N·m, J4–J7 ±12.5 rad, ±30 rad/s, ±10 N·m; profiles without `damiao_ranges` use ±12.5 / ±30 / ±18 for every joint), because a different TMAX scales every torque command. Feedback is decoded with the same per-joint ranges. CTRL_MODE is not stored to flash; the next enable handshake restores POS_VEL on any joint left in another mode, and a motor power cycle returns to the flashed mode.
- **Entry** (`GRAVITY_COMP_*` or the usual codes otherwise): rebot-dm profile with the verified URDF and a driver that can switch joints (`UNSUPPORTED`); no E-stop or fault; torque on and state `Armed` (`NOT_ARMED`); no trajectory, servo stream, grasp or park (`MOTION_BUSY`); lease held (`LEASE_REQUIRED`); feedback younger than `feedback_max_age_ms` (`FEEDBACK_STALE`); every arm joint slower than `entry_max_velocity` (`GRAVITY_COMP_NOT_STATIONARY`); no joint within `joint_limit_margin_rad` of a limit (`GRAVITY_COMP_JOINT_LIMIT`); model torque computable (`GRAVITY_MODEL_UNAVAILABLE`). A failed switch is `GRAVITY_COMP_SWITCH_FAILED`.
- **Ramp-in.** The switch frame holds the measured pose with `hold_kp` / `hold_kd` and the torque the motor reported (the load the position loop was carrying). Over `ramp_in_s` the stiffness fades to 0, the damping to `damping_kd`, and the feed-forward from the reported torque to the model torque. A joint that moves more than `ramp_max_deviation_rad` from the entry pose during the ramp ends the mode (`GRAVITY_COMP_SAG`).
- **Exit.** Every exit captures the measured pose and at once sends an MIT stiff hold there (`hold_kp`, `hold_kd`, feed-forward unchanged); after `exit_hold_ms` J1–J6 are switched back to POS_VEL holding that pose. POS_VEL frames carry no torque, so the feed-forward ends with that switch and the motor's position loop carries the load. If the switch back is not acknowledged the MIT stiff hold continues, `GRAVITY_COMP_EXIT_FAILED` is latched as a fault (it cannot be cleared before POS_VEL is confirmed), and the switch is retried every 0.5 s.
- **Exit causes and codes** (`gravity_comp.last_exit.code`): `REQUESTED` (mode command), `STOPPED` (`/api/v1/motion/stop`), `ESTOP`, `FAULT`, `BUS_LOSS`, `FEEDBACK_STALE` (older than `feedback_max_age_ms`), `WATCHDOG` (no heartbeat for the lease timeout), `LEASE_LOST` (released, expired or taken over), `TORQUE_LOST`, `GRAVITY_COMP_OVERSPEED` (a joint faster than its limit for `overspeed_ticks` ticks, speed = max of reported velocity and position difference per tick; the limit is `joint_max_speed_rad_s` / `max_speed_rad_s` when the joint moves with the model gravity torque (falling), and `lift_max_speed_rad_s` when it moves against it (lifted by hand) or carries less than 0.3 N·m of it), `GRAVITY_COMP_SAG`, `GRAVITY_COMP_JOINT_LIMIT`, `GRAVITY_MODEL_UNAVAILABLE`. None of them turns torque off. E-stop and bus-loss handling send the hold in the same call; the others act at the next control tick (≤ 20 ms at 50 Hz). Overspeed is reported as the exit reason, not as a fault.
- **Watchdog.** While the mode is on the lease watchdog does not start a park. A heartbeat gap first ends the mode (`WATCHDOG`, hold at the measured pose); once the arm is back in POS_VEL the existing watchdog logic runs on the next tick (park, or hold and `Fault(WatchdogTimeout)`).
- **Exceptions.** A thermal trip still disables torque, as in position mode. With a complete bus loss no hold frame reaches the motors: they keep executing the last MIT command (model feed-forward and damping) until the bus returns, and the switch back is retried.
- **Tracking error.** While floating the reference of J1–J6 is set to the measured position every tick, so intended hand motion produces no following error; during the exit the reference is the captured pose and the following-error check applies. Overspeed, hardware fault, feedback and thermal checks stay active.
- **Commands while on.** Servo frames, `jog`, `home`, presets, `unload`, `torque` and the `move_to` / `move_relative` / `grasp` actions return `409 MOTION_BUSY`. Accepted: the mode command, `motion/stop` (exits), E-stop (exits), `action/gripper`, grasp setup, recording (REST).
- **Recording.** Each tick still appends one frame; while floating `action` equals `observation.state` for J1–J6.
- **Observation.** `control_mode` (`position` | `gravity_comp`, any phase) and `gravity_comp`: `supported`, `blocker` (`{code, message}` or null), `phase` (`ramp_in`, `active`, `exiting`, `exit_failed`), `ramp` (0..1), `scale`, `damping_kd`, `tau_ff` (N·m sent to J1–J6), `last_exit` (`{code, message, at}`).
- **rebot-dm defaults** (software values, not measured): `ramp_in_s` 1.0, `scale` 1.0 (override range 0.5–1.2), `damping_kd` [0.4, 0.6, 0.5, 0.35, 0.15, 0.1] (override ≤ 2.0), `torque_limits_nm` [2, 12, 8.5, 3, 1.5, 0.5], `max_speed_rad_s` 1.5 with per-joint `joint_max_speed_rad_s` [1.5, 1.5, 1.5, 3.0, 3.0, 3.0] (a hand flick of the wrist reached 2.5 rad/s on the real arm), `lift_max_speed_rad_s` [3.0, 3.0, 3.0, 3.0, 3.0, 3.0] (lifting the arm off the folded pose by hand reached 1.59 and 2.16 rad/s on J3, 2026-11-12), `overspeed_ticks` 3, `hold_kp` [30, 30, 30, 15, 10, 8], `hold_kd` [1, 1, 1, 0.5, 0.3, 0.2], `exit_hold_ms` 100, `entry_max_velocity` 0.05, `feedback_max_age_ms` 100, `joint_limit_margin_rad` 0.05, `ramp_max_deviation_rad` 0.15. The URDF model torque reaches 16.3 N·m on J2 with the arm stretched out horizontally (grid maximum), above the 12 N·m clamp.

状态：已实现，并在仿真机械臂上测试（`tests/test_gravity_comp.rs`、`tests/test_gravity_comp_api.rs`、`tests/test_damiao_mode_switch.rs`）。已在 reBot B601-DM 上实机验证（各退出路径保持位置偏差不超过 1.5 mrad；30 s 拖动录制 1509 帧；结果见 README）。 代码在 `src/gravity_comp.rs`，参数在 `ArmConfig.gravity_comp`（rebot-dm 已设置，其他 profile 为 `None`，即不支持）。

- **控制律**：J1–J6 用达妙 MIT 模式，kp = 0，阻尼 `damping_kd`，前馈 τ = clamp(URDF 重力力矩 × `scale`, ±`torque_limits_nm`)。夹爪保持 POS_VEL，停在指令位置。
- **模式切换（达妙）**：控制模式是 10 号寄存器（CTRL_MODE：1 = MIT，2 = POS_VEL），用 `0x7FF` 帧 `[id_l, id_h, 0x55, 10, 值 u32 小端]` 写入 RAM；MIT 帧发往 CAN ID = 电机 ID，POS_VEL 帧发往 `0x100 + ID`。切换时不失能电机。帧格式依据达妙 DM_CAN 参考库；寄存器读取已在 B601-DM 上核对（2026-11-09），写入尚未在实机上核对。每个关节的顺序：写 CTRL_MODE，总线上紧接着发新模式下的保持帧，然后最多等待 50 ms 的写入应答（反馈 ID 上的 `[id_l, id_h, 0x55, 10, 值]`）。未应答的关节切回原模式，并同时用 POS_VEL 帧和 MIT 帧保持；仍无法确认的关节此后每次写入都收到两种帧，并锁存故障。第一次切到 MIT 前，驱动读取 PMAX / VMAX / TMAX（21–23 号寄存器），与该关节配置的范围（`damiao_ranges`；rebot-dm：J1–J3 为 ±12.5 rad、±10 rad/s、±28 N·m，J4–J7 为 ±12.5 rad、±30 rad/s、±10 N·m；未设置 `damiao_ranges` 的 profile 所有关节用 ±12.5 / ±30 / ±18）不一致时拒绝进入，因为 TMAX 不同会按比例改变每个力矩指令。反馈也按同一组分关节范围解码。CTRL_MODE 不写入 flash；下一次使能握手会把仍处于其他模式的关节恢复为 POS_VEL，电机断电重启后回到 flash 中的模式。
- **进入条件**（不满足时返回对应错误码）：rebot-dm profile、URDF 校验通过、驱动能切换关节模式（`UNSUPPORTED`）；无急停、无故障；力矩开启且状态为 `Armed`（`NOT_ARMED`）；没有轨迹、servo 流、抓取或收纳（`MOTION_BUSY`）；持有租约（`LEASE_REQUIRED`）；反馈不超过 `feedback_max_age_ms`（`FEEDBACK_STALE`）；各臂关节速度低于 `entry_max_velocity`（`GRAVITY_COMP_NOT_STATIONARY`）；没有关节在限位 `joint_limit_margin_rad` 以内（`GRAVITY_COMP_JOINT_LIMIT`）；能算出模型力矩（`GRAVITY_MODEL_UNAVAILABLE`）。切换失败返回 `GRAVITY_COMP_SWITCH_FAILED`。
- **渐入**：切换帧以 `hold_kp` / `hold_kd` 保持实测位姿，前馈取电机反馈的当前力矩（位置环正在承担的负载）。在 `ramp_in_s` 内刚度降到 0，阻尼过渡到 `damping_kd`，前馈从反馈力矩过渡到模型力矩。渐入期间任一关节偏离进入位姿超过 `ramp_max_deviation_rad` 即退出（`GRAVITY_COMP_SAG`）。
- **退出**：所有退出都先记录实测位姿，立即在该位姿发送 MIT 刚性保持（`hold_kp`、`hold_kd`，前馈不变）；`exit_hold_ms` 后 J1–J6 切回 POS_VEL 保持该位姿。POS_VEL 帧不带力矩，前馈随切换结束，之后由电机位置环承担负载。切回未被应答时继续 MIT 刚性保持，锁存故障 `GRAVITY_COMP_EXIT_FAILED`（POS_VEL 确认之前不能清除），每 0.5 s 重试一次切换。
- **退出原因与代码**（`gravity_comp.last_exit.code`）：`REQUESTED`（模式指令）、`STOPPED`（`/api/v1/motion/stop`）、`ESTOP`、`FAULT`、`BUS_LOSS`、`FEEDBACK_STALE`（超过 `feedback_max_age_ms`）、`WATCHDOG`（超过租约超时没有心跳）、`LEASE_LOST`（释放、过期或被接管）、`TORQUE_LOST`、`GRAVITY_COMP_OVERSPEED`（任一关节超过其限值连续 `overspeed_ticks` 个 tick，速度取反馈速度与每 tick 位置差分中的较大者；关节顺着模型重力力矩方向运动（下坠）时限值为 `joint_max_speed_rad_s` / `max_speed_rad_s`，逆着重力方向运动（用手抬起）或重力力矩小于 0.3 N·m 时为 `lift_max_speed_rad_s`）、`GRAVITY_COMP_SAG`、`GRAVITY_COMP_JOINT_LIMIT`、`GRAVITY_MODEL_UNAVAILABLE`。这些都不会断力矩。急停和总线中断在同一次调用中发出保持帧，其他原因在下一个控制 tick 生效（50 Hz 时 ≤ 20 ms）。超速作为退出原因上报，不锁存故障。
- **看门狗**：模式开启期间租约看门狗不启动收纳。心跳中断先退出本模式（`WATCHDOG`，在实测位姿保持）；回到 POS_VEL 后，下一个 tick 由原有看门狗逻辑处理（收纳，或保持并锁存 `Fault(WatchdogTimeout)`）。
- **例外**：过温保护仍会断力矩，与位置模式相同。总线完全中断时保持帧到不了电机，电机继续执行最后一条 MIT 指令（模型前馈加阻尼），直到总线恢复，期间持续重试切回。
- **跟随误差**：漂浮期间 J1–J6 的参考位置每个 tick 取实测值，用手推动不产生跟随误差；退出期间参考位置为记录的位姿，跟随误差检查照常生效。超速、硬件故障、反馈和温度检查一直有效。
- **模式开启时的指令**：servo 帧、`jog`、`home`、预设、`unload`、`torque` 以及 `move_to` / `move_relative` / `grasp` 动作返回 `409 MOTION_BUSY`。可用：模式指令、`motion/stop`（退出）、急停（退出）、`action/gripper`、抓取设置、录制（REST）。
- **录制**：每个 tick 照常追加一帧；漂浮期间 J1–J6 的 `action` 等于 `observation.state`。
- **观测**：`control_mode`（`position` | `gravity_comp`，任何阶段）与 `gravity_comp`：`supported`、`blocker`（`{code, message}` 或 null）、`phase`（`ramp_in`、`active`、`exiting`、`exit_failed`）、`ramp`（0..1）、`scale`、`damping_kd`、`tau_ff`（发给 J1–J6 的前馈，N·m）、`last_exit`（`{code, message, at}`）。
- **rebot-dm 默认值**（软件取值，未实测）：见上方英文列表。URDF 模型在机械臂水平伸直时 J2 力矩达 16.3 N·m（网格最大值），高于 12 N·m 的限幅。

### Hardware verification checklist / 实机核实清单

Ordered from no motion to full use. Keep a hand on the arm and the power cut-off within reach from step 4 on.

1. Arm unpowered or disabled: read registers 10 and 21–23 of every motor (`0x7FF`, `[id, 0, 0x33, rid, 0, 0, 0, 0]`) and compare PMAX / VMAX / TMAX with the driver ranges (±12.5 / ±30 / ±18). If they differ, configure matching ranges before anything else (entry is refused until then).
2. Disabled motor: write CTRL_MODE = 1 and back to 2 on one joint; confirm the acknowledgement layout and that the value reads back.
3. Arm supported at the resting pose, torque on, one joint (J6, lightest load): switch that joint to MIT with a stiff hold and back while logging position; confirm no motion beyond a few mrad and no disable.
4. Same pose: compare the URDF gravity torque with the reported holding torque of J2–J4 in POS_VEL at a few poses; adjust `scale` if needed.
5. Enter the mode with the arm held by hand at a low pose; watch the ramp (`tau_ff`, positions). Check that `GRAVITY_COMP_SAG` / overspeed exits end in a hold.
6. Exit (button, stop, E-stop, unplug the WebSocket client, lease takeover) and measure the sag when the feed-forward ends at the switch back to POS_VEL.
7. Pull the CAN connector briefly while floating (bus loss) with the arm supported; confirm the behaviour after reconnection.
8. Hand-guide over the workspace; tune `damping_kd`, `max_speed_rad_s`; record an episode and check the file.

1. 不上电或失能：读取每个电机的 10 号与 21–23 号寄存器（`0x7FF`，`[id, 0, 0x33, rid, 0, 0, 0, 0]`），将 PMAX / VMAX / TMAX 与驱动范围（±12.5 / ±30 / ±18）比较；不一致时先配置一致的范围（在此之前无法进入本模式）。
2. 电机失能：对一个关节写 CTRL_MODE = 1 再改回 2，确认应答格式和回读值。
3. 机械臂在收纳位有支撑、力矩开启，只对一个关节（负载最小的 J6）：切到 MIT 刚性保持再切回，同时记录位置，确认位移不超过几 mrad 且未失能。
4. 同一位姿：在几个位姿下比较 POS_VEL 时 J2–J4 的反馈保持力矩与 URDF 重力力矩，必要时调整 `scale`。
5. 用手扶住机械臂、在较低位姿进入本模式，观察渐入（`tau_ff`、位置）；确认 `GRAVITY_COMP_SAG` / 超速退出后进入保持。
6. 逐一测试退出（按钮、停止、急停、断开 WebSocket 客户端、被接管），测量切回 POS_VEL、前馈结束时的下沉量。
7. 机械臂有支撑时，在漂浮状态下短暂拔掉 CAN 插头（总线中断），确认恢复连接后的行为。
8. 在工作空间内拖动示教；调整 `damping_kd`、`max_speed_rad_s`；录制一个片段并检查文件。

## Configuration / 配置

`--config` loads a complete `ArmConfig` JSON. `profile_version` is the arm profile contract version (missing = 1; armd refuses versions newer than `ARM_PROFILE_VERSION`, currently 1). Core fields are `dof`, `joint_names`, `limits`, `home_positions`, `lease_timeout_ms`, `max_temperature`, and `control_frequency_hz`; optional fields are `resting_pose`, `following_error`, `max_jerk`, `gravity_model`, `planned_max_velocity`, `speed_cap`, `collision`, `servo_max_velocity`, `servo_max_lead_rad`, `kinematics`, `workspace`, `camera_mount`, `gripper_policy`, `grasp`, `gravity_comp` (requires dof 7 and `gravity_model`), and `damiao_ranges` (one `{p_max, v_max, t_max}` per joint; the Damiao feedback decoding and MIT encoding range of each motor). Follower DOF is fixed by model (`rebot-dm=7`; `rebot-rs`, `so-arm101`, `fashionstar`, and `star-arm102=6`), and mismatches are rejected. `--leader` and `--leader-port` are rejected because leader-following is not implemented.

`--config` 加载完整 `ArmConfig` JSON。`profile_version` 是机械臂 profile 契约版本（缺省为 1；高于 `ARM_PROFILE_VERSION`（当前为 1）的版本会被拒绝）。核心字段为 `dof`、`joint_names`、`limits`、`home_positions`、`lease_timeout_ms`、`max_temperature`、`control_frequency_hz`；可选字段为 `resting_pose`、`following_error`、`max_jerk`、`gravity_model`、`planned_max_velocity`、`speed_cap`、`collision`、`servo_max_velocity`、`servo_max_lead_rad`、`kinematics`、`workspace`、`camera_mount`、`gripper_policy`、`grasp`、`gravity_comp`（要求 dof 为 7 且设置了 `gravity_model`）、`damiao_ranges`（每个关节一组 `{p_max, v_max, t_max}`，即该达妙电机的反馈解码与 MIT 编码范围）。follower 的 DOF 按型号固定（`rebot-dm=7`；`rebot-rs`、`so-arm101`、`fashionstar`、`star-arm102=6`），不匹配会拒绝启动。`--leader` 与 `--leader-port` 因主从功能未实现而被拒绝。
