# 计划：驾驶舱点框抓取（Tap-to-Grasp）

状态：第一版已实施，未经真机验证（2026-11-09）。实现与本计划的差异见 §7；接口见 `docs/agent_action_api.md`「Grasp / 点框抓取」。

原前置：视角模式遥操作先落地；本功能不依赖它的 6 轴 IK，可独立开发。

## 1. 范围

用户在驾驶舱开启「识别」→ 画面上的检测框可点击 → 点一个框 → 确认「抓取」→ 机械臂自动完成：俯视对准 → 下降 → 夹紧 → 抬起到安全高度保持。放置由用户手动遥操作完成。

不做：任意点击定位（点空白处移动）、拖拽、双指旋转、自动放置、高物体 / 叠放物体（第一版）。

## 2. 硬件前提与已知约束

- 单目 eye-in-hand：reCamera 装在 J6 之后，随 J6 转动（真机实测：J5 为摆动，J6 为滚转）。
- 无深度。3D 位置的获取方式：
  - **水平 X/Y**：闭环视觉对中。每帧比较框中心与「夹爪位置像素」的偏差，按偏差小步移动 TCP，直到偏差 < 阈值。不需要精确内参与手眼标定，误差靠闭环收敛。
  - **高度 Z**：机械臂 FK 已知自身高度；桌面高度一次性测量；抓取高度 = 桌面 + 固定偏移（物体放在桌上）。
  - 后续（高物体）：下降过程中框尺寸 s₁→s₂，下降距离 Δh 由 FK 已知，Z₁ = Δh·s₂/(s₂−s₁)，不依赖内参。
- 检测：设备上的 yolo-detector（COCO 类别，只有框、无 mask、无 track id）。框无角度 → J6 只能取 0° / 90°（沿框短边夹）。
- 夹爪：J7，POS_VEL。armd 当前**没有**开机零位校验（`src/supervisor.rs` 只有 stall 检测）。

## 3. 可复用的已有实测结论

此前一个基于深度相机的 B601-DM 抓取原型（3D 定位方式不同，不可复用）在真机上测得以下逻辑与参数：

| 内容 | 用法 |
|---|---|
| 夹持判定：开口间隙 ≥ 0.30 rad（≈5 mm）且持续夹持力矩 ≥ 0.12 N·m（旧 TMAX 18 解码下的读数；按 J7 实际 TMAX 10 为 0.0667 N·m，见 `docs/control_safety_contract.md`） | 抓取成功判定；闭空则张开重试 |
| 全开欠行程 ≈0.1 rad 且带残余力矩；物体 ≥≈82 mm 与限位不可区分 | 演示物体 ≤ 75 mm；全开判定留余量 |
| 断裂开口 ≈105 mm，指令最大 9 cm | 夹爪开口上限 |
| J4310 单圈编码器：上电未完全闭合时零位偏移（实测 +4.63 / +1.67 rad），需每次开机堵转回零 | **前置安全项**，见 §5 步骤 0 |
| 自适应夹持：从轻力起步，逐步升到上限，直到开口不再变化 | 未知物体的夹持策略（POS_VEL 下用位置步进 + 电流判定近似） |
| 抓取阶段与取消检查：open → pregrasp → servo 校正 → grasp_move → grasp → 闭空检查 → lift | 状态机结构 |
| servo 校正只接受 4–30 mm 的偏移，<4 mm 视为噪声，>30 mm 视为误检 | 对中步的门限 |
| 多帧稳定：中心距 < 35 px 或 IoU > 0.45 视为同一目标，取中位数 | 跟踪被点选的框 |
| 掩码最小外接矩形短轴定向 | 若以后检测器输出 mask，J6 可任意角度对齐 |
| 桌面边界标定 | 桌面高度标定的参考 |

## 4. 交互设计（沿用现有驾驶舱样式）

1. 「识别」开启后，叠加层的框可点击（命中测试在 overlay 上做；不改现有绘制样式，选中框加高亮描边）。
2. 点框 → 视频区底部出现「抓取 / 取消」按钮组（现有 `.btn` 样式），显示类别与置信度。
3. 抓取中：显示当前阶段（对准 / 下降 / 夹紧 / 抬起）与进度；「停止」按钮常驻。
4. 任一中止条件 → 停在当前位置（保持力矩），提示原因：
   - 用户操作任意摇杆 / 按键 / 点停止 / 急停；
   - 目标连续丢失 > 1 s；
   - 单阶段超时；
   - IK / 限位 / 地面 / 滞后保护触发（复用 `cartTick` 现有保护）。
5. 抽屉新增「抓取设置」：桌面高度（让臂慢降触桌或手动输入）、夹爪位置像素（物体放在张开的夹爪之间，点一下画面记录）、抓取偏移、速度。

## 5. 实施步骤

0. **夹爪零位校验（armd，安全前置）**：开机或首次使能时，夹爪低速闭合直到堵转，确认堵转位置在 0 ± 0.15 rad 内；否则锁存故障、禁止张开超过安全值。先在真机读一次上电后的 J7 位置，确认是否存在偏移问题。
1. **框可点击**：overlay 命中测试、选中状态、跨帧跟踪（类别相同 + IoU / 中心距门限，取多帧中位数）。
2. **抓取状态机（浏览器侧）**：通过 `C.goal` 驱动现有笛卡尔通道（限速、跳变、滞后、地面保护、租约看门狗全部保留）。
   - a. 张开夹爪到 min(框宽估计 + 余量, 9 cm)；
   - b. 移到目标上方、俯视（pitch = 90°），高度 = 桌面 + 安全高度；
   - c. 对中：按像素偏差小步移动 X/Y，直到偏差 < 阈值并稳定 N 帧；J6 转到框短边方向（0° / 90°）；
   - d. 下降到抓取高度，下降中持续对中，直到框超出画面或尺寸超过阈值后停止对中、盲降剩余距离；
   - e. 夹紧，按 §3 的夹持判定；闭空 → 张开、抬起、提示「未抓到」，可重试一次；
   - f. 抬起到安全高度保持，交还用户控制。
3. **抓取设置与持久化**：桌面高度、夹爪像素、偏移存 localStorage（与标定模式同样的方式）。
4. **i18n**：中英文全部新文案。
5. **测试**：
   - 自测脚本：假检测序列驱动状态机（对中收敛、丢失中止、闭空重试、超时）；
   - 真机：杯子 / 瓶子等 COCO 类物体，记录成功率、对中残差、单次耗时。

## 6. 待真机确认

- 俯视时相机能否看到夹爪正下方区域（决定闭环对中是否可行）。
- 目标物是否在 yolo-detector 当前模型的类别内。
- 夹爪最大开口与 J7 角度的对应关系（未测）。
- 检测帧率与延迟（对中环路增益按此设定）。
- J7 上电零位是否偏移（步骤 0）。

## 7. 实施情况（2026-11-09）

已实施：

- armd 动作 `/api/v1/action/grasp`（`src/grasp.rs`），走 WS 租约，与其他动作相同的 command / ack / action_id / status 流程。阶段：张开 → 俯视接近 → 闭环对中 → J6 对齐（0° / 90°）→ 下降 → 夹紧并判定 → 抬起。`action.phase` / `iteration` / `error_px` 报告进度。
- 抓取设置：`ArmConfig.grasp` 提供默认值，`GET /api/v1/grasp/setup` 读取，WS 指令 `/api/v1/grasp/setup` 修改，保存到 `ARMD_GRASP_SETUP`（默认 `/userdata/rebot-teleop/grasp_setup.json`）。相机俯角 `camera_tilt_deg` 即 `camera_mount.tilt_deg`，可在设置中修改。
- 驾驶舱：开启识别后点框 → 确认条（类别、置信度、抓取 / 取消）→ 运行中显示阶段、进度与停止按钮；摇杆 / 按键 / 点动、停止按钮、急停都会中止；结果以提示条显示。「抓取设置」抽屉：桌面高度（用当前夹爪尖高度）、夹爪位置像素（点画面）、接近 / 抓取高度、相机俯角。
- 夹爪交接：任何 gripper / grasp 动作之后，驾驶舱从 `commanded_positions[6]` 同步 `S.grip`，接管遥操作时夹爪不会被拉回原开度。
- 测试：`tests/test_grasp.rs`（模拟相机：按当前 FK 位姿、相机安装与针孔内参投影桌面上固定位置的物体，内参与安装角故意与控制器假设不同），`scripts/grasp_shots.mjs`（驾驶舱截图与断言）。

与计划的差异：

| 计划 | 实施 | 原因 |
|---|---|---|
| 状态机在浏览器侧，经 `C.goal` 驱动笛卡尔通道 | 状态机在 armd（异步任务，锁外运行），浏览器只发起与显示 | agent 与驾驶舱共用；停止 / 急停 / 租约丢失在服务端同一处结束；不依赖浏览器连接质量 |
| 设置存 localStorage | 存在 armd 的 JSON 文件 | 多个客户端共用同一份设置 |
| 闭空张开后可重试一次 | `NOT_HOLDING`：张开、抬起、结束，不重试 | 保守选择，重试由用户决定 |
| 下降过程中持续对中 | 只在接近高度对中，然后直线下降 | 第一版简化；夹爪像素按接近高度标定 |
| servo 校正只接受 4–30 mm | 每步 = 增益 0.6 × 估计误差，上限 30 mm，不设下限；收敛判据为像素误差 ≤ 10 px 连续 3 帧 | 粗接近误差可能超过 30 mm，直接拒绝会失败；小步由像素门限结束 |
| 目标跟踪：中心距 < 35 px 或 IoU > 0.45 | 相同，预测位置为上一帧位置（运动后为按模型投影的位置）；接近后的第一次匹配放宽到 160 px | 接近位姿由粗估计得到，第一帧偏差较大 |
| 步骤 0 夹爪零位校验 | 未实施 | 不在本次范围 |

需真机确认（新增）：新支架的 `camera_tilt_deg` 符号与数值（默认安装下负值朝夹爪方向）、`camera_mount.offset_m`、夹爪闭合方向在画面中的轴（J6 对齐假设为 end_link y）、检测帧率与延迟对 `settle_delay_s` / `lost_*` 的影响、`centre_tol_px` 与检测抖动、POS_VEL 下的 `holding` 阈值。
