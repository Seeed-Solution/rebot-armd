# Agent action API / 动作接口

High-level arm actions for agents (MCP server, scripts). They run on the WebSocket `/api/v1/ws` under the same control lease, epoch and `request_id` rules as every other `command`. The REST paths `POST /api/v1/action/*` exist only to return `409 LEASE_REQUIRED` / `LEASE_ACTIVE`, except `POST /api/v1/action/grasp` with `{"dry_run": true}` which checks reachability and returns `200 OK` without requiring a lease.

面向 agent（MCP server、脚本）的高层动作。走 WebSocket `/api/v1/ws` 的 `command`，租约、epoch、`request_id` 规则与其他指令相同。REST 路径 `POST /api/v1/action/*` 只返回 `409 LEASE_REQUIRED` / `LEASE_ACTIVE`；`POST /api/v1/action/grasp` 带 `{"dry_run": true}` 例外，无需租约即可进行可达性检查并返回 `200 OK`。

Profiles without `kinematics` (any `--config` profile that omits it) return `UNSUPPORTED` for `move_to` / `move_relative`; without `gripper_policy`, `gripper` returns `UNSUPPORTED`. The built-in `rebot-dm` profile has all three.

未配置 `kinematics` 的 profile 对 `move_to` / `move_relative` 返回 `UNSUPPORTED`；未配置 `gripper_policy` 时 `gripper` 返回 `UNSUPPORTED`。内置 `rebot-dm` profile 三者都已配置。

## Message / 消息

```json
{"type":"command", "request_id":42, "generation":7, "epoch_id":3,
 "path":"/api/v1/action/move_to", "body":{"position":[0.30,0.0,0.25]}}
```

Accepted: `{"type":"command_ack", "request_id":42, "status":"accepted", "action_id":5, "expected_duration_s":2.4, ...}`. Rejected: `{"type":"command_reject", "request_id":42, "status":422, "code":"IK_UNREACHABLE", "message":"..."}`.

The existing `/api/v1/motion/jog`, `/motion/home`, `/motion/unload` commands and WS `preset` keep their bodies and now also create an action record (kind `joint_move`, `home`, `park`); their `command_ack` / `preset_ack` carry `action_id`.

已有的 jog / home / unload 指令与 WS `preset` 请求体不变，同时生成动作记录（`joint_move` / `home` / `park`），ack 带 `action_id`。

### `move_relative` frames / 坐标系

| frame | translation `d` | rotations (about the end_link origin) |
|---|---|---|
| `base` | base axes | `dyaw` about world Z; `dpitch` about unit(Z × x_tool), positive tips the tool down; `droll` about tool x |
| `tool` | end_link axes | `droll` / `dpitch` / `dyaw` about end_link x / y / z (intrinsic, applied z·y·x) |
| `camera` | OpenCV camera axes (x right, y down, z optical) | `dpitch` > 0 looks down (−dpitch about x_cam); `dyaw` > 0 looks right (−dyaw about world Z); `droll` about z_cam. `level` (default true) then rolls x_cam horizontal unless the optical axis is within 15° of vertical |

The camera rotation is R_base_cam = R_base_end · R_end_cam, R_end_cam from `config.camera_mount` (`flip`, `rot_deg`, `tilt_deg`; defaults = cockpit defaults, optical axis = end_link x). With `rot_deg` 0 and `flip` false, image y (down) = −end_link z and image x = −end_link y: a camera above the jaws whose image is upright at the rest pose (the mount is referenced to the rest pose, URDF angles 0 including J6, the profile's `zero_reference`). `level` is only accepted for `camera`.

相机旋转 R_base_cam = R_base_end · R_end_cam，R_end_cam 来自 `config.camera_mount`（`flip`、`rot_deg`、`tilt_deg`；默认值同 cockpit，光轴 = end_link x）。`rot_deg` 0、`flip` false 时，图像 y（向下）= −end_link z，图像 x = −end_link y，即相机位于夹爪上方、静置位姿下图像正立（安装以收纳姿态为参考：含 J6 在内 URDF 角均为 0，即 profile 的 `zero_reference`）。`level` 只用于 `camera`。

### Outward yaw / 朝外偏航

`"yaw": "outward"` on `move_to`, `move_relative` and `place` (capability `yaw_outward`, same value as `cartesian`; absent on older armd) sets the yaw to ψ = atan2(y, x) of the target position, about the base z axis. Any other value than `"outward"` or null is `INVALID_COMMAND`.

- Combination with the orientation: the orientation is resolved as without `yaw` (`orientation` rpy or quat, the current orientation when null, `move_relative`'s rotations, a named pose's orientation for `place`); then its rpy yaw is replaced by ψ and its rpy roll and pitch are kept: R = Rz(ψ − yaw) · R, yaw = atan2(R[1][0], R[0][0]) (heading of the end_link x axis). With `{"rpy":[r,p,y]}` the result is rpy `[r, p, ψ]`; the given `y` is ignored. When the end_link x axis is within 2.6° of vertical (pitch ±90°, `is_tool_vertical`) yaw and roll are the same rotation and the orientation is used unchanged.
- `move_relative` with `yaw: "outward"` and a non-zero `dyaw` is `INVALID_COMMAND`.
- Path: with ψ(s) = atan2(y, x) of path sample s (unwrapped along the line), the sample orientation is R(s) = Rz(ψ(s)) · Rrel(s), where Rrel slerps from Rz(−ψ(0)) · R_start to Rz(−ψ(1)) · R_goal. A start whose yaw is already outward keeps the yaw at atan2(y, x) of every sample; another start's offset from outward goes linearly (slerp) to 0. The sample count and duration use the slerp angle plus |ψ(1) − ψ(0)|.
- A path whose xy projection passes within 0.03 m of the base z axis (atan2 undefined) is refused before planning: `INVALID_COMMAND` `yaw "outward" is undefined near the base z axis: the path passes 0.006 m from it (minimum 0.03 m)`.
- `place`: the place orientation gets the outward yaw of the target; `approach` and `descend` are planned with the outward path, `lift` and `retreat` (straight up, orientation kept) are not.
- 5-DOF arms: `auto_yaw` keeps its behaviour (the IK leaves yaw free, as without `yaw`); `yaw: "outward"` sets the targets as above in addition.
- Hint: on arms with 6 or more arm joints, an `IK_UNREACHABLE` or `IK_BRANCH_FLIP` of a path planned without `yaw: "outward"` ends its message with `; yaw differs from the outward direction by N°; try yaw: "outward"` when the yaw of the start or of a sample up to the failing one differs from atan2(y, x) by more than 15° (N = the largest such difference; samples within 0.03 m of the base axis or with a vertical tool are not counted). Example (B601-DM, mock): from `move_to` (0.18, 0.10, 0.30) rpy (0, 40°, 0), which ends at J1 1.194 rad (atan2 0.507), a straight move to (0.18, −0.10, 0.30) gives `IK branch flip at s=0.425: joint 1 jumps 0.105 rad between samples (limit 0.10); yaw differs from the outward direction by 29°; try yaw: "outward"`. With `yaw: "outward"` both moves succeed, J1 within 0.005 rad of atan2(y, x) on every sample (`tests/test_yaw_outward.rs`).

`move_to`、`move_relative`、`place` 的 `"yaw": "outward"`（能力 `yaw_outward`，与 `cartesian` 取值相同；旧版 armd 无此字段）把偏航设为目标位置的 ψ = atan2(y, x)，绕基座 z 轴。`"outward"` 与 null 以外的值返回 `INVALID_COMMAND`。

- 与姿态的组合：先按没有 `yaw` 时的规则得到姿态（`orientation` 的 rpy 或 quat；为 null 时取当前姿态；`move_relative` 的旋转；`place` 的命名姿态的姿态），再把它的 rpy 偏航换成 ψ，保留 rpy 的横滚与俯仰：R = Rz(ψ − yaw) · R，yaw = atan2(R[1][0], R[0][0])（end_link x 轴的朝向）。给 `{"rpy":[r,p,y]}` 时结果为 rpy `[r, p, ψ]`，给定的 `y` 不使用。end_link x 轴与竖直方向夹角在 2.6° 以内时（俯仰 ±90°，`is_tool_vertical`）偏航与横滚是同一个旋转，姿态按原样使用。
- `move_relative` 同时给 `yaw: "outward"` 和非零 `dyaw` 返回 `INVALID_COMMAND`。
- 路径：ψ(s) 为路径采样点 s 的 atan2(y, x)（沿直线连续展开），采样点姿态 R(s) = Rz(ψ(s)) · Rrel(s)，Rrel 从 Rz(−ψ(0)) · R_start 球面插值到 Rz(−ψ(1)) · R_goal。起点偏航已朝外时，每个采样点的偏航都等于该点的 atan2(y, x)；否则起点相对朝外方向的偏差沿路径（球面插值）线性减到 0。采样数和时长按球面插值角度加 |ψ(1) − ψ(0)| 计算。
- 路径在 xy 平面上的投影离基座 z 轴不到 0.03 m（atan2 无定义）时，规划前拒绝：`INVALID_COMMAND` `yaw "outward" is undefined near the base z axis: the path passes 0.006 m from it (minimum 0.03 m)`。
- `place`：放置姿态取目标点的朝外偏航；`approach` 与 `descend` 按朝外路径规划，`lift` 与 `retreat`（竖直移动，保持姿态）不按朝外路径规划。
- 5 轴机械臂：`auto_yaw` 行为不变（与不带 `yaw` 时一样，IK 放开偏航）；`yaw: "outward"` 另外按上述规则设定目标姿态。
- 提示：机械臂关节数 ≥ 6 时，不带 `yaw: "outward"` 规划的路径若报 `IK_UNREACHABLE` 或 `IK_BRANCH_FLIP`，且起点或失败点之前（含失败点）任一采样点的偏航与 atan2(y, x) 相差超过 15°，消息末尾加 `; yaw differs from the outward direction by N°; try yaw: "outward"`（N 为其中最大的差值；离基座轴 0.03 m 以内或工具竖直的采样点不计）。示例（B601-DM，mock）：`move_to` (0.18, 0.10, 0.30) rpy (0, 40°, 0) 结束时 J1 为 1.194 rad（atan2 为 0.507），再直线移动到 (0.18, −0.10, 0.30) 返回 `IK branch flip at s=0.425: joint 1 jumps 0.105 rad between samples (limit 0.10); yaw differs from the outward direction by 29°; try yaw: "outward"`。带 `yaw: "outward"` 时两次移动都成功，每个采样点 J1 与 atan2(y, x) 相差不超过 0.005 rad（`tests/test_yaw_outward.rs`）。

### Joint path / 关节空间路径

`"path": "joint"` on `move_to` and `move_relative` (capability `move_path_joint`, same value as `cartesian`; absent on older armd) moves to the goal pose in joint space instead of along a straight line. `"linear"` or no `path` keeps the straight line. Any other value is `INVALID_COMMAND`.

- **The TCP path is not a straight line.** The joints move from the start to the goal joints along one quintic (the trajectory of `move_to_pose`). Only the start and the goal pose are Cartesian; the TCP and orientation between them follow from the joint interpolation.
- Goal: resolved as for the straight line (`orientation`, `yaw: "outward"`, `move_relative` frames, 5-DOF `auto_yaw`). The IK is solved for the goal only, from several seeds: the current joints; the current joints with J1 turned by the azimuth change from the current TCP to the goal; the profile home and the resting pose (when it differs), each as is and with J1 turned the same way. A seed's result counts when it reaches the goal within the IK tolerance (1 mm, 0.5°), lies within the joint limits and passes the workspace rule at the goal. Of those, armd takes the one with the smallest Σ |q − q_start| / max_velocity over the arm joints. None: when a seed's result was within the joint limits but failed the workspace rule at the goal, that `WORKSPACE_VIOLATION`; else `IK_UNREACHABLE` `No IK solution for the goal pose within the joint limits (best of N seeds: position error … m, rotation error … rad)`. With `yaw: "outward"` a goal within 0.03 m of the base z axis is `INVALID_COMMAND`.
- Speed: `speed_scale` (0.1..1.0, default 1.0) multiplies the joint planning velocity as for `move_to_pose` (`planned_max_velocity`, the profile `speed_cap.joint_velocity_scale`; gripper excluded). `speed` (m/s) is `INVALID_COMMAND` with `path: "joint"`.
- Checks: the same as `move_to_pose` and joint moves: the swept workspace check of the quintic (floor, outer box, reach, keep-out boxes, link capsules, self-collision; `WORKSPACE_VIOLATION`), the power budget, the torque and collision holds, and the plan freshness check (`PLAN_STALE`). The gripper keeps its command.
- `precise: true` / `approach: "same_side"`: the quintic ends with the same-side approach of `move_to_precise` as in `move_to_pose` (see [Same-side final approach](#same-side-final-approach--同侧接近)).
- Action kind stays `move_to` / `move_relative`.
- Hint: when a straight-line `move_to` / `move_relative` is refused with `IK_BRANCH_FLIP` and the joint-space move to the same goal has an IK solution (seeds as above) whose quintic passes the joint limits and the swept workspace check, the message ends with `; a joint-space move reaches it: try path: "joint"`. The check costs one goal IK and one sweep check; nothing moves.

`move_to` 与 `move_relative` 的 `"path": "joint"`（能力 `move_path_joint`，与 `cartesian` 取值相同；旧版 armd 无此字段）在关节空间移动到目标位姿，不走直线。`"linear"` 或不给 `path` 时仍走直线。其他取值返回 `INVALID_COMMAND`。

- **TCP 路径不是直线。** 各关节从起点到目标关节角按同一条五次多项式运动（与 `move_to_pose` 相同的轨迹）。只有起点和目标位姿是笛卡尔约束，中间的 TCP 位置和姿态由关节插值决定。
- 目标：与直线相同的方式解析（`orientation`、`yaw: "outward"`、`move_relative` 坐标系、5 轴 `auto_yaw`）。只对目标位姿求 IK，使用多个初值：当前关节角；当前关节角并把 J1 转过当前 TCP 到目标的方位角差；profile 的 home 和静置位姿（与 home 不同时），各自原样及按同样方式转 J1。某个初值的解满足以下条件才计入：在 IK 容差内（1 mm、0.5°）到达目标、在关节限位内、目标处通过工作空间检查。其中取各臂关节 Σ |q − q_start| / max_velocity 最小的解。没有可用解时：若有初值的解在关节限位内但目标处未通过工作空间检查，返回该 `WORKSPACE_VIOLATION`；否则返回 `IK_UNREACHABLE` `No IK solution for the goal pose within the joint limits (best of N seeds: position error … m, rotation error … rad)`。带 `yaw: "outward"` 时，目标离基座 z 轴不到 0.03 m 返回 `INVALID_COMMAND`。
- 速度：`speed_scale`（0.1..1.0，默认 1.0）与 `move_to_pose` 一样乘到关节规划速度上（`planned_max_velocity`、profile 的 `speed_cap.joint_velocity_scale`；夹爪除外）。`path: "joint"` 时给 `speed`（m/s）返回 `INVALID_COMMAND`。
- 检查：与 `move_to_pose` 和关节运动相同：五次多项式轨迹的扫掠工作空间检查（地面、外框、可达范围、禁入盒、连杆胶囊体、自碰撞；`WORKSPACE_VIOLATION`）、电源功率预算、力矩保护与碰撞保护的保持状态，以及规划时效检查（`PLAN_STALE`）。夹爪保持当前指令。
- `precise: true` / `approach: "same_side"`：与 `move_to_pose` 一样，五次多项式末段按 `move_to_precise` 做同侧接近（见[同侧接近](#same-side-final-approach--同侧接近)）。
- 动作类型仍为 `move_to` / `move_relative`。
- 提示：直线 `move_to` / `move_relative` 因 `IK_BRANCH_FLIP` 被拒绝时，若到同一目标的关节空间移动有 IK 解（初值同上）且其五次多项式轨迹通过关节限位和扫掠工作空间检查，消息末尾加 `; a joint-space move reaches it: try path: "joint"`。这项检查只做一次目标 IK 和一次扫掠检查，不产生运动。

### Speed / 速度

Defaults linear 0.05 m/s (max 0.15), angular 0.5 rad/s (max 1.0). Joint speed is capped by `planned_max_velocity` (0.45 rad/s on rebot-dm), joint acceleration by min(limit, 3.0 rad/s²).

A profile `speed_cap` (`linear_mps`, `angular_rps`, `joint_velocity_scale`) lowers these further: the request speed is accepted within the limits above, then min(request, cap) is planned, and the joint speed cap is multiplied by `joint_velocity_scale` (gripper excluded). It applies to every planned motion (actions, jog, home, park, `move_to_pose`), cannot be changed at runtime and is published as `schema.speed_cap`.

默认线速度 0.05 m/s（上限 0.15），角速度 0.5 rad/s（上限 1.0）。关节速度受 `planned_max_velocity`（rebot-dm 0.45 rad/s）限制，加速度上限 min(限位, 3.0 rad/s²)。

profile 的 `speed_cap`（`linear_mps`、`angular_rps`、`joint_velocity_scale`）进一步降低速度：请求值在上述范围内被接受，规划时取 min(请求值, 上限)，关节限速乘以 `joint_velocity_scale`（夹爪除外）。对所有规划运动生效（动作、jog、home、park、`move_to_pose`），运行时不可修改，发布在 `schema.speed_cap`。

## Planning and execution / 规划与执行

1. Under the lock: lease, epoch, `request_id`, then preconditions — Armed/Moving, no pending re-arm / park / handover, no trajectory, no servo target, all commanded velocities < 1e-3 (else `MOTION_BUSY`).
2. Without the lock (blocking thread): straight line in position, slerp in rotation (with `yaw: "outward"` in the outward frame, see [Outward yaw](#outward-yaw--朝外偏航)), one sample per 5 mm / 2° (≤ 400), DLS IK per sample seeded with the previous one, within joint limits − 0.02 rad. A joint change > 0.10 rad between samples is `IK_BRANCH_FLIP`; every sample passes the workspace rule. One quintic time scaling over the whole path.
3. Lock again: same lease and generation, epoch unchanged, still idle and commanded positions unchanged (< 1e-4 rad), else `PLAN_STALE`. Then the path is installed and acknowledged.

Execution: each tick advances path time by dt·rate with rate = clamp((0.45 − lag)/(0.45 − 0.38), 0, 1), lag = max over J1..J6 of |commanded − measured|. Geometry stays the same, only speed drops. Rate 0 for 1 s ends the action as `TRACKING_STALL` (commanded reset to measured, no Fault). After the path: settle until |commanded − measured| < 0.05 rad and |v| < 0.05 rad/s for 200 ms (`settled:true`), at most 2 s (`settled:false`). J7 holds its commanded value during arm paths.

Gripper: J1..J6 hold; J7 steps at `speed`. `open` / `move` are done at the target (±0.05 rad, still 200 ms) or on a stall in the travel direction. A stall latch set while J7 pushed the other way (the squeeze of a grasp, also while the command unwinds from the squeeze hold) is released and J7 keeps travelling; the latch stores the direction J7 was driven into the obstacle (commanded − measured; torque sign only when they coincide). `close` with `grasp`: on contact (stall latch, or still 200 ms after moving) J7 holds min(measured + `squeeze_rad`, `closed_rad`) for `settle_ms`; `holding` = gap ≥ `holding_gap_rad` and median |τ7| ≥ `holding_torque_nm`. The hold target stays in `commanded_positions[6]` after the action. Timeout is `GRIPPER_TIMEOUT` (J7 held at measured). The existing stall protection still applies: a sustained |τ7| ≥ 0.444 N·m with |v7| < 0.10 rad/s for 6 ticks re-latches and resets J7 to measured.

执行：每 tick 按 dt·rate 推进路径时间，滞后超过 0.38 rad 开始降速，0.45 rad 停止；持续 1 s 停止则 `TRACKING_STALL`（指令重置为实测，不进入 Fault）。夹爪闭合抓取：接触后保持 min(实测 + `squeeze_rad`, `closed_rad`) `settle_ms` 毫秒，按间隙和扭矩中位数判定 `holding`。

```json
           "progress":0.42, "started_at":812.3, "finished_at":null,
           "holding":null, "gripper_gap_rad":null, "settled":null}
```

`kind`: `move_to`, `move_relative`, `gripper`, `gripper_zero_check`, `grasp`, `place`, `joint_move`, `home`, `park`, `move_to_pose`, `replay`, `measure_multiview` (carries `measurement`, see [Multi-view measurement](#multi-view-measurement--多视角测量)). Planned motions carry `power_scale` when the profile has a power budget (see [Power budget](#power-budget--电源功率预算)). A `gripper_zero_check` record carries `stop_rad`, `offset_rad` and `pass: bool` (null while running). Macro actions (`grasp`, `place`) record `phase_ms` (per-phase duration in milliseconds) and `motions` (diagnostics per Cartesian sub-motion, up to 32 entries: `{phase, ms, track_mm, track_deg, goal_mm, goal_deg, contact}`). `state`: `running`, `done`, `failed`, `cancelled`. `started_at` / `finished_at` use the observation `timestamp` clock. Clients block by waiting until `action.id == action_id` and `state != "running"`, or until `previous_action.id == action_id`.

`kind`：`move_to`、`move_relative`、`gripper`、`gripper_zero_check`、`grasp`、`place`、`joint_move`、`home`、`park`、`move_to_pose`、`replay`、`measure_multiview`（携带 `measurement`，见[多视角测量](#multi-view-measurement--多视角测量)）。规划运动在 profile 包含电源预算时携带 `power_scale`（见[电源功率预算](#power-budget--电源功率预算)）。`gripper_zero_check` 记录携带 `stop_rad`、`offset_rad` 与 `pass: bool`（运行中为 null）。`grasp` 记录另带 `task`（请求指定的[抓取任务](#grasp-tasks--抓取任务)，未指定时缺省）、`phase`、`iteration`、`error_px`、`angle_spread_deg`（度；检测角度的圆周离散度），`height_estimates`（每个已评估的物体高度来源，见[稳健性步骤](#robustness-steps--稳健性步骤)“高度来源”；高度步骤之前缺省），目标框在对中目标处被画面边界截断时另带 `border` / `border_shift_px`（见[稳健性步骤](#robustness-steps--稳健性步骤)“边界截断的框”），相机朝下采集时另带 `final_offset_px` 和 `acquire_height_m`；`place` 记录带 `phase`，在防倾洒调平时带 `orientation: "levelled"`（其余为 null）；`replay` 记录带 `phase`、`episode` 和 `t_s`。`move_to_pose`、`grasp`、`place` 及 precise 的 `move_to` / `move_relative` 记录带 `approach`、`approach_reason`、`approach_signs`、`approach_flipped`（见[同侧接近](#same-side-final-approach--同侧接近)）。宏动作（`grasp`、`place`）记录 `phase_ms`（各阶段耗时毫秒）和 `motions`（各笛卡尔子运动诊断，最多 32 条：`{phase, ms, track_mm, track_deg, goal_mm, goal_deg, contact}`）。`state`：`running`、`done`、`failed`、`cancelled`。`started_at` / `finished_at` 使用观测的 `timestamp` 时钟。客户端通过等待 `action.id == action_id` 且 `state != "running"` 或 `previous_action.id == action_id` 阻塞同步。

A running action ends when its reference goes away:

| cause | state / code |
|---|---|
| E-stop | `failed` / `ESTOP_ACTIVE` |
| Fault | `failed` / `FAULT` (message = reason) |
| lease watchdog (park or `WatchdogTimeout`) | `failed` / `WATCHDOG` |
| lease released, preempted or connection closed | `cancelled` / `LEASE_LOST` |
| new jog / preset / home / park / action | `cancelled` / `SUPERSEDED` |
| `/motion/stop` | `cancelled` / `STOPPED` |
| park ended with torque on | `failed` / `UNLOAD_FAILED` |

Servo frames while an action runs are rejected with `MOTION_BUSY`. Jog, preset, home and park are accepted and supersede it.

## Named poses / 命名姿态

`GET /api/v1/poses` (no lease) returns `{"poses":[{"name", "positions":[dof], "tcp":{"position":[x,y,z], "rpy":[r,p,y]} | null, "saved_at_ms"}]}`. `tcp` is the end_link pose at save time (null without `kinematics`); `saved_at_ms` is Unix time.

- `/api/v1/poses/save` (lease): `name` matches `^[A-Za-z0-9_-]{1,64}$`; `positions` defaults to the measured positions and must be within the joint limits. Saving an existing name replaces it. At most 64 poses. The ack carries `pose`.
- `/api/v1/poses/rename` (lease) `{id, name}`: the pose keeps its id, positions and stale mark, so sequences that reference it keep working; another pose with the name is `409 POSE_EXISTS`, an unknown id `404 POSE_NOT_FOUND`. The ack carries `pose`.
- `/api/v1/poses/delete` (lease): an unknown name is `404 POSE_NOT_FOUND`; a pose referenced by a sequence is `409 IN_USE {sequences}`.
- Every pose carries `id` (ULID, see [Teach v1](#sequences--序列)) and `stale` (null, or `{reason, at}` after a joint zero change).
- Both acks carry `persisted` (true / false with `persist_error`). The store is written atomically to `ARMD_POSES` (default `/userdata/rebot-teleop/poses.json`) after the supervisor lock is released. At start a valid file is loaded; an unreadable or invalid file is logged and the store starts empty; a malformed or invalid file is renamed to `poses.json.bad-<unix seconds>` so the next save cannot overwrite it.
- `/api/v1/action/move_to_pose`: joint-space quintic of J1..J6 (and J7 with `include_gripper`) to the stored positions, planned with the joint speed cap × `speed_scale`. Action kind `move_to_pose`; same preconditions as the other actions (`MOTION_BUSY` while a trajectory or servo stream runs) and the same cancellation causes. The path's verification samples (21, more with keep-out boxes: see [Keep-out boxes](#keep-out-boxes--禁入盒)) pass the joint limits and, with `kinematics` and `workspace`, the workspace rule including keep-out boxes. Errors: `POSE_NOT_FOUND` (404), `WORKSPACE_VIOLATION` (422), `INVALID_COMMAND` (400).

`GET /api/v1/poses`（无需租约）返回已保存的姿态，每个姿态带 `id`（ULID）与 `stale`（null，或零位变更后的 `{reason, at}`）。`/api/v1/poses/rename {id, name}`（需租约）改名时保留 id、位置与过期标记，引用它的序列不受影响；重名返回 `409 POSE_EXISTS`。被序列引用的姿态删除返回 `409 IN_USE {sequences}`。`/api/v1/poses/save`、`/api/v1/poses/delete` 需要租约：名称须匹配 `^[A-Za-z0-9_-]{1,64}$`，`positions` 默认取实测位置并须在关节限位内，同名覆盖，最多 64 个；删除不存在的名称返回 `404 POSE_NOT_FOUND`。文件在释放锁后原子写入 `ARMD_POSES`（默认 `/userdata/rebot-teleop/poses.json`）；启动时文件无效则记录日志、以空列表启动；格式错误或无效的文件重命名为 `poses.json.bad-<unix 秒>`，之后的保存不会覆盖它。`move_to_pose` 以关节空间五次多项式移动 J1..J6（`include_gripper` 时含 J7），速度为关节限速 × `speed_scale`，动作类型 `move_to_pose`，前置条件与取消规则同其他动作，路径的校验采样点（21 个，有禁入盒时更多，见“禁入盒”）须满足关节限位和工作空间规则（含禁入盒）。

## Same-side final approach / 同侧接近

Gear backlash makes a joint stop at a slightly different place depending on the direction it arrives from. Measured on the B601-DM (2026-11-18, calibration board, camera vs encoder): J1 0.28–0.30° (about 2.3 mm at 0.45 m; the encoder sees 0.01–0.02°), the base pose reached from above vs below 1.6 mm / 0.29°, same-direction repeats about 0.2 mm, J2–J6 < 0.15°. The fine calibration captures every pose from one side, so a motion that arrives from the other side carries the backlash error the calibration removed.

With the approach on, a motion ends with a short joint-space segment `q_pre → q_target` at a low speed (phase `approach`; `final_approach` in `grasp` / `place`, which already have a phase `approach`). `q_pre = q_target − delta × s` per listed joint, in armd joint (motor) angles: `s = +1` (the joint arrives moving in +), `s = −1` when `q_target − delta` is below the joint's lower soft limit. Joint-space motions (`move_to_pose`) plan their quintic to `q_pre`; Cartesian motions (`move_to` / `move_relative` with `precise`, the `descend` of `grasp` and `place`) plan the straight line to the pose of `q_pre` (`q_pre` is the pre-target of the end of the direct path), then the segment.

- From above (grasp / place descent): a listed joint whose offset alone puts a tool point (end_link origin, `workspace.check_points_end_m`; for grasp also the camera body of the grasp envelope) more than 0.1 mm lower than at the target gets `s` flipped (reported in `approach_flipped`), and the 21 samples of the segment must stay no lower than the target, so the last segment never rises to the table or the object from below. A joint that lowers the tool either way, or has no room above, makes the motion direct.
- Checks: the pre-target and the segment pass the checks of a joint move (soft limits, power budget, workspace and keep-out sweep, no torque or power hold in force), the leg to the pre-target the checks of its motion. Any failure falls back to the direct motion with `approach: "direct"` and `approach_reason` (`pre_target: <code or rule>`, `segment: <code>`, `from_below: ...`). A grasp descent stopped by contact (`descend_contact`) ends without the segment: `approach_reason: "contact"`.
- Request field `approach`: `"same_side"` uses it even where the profile does not (the profile's settings, else the defaults), `"direct"` turns it off (`approach_reason: "request"`, the motion is the one without the feature). `move_to` / `move_relative` keep their straight line unless `precise: true` (or `approach: "same_side"`).
- Records: `approach` (`same_side` | `direct`; absent when the approach does not apply and the request did not ask for it), `approach_reason`, `approach_signs` (per arm joint +1 / −1, 0 = not listed), `approach_flipped` (joint names). `expected_duration_s` includes the segment (and, for grasp / place, an estimate of it).
- The cockpit's fine calibration uses the same rule for its pre-pose (`schema.backlash_approach.delta_deg`, same sign rule in motor angles; 0.5° without the section), so calibration and run time see the same backlash side.

Profile section `backlash_approach` (published as `schema.backlash_approach`, capability `backlash_approach`): `{"enabled": bool (default true), "delta_deg": 0.05..5 (default 0.5, above the measured 0.3° J1 backlash), "joints": [joint names]? (default every arm joint), "applies_to": ["move_to_pose", "grasp_final", "place_final", "move_to_precise"] (default all), "speed_rad_s": 0.005..0.5 (default 0.05; joint speed cap of the segment, which lasts at least 0.5 s)}`. The B601-DM profile enables it for all four; a profile without the section moves as before. Real-arm effect: needs verification (`_scratch/teach/backlash_check.mjs` reaches a pose from both sides with `direct` and `same_side`).

齿轮回差使关节停止位置随到达方向不同而不同。B601-DM 实测（2026-11-18，标定板，相机对比编码器）：J1 0.28–0.30°（0.45 m 处约 2.3 mm；编码器只看到 0.01–0.02°），基准姿态从上方与从下方到达相差 1.6 mm / 0.29°，同向重复约 0.2 mm，J2–J6 < 0.15°。精校从同一方向采集每个位姿，从另一方向到达的运动会带回精校去掉的回差误差。

启用后，运动最后一段为低速的关节空间短段 `q_pre → q_target`（阶段 `approach`；`grasp` / `place` 已有阶段 `approach`，其短段为 `final_approach`）。每个列出的关节 `q_pre = q_target − delta × s`（armd 关节角，即电机方向）：`s = +1`（关节沿 + 方向到达），`q_target − delta` 低于该关节软限位时 `s = −1`。关节空间运动（`move_to_pose`）的五次多项式规划到 `q_pre`；笛卡尔运动（带 `precise` 的 `move_to` / `move_relative`、`grasp` 与 `place` 的 `descend`）先直线运动到 `q_pre` 对应的位姿（`q_pre` 为直接路径终点的预目标），再走短段。

- 从上方接近（抓取 / 放置下降）：某个列出的关节单独偏移后使任一工具点（end_link 原点、`workspace.check_points_end_m`；抓取时另含抓取包络中的相机机身）比目标处低 0.1 mm 以上时，该关节的 `s` 取反（记录在 `approach_flipped`），短段的 21 个采样点也不得低于目标高度，因此最后一段不会从下方升向桌面或物体。某关节向两个方向都使工具降低、或上方没有余量时，该运动改为直接接近。
- 检查：预目标与短段执行关节运动的全部检查（软限位、电源预算、工作空间与禁入盒扫掠、无力矩或功率保持），到预目标的一段执行其所属运动的检查。任一项失败即回退为直接运动，记录 `approach: "direct"` 与 `approach_reason`（`pre_target: <错误码或规则>`、`segment: <错误码>`、`from_below: ...`）。抓取下降因接触停止（`descend_contact`）时不再执行短段：`approach_reason: "contact"`。
- 请求字段 `approach`：`"same_side"` 在 profile 未启用的运动上也使用（取 profile 的设置，没有则用默认值），`"direct"` 关闭（`approach_reason: "request"`，运动与不带此功能时相同）。`move_to` / `move_relative` 保持直线，除非传 `precise: true`（或 `approach: "same_side"`）。
- 记录字段：`approach`（`same_side` | `direct`；不适用且请求未要求时缺省）、`approach_reason`、`approach_signs`（每个臂关节 +1 / −1，0 = 未列出）、`approach_flipped`（关节名）。`expected_duration_s` 包含短段（抓取 / 放置为估计值）。
- cockpit 精校的预位姿使用同一规则（`schema.backlash_approach.delta_deg`，同样的电机方向符号规则；无该字段时 0.5°），精校与运行时处于回差的同一侧。

profile 字段 `backlash_approach`（发布为 `schema.backlash_approach`，能力 `backlash_approach`）：`{"enabled": bool（默认 true）, "delta_deg": 0.05..5（默认 0.5，大于实测 J1 回差 0.3°）, "joints": [关节名]?（默认所有臂关节）, "applies_to": ["move_to_pose", "grasp_final", "place_final", "move_to_precise"]（默认全部）, "speed_rad_s": 0.005..0.5（默认 0.05；短段的关节限速，短段至少 0.5 s）}`。B601-DM profile 对四项全部启用；没有该字段的 profile 运动方式不变。真机效果需核实（`_scratch/teach/backlash_check.mjs` 用 `direct` 与 `same_side` 从两侧到达同一位姿）。

## Keep-out boxes / 禁入盒

Axis-aligned boxes in the base frame that no workspace check point may enter. They are checked wherever the workspace rule applies (servo targets, every sample of Cartesian paths, the samples of jog / home / preset / `move_to_pose` quintics: 21, plus with keep-out boxes the samples of the sweep check described in the safety contract, at most 4000 added FK evaluations, else `WORKSPACE_VIOLATION`; servo and braking steps are checked the same way, at most 64 added evaluations per tick, else the stream stops in the recoverable hold; park is checked too: it is exempt from the floor, box and reach limits only, so a park through a box is `WORKSPACE_VIOLATION` and a watchdog park through a box holds position and latches `WATCHDOG_TIMEOUT`) on the same check points (end_link origin, `check_points_end_m`, camera offset). Entering a box is `WORKSPACE_VIOLATION` with `keepout '<name>'` in the message; as with the other limits, a move that starts inside a box and does not go deeper is allowed.

- Profile: `workspace.keepout_boxes` (default empty, at most 16).
- `GET /api/v1/workspace/keepout` returns `{"boxes":[{name, min_m, max_m, "source":"profile"|"runtime"}, ...], "source":"profile"|"runtime"}`: the boxes in force, profile boxes first; the top-level `source` is `runtime` once a runtime list was set.
- WS command `/api/v1/workspace/keepout` `{"boxes":[...]}` (lease) replaces the runtime list: names 1..64 bytes, finite, `min_m < max_m` on every axis, at most 16 boxes in force (profile + runtime), else `400 INVALID_COMMAND`. Profiles without `kinematics` and `workspace` return `UNSUPPORTED`. The boxes in force are the profile boxes plus the runtime list: a runtime list only adds boxes and cannot remove a profile box; `{"boxes": []}` clears the runtime list. While a trajectory, macro action, servo stream or park runs, or the arm still moves, the command is `409 MOTION_BUSY`; an action planned before a change is `409 PLAN_STALE` at install. It is written to `ARMD_KEEPOUT` (default `/userdata/rebot-teleop/keepout.json`, ack field `persisted`) and loaded at the next start. Acks of state-file commands (keep-out, poses, collision setting, grasp setup) are sent when the write finished, so they can arrive after replies to later messages; their `epoch_id`, `safety_state` and `is_torqued` are read when the ack is sent.

禁入盒为基座坐标系下的轴对齐盒，工作空间检查点不得进入。在所有应用工作空间规则的位置检查（有禁入盒时，关节空间轨迹与 servo / 制动步按安全契约中的扫掠检查验证，每条轨迹最多追加 4000 次 FK，超出返回 `WORKSPACE_VIOLATION`；每个 servo 周期最多追加 64 次，超出则 servo 流停在可恢复的保持状态），进入时返回 `WORKSPACE_VIOLATION`，消息中带 `keepout '<name>'`；起点已在盒内且不再深入的运动允许。profile 字段 `workspace.keepout_boxes`；`GET /api/v1/workspace/keepout` 返回列表与来源；WS 指令 `/api/v1/workspace/keepout` 需要租约，替换运行时列表（profile 与运行时合计最多 16 个），写入 `ARMD_KEEPOUT`（默认 `/userdata/rebot-teleop/keepout.json`），下次启动时加载。状态文件类指令（禁入盒、姿态、碰撞设置、抓取设置）的应答在写入完成后发送，可能晚于后续消息的应答；其中的 `epoch_id`、`safety_state`、`is_torqued` 取发送时的值。生效的禁入盒为 profile 列表加运行时列表：运行时列表只能增加禁入盒，不能删除 profile 中的禁入盒；轨迹、宏动作、servo 流或收纳进行中（或机械臂仍在运动）时该指令返回 `409 MOTION_BUSY`，变更前规划的动作在安装时返回 `409 PLAN_STALE`；`GET` 返回的每个盒带 `source`（`profile` 或 `runtime`）。

## Observation rate, faults and residual torques / 观测频率、故障与残差力矩

- `/api/v1/ws?obs_hz=N` (integer >= 0, clamped to 1..`control_frequency_hz`, so 0 and 1 mean 1 Hz; anything else: `400` before the upgrade) sends at most N observations per second on that connection, always the newest. Lease, ack, reject, `lease_lost` and `epoch_sync` messages are not decimated. `action` keeps the latest record and `previous_action` stays 2 s, so N ≥ 1 does not lose a terminal action state.
- `fault`: null, or `{"code", "message", "recoverable"}` while `safety_state` is Fault or EStop (`safety_state` keeps its shape). Codes: `ESTOP`, `BUS_LOSS`, `THERMAL_TRIP`, `JOINT_LIMIT`, `WATCHDOG_TIMEOUT`, `FOLLOWING_ERROR`, `CONTROL_DEADLINE`, `INVALID_TELEMETRY`, `DRIVER_WRITE_FAILED`, `HARDWARE_FAULT`, `ENABLE_FAILED`, `SERVO_NO_BRAKE`, `HANDOVER_UNSETTLED`, `GRAVITY_COMP_FAILED`, `COLLISION`, `OTHER`. `recoverable` is true only for `WATCHDOG_TIMEOUT`, `CONTROL_DEADLINE`, `HANDOVER_UNSETTLED`; it is a hint for client policies, armd never clears a fault by itself. In Fault / EStop, when every motor reports fresh feedback with enable state Disabled (e.g. a motor power reset during `BUS_LOSS`), `is_torqued` becomes false and the fault stays until `clear_fault`.
- `residual_torques`: measured torque minus model gravity torque for J1..J6 (N·m), null without a gravity model or valid torque feedback (also null with the mock follower). The residual raises no fault itself; the collision guard below uses it.

`?obs_hz=N` 限制该连接每秒最多 N 条观测（取 1..`control_frequency_hz`），租约、应答、拒绝、`lease_lost`、`epoch_sync` 不降频。`fault` 在 Fault / EStop 时为 `{code, message, recoverable}`，否则为 null；`recoverable` 仅对 `WATCHDOG_TIMEOUT`、`CONTROL_DEADLINE`、`HANDOVER_UNSETTLED` 为 true，只是给客户端的提示，armd 不会自行清除故障。Fault / EStop 期间若所有电机反馈新鲜且使能状态为 Disabled（例如 `BUS_LOSS` 期间电机掉电复位），`is_torqued` 变为 false，故障保持到 `clear_fault`。`residual_torques` 为 J1..J6 实测力矩减模型重力力矩，无重力模型或无有效力矩反馈时为 null，本身不触发故障，碰撞保护（见下）使用它。

## Collision guard / 碰撞保护

Contact detection with a protective stop, built on `residual_torques` (capability `collision_guard`: profile gravity model and a driver that reports torque). It is contact detection, not a certified safety function, and the default thresholds are placeholders until measured on a real arm, so it is **off by default**; thresholds must come from rebot-sysid. Joints in `collision.rest_exempt_joints` (default: those of `resting_pose.support_torque_limits`; B601-DM: J2, J3, J4) are not watched at the resting pose. Full rules: `docs/control_safety_contract.md` "Collision guard".

- Profile section `collision`: `{"enabled": false, "thresholds_nm": [6.0,6.0,6.0,2.5,2.5,2.5], "persist_ticks": 4, "clear_ratio": 0.5, "resume_after_s": 2.0, "max_auto_resumes": 3, "escalate_window_s": 60}` (all optional).
- `GET /api/v1/safety/collision` (no lease): `{"available", "enabled", "sensitivity", "thresholds_nm" (scaled), "profile_thresholds_nm", "persist_ticks", "clear_ratio", "resume_after_s", "max_auto_resumes", "escalate_window_s", "source": "profile"|"runtime", "active"}`.
- WS command `/api/v1/safety/collision` `{"enabled": bool?, "sensitivity": "low"|"medium"|"high"?}` (lease; at least one field; unknown fields or values are `400 INVALID_COMMAND`; enabling while unavailable is `422 UNSUPPORTED`). Sensitivity scales the thresholds ×1.5 / ×1.0 / ×0.7. The ack carries `collision` (the config above) and `persisted`; the setting is written to `ARMD_COLLISION` (default `/userdata/rebot-teleop/collision.json`) and loaded at the next start. Switching the guard off ends a hold at once.
- Trip: |residual| above the threshold for `persist_ticks` ticks on any of J1..J6, with torque on, Armed / Moving and gravity compensation off. The running action ends `failed` with code `COLLISION` (message names the joint and residual); the arm holds its measured pose with torque on. `safety_state` does not change.
- While `collision.active`, motion (jog, home, presets, park, servo, every action) is rejected with `409 COLLISION_HOLD`; e_stop, stop, clear_fault and torque off work. Entering gravity compensation is allowed and ends the hold.
- The hold ends by itself after every residual stays below `clear_ratio` × threshold for `resume_after_s`. The (`max_auto_resumes`+1)-th trip within `escalate_window_s` latches Fault code `COLLISION` (`recoverable: false`), which needs `clear_fault`.
- Observation `collision`: null while disabled or unavailable, else `{"active": bool, "joint": int|null (1-based), "residual_nm": float|null, "threshold_nm": float|null, "since_s": float|null, "resume_in_s": float|null, "trips_in_window": int, "enabled": true, "sensitivity": "medium"}`.

Client pattern: on an action failing with `COLLISION`, wait until `collision.active` is false (raise if `fault.code` is `COLLISION`), then retry the step once; on escalation stop.

基于 `residual_torques` 的接触检测与保护性停止（能力 `collision_guard`：profile 有重力模型且驱动报告力矩）。它是接触检测，不是经过认证的安全功能；默认阈值在真机实测前为占位值，因此**默认关闭**；阈值须来自 rebot-sysid。`collision.rest_exempt_joints` 中的关节（缺省时取 `resting_pose.support_torque_limits` 的关节；B601-DM 为 J2、J3、J4）在收纳位姿不参与检测。完整规则见 `docs/control_safety_contract.md`“碰撞保护”。profile 段 `collision` 字段同上；`GET /api/v1/safety/collision`（无需租约）返回含缩放后阈值的生效配置；WS 指令 `/api/v1/safety/collision`（需租约）设置 `enabled` 与 `sensitivity`（low / medium / high，阈值乘以 1.5 / 1.0 / 0.7），写入 `ARMD_COLLISION`（默认 `/userdata/rebot-teleop/collision.json`），下次启动加载；关闭保护会立即结束保持。触发后正在执行的动作以 `COLLISION` 失败，机械臂在实测位置保持力矩，`safety_state` 不变；保持期间运动类指令返回 `409 COLLISION_HOLD`，急停、停止、`clear_fault`、断力矩仍可用；可以进入重力补偿，进入时保持结束。残差低于 `clear_ratio` × 阈值持续 `resume_after_s` 后自动恢复；`escalate_window_s` 内第 `max_auto_resumes`+1 次触发锁存 Fault `COLLISION`，须 `clear_fault`。观测字段 `collision` 结构见上。

## Torque guard / 力矩保护

A joint whose measured |torque| stays at or above `ratio` × its TMAX (`damiao_ranges[j].t_max`) for `persist_ms` stops the motion (capability `torque_guard`, capabilities version 8; profile section `torque_guard`, absent = off). B601-DM: `ratio` 0.60, `persist_ms` 100, J1–J6 watched: 16.8 N·m on J1–J3, 6.0 N·m on J4–J6; the gripper is not watched. 0.60 was set on 2026-11-12 for the 24 V 6.5 A supply in use; 0.85 is the value intended with a 14.6 A supply. Full rules: `docs/control_safety_contract.md` "Torque guard".

- `schema.torque_guard`: `{"ratio", "persist_ms", "thresholds_nm": [per joint, null = not watched], "release_rad"}`; `GET /api/v1/safety/describe` lists it as `torque_limit_hold`.
- Trip (torqued, Armed / Moving, position control; not in gravity compensation or the park settle phase): the running action (planned motion, Cartesian action, macro, replay, park) ends `failed` with code `TORQUE_LIMIT` (message names the joint, torque and threshold); every motion ends; J1–J6 hold the measured pose with torque on, the gripper keeps its command. `safety_state` does not change, no Fault.
- `motion_limit` = `{"reason": "torque", "joint": <0-based>, "since_ms"}` while the hold lasts.
- The held joint is commanded 0.005 rad back from its measured position, away from the load (`backoff_rad` in `torque_limit_hold`).
- While held: servo frames and jog / joint_move / home targets that move the held joint further in the push direction (sign of the torque at the trip) are clamped to the hold position for that joint, the other joints follow; moves the other way pass. Any motion that commands the held joint more than 0.002 rad past the trip position trips at once (`TORQUE_LIMIT`). A motion that moves the held joint away from the load (park, home, jog, Cartesian, the watchdog park) is not tripped on that joint for up to 1.5 s while its torque does not rise above the trip torque + 10 % of the threshold and the joint follows the command; the other joints stay watched. The hold ends when the joint is 0.05 rad from the hold position with |torque| below the threshold, or on torque off, E-stop, Fault or gravity-compensation entry.
- Lease expiry while held: the watchdog park retreats like a park. If the resting pose lies in the push direction, or the park trips, the arm holds with torque on and Fault `WATCHDOG_TIMEOUT` is latched; the log names the torque hold.

Client pattern: on `TORQUE_LIMIT`, do not retry the same goal; move the named joint back (opposite to the direction it was moving) or park, and re-plan.

关节实测 |力矩| ≥ `ratio` × 该关节 TMAX（`damiao_ranges[j].t_max`）持续 `persist_ms` 时停止运动（能力 `torque_guard`，能力版本 8；profile 段 `torque_guard`，缺省为关闭）。B601-DM：`ratio` 0.60、`persist_ms` 100，检测 J1–J6：J1–J3 16.8 N·m，J4–J6 6.0 N·m；夹爪不检测。0.60 于 2026-11-12 按当前 24 V 6.5 A 电源设定，配 14.6 A 电源时预期值为 0.85。完整规则见 `docs/control_safety_contract.md`「力矩保护」。`schema.torque_guard` 结构见上，`GET /api/v1/safety/describe` 中为 `torque_limit_hold`。触发（力矩开启、Armed / Moving、位置控制；重力补偿和收纳稳定阶段不检测）后正在执行的动作（规划运动、笛卡尔动作、宏动作、回放、收纳）以 `TORQUE_LIMIT` 失败，所有运动结束，J1–J6 在实测位置保持力矩，夹爪指令不变，`safety_state` 不变，不锁存 Fault；保持期间 `motion_limit` 为 `{"reason": "torque", "joint", "since_ms"}`。触发关节的指令为实测位置朝离开负载方向后退 0.005 rad（`torque_limit_hold` 的 `backoff_rad`）。保持期间 servo 帧与 jog / joint_move / home 目标若使该关节继续朝施力方向（触发时力矩的符号）越过保持位置，该关节被限制在保持位置，其他关节照常；反方向运动照常通过。任何运动使该关节指令越过触发位置 0.002 rad 以上时立即触发（`TORQUE_LIMIT`）。使该关节离开负载的运动（收纳、home、jog、笛卡尔、看门狗收纳）在力矩不超过触发力矩 + 10 % 阈值且关节跟随指令时，最长 1.5 s 内不因该关节触发；其他关节照常检测。保持期间租约过期：看门狗收纳按收纳方式退出；若静止位位于施力方向或收纳被触发，机械臂保持力矩并锁存 Fault `WATCHDOG_TIMEOUT`，日志注明力矩保持。关节离开保持位置 0.05 rad 且 |力矩| 低于阈值，或断力矩、急停、Fault、进入重力补偿时保持结束。客户端做法：收到 `TORQUE_LIMIT` 不要重试同一目标，先把该关节反向移出或收纳，再重新规划。

## Power budget / 电源功率预算

armd estimates the motor supply current from the measured joint torques and velocities with datasheet motor parameters (capability `power_budget`, capabilities version 9; profile section `power_budget`, absent = off). There is no current sensor: the values are estimates, not measurements. B601-DM: Mean Well LRS-150-24, 6.5 A rated, trip ~8.5 A. Full model, parameters and rules: `docs/control_safety_contract.md` "Power budget".

- `observation.power` (null without a budget):

  ```json
  "power": {"valid": true, "bus_a": 1.42, "peak_a": 2.10, "rated_a": 6.5, "ratio": 0.218, "regen_w": 0.0,
            "per_joint_a": [0.02, 0.41, 0.33, 0.12, 0.02, 0.02, 0.02], "scale": 1.0, "limiting": false, "hold": false}
  ```

  `bus_a` estimated supply current (A, 0.25 s low-pass), `peak_a` its 5 s peak, `ratio` = `bus_a / rated_a`, `regen_w` mechanical power fed back by the motors (not credited), `per_joint_a` per-joint share (idle power included, the base load is not), `scale` speed scale the governor applies to every motion this tick, `limiting` the governor slows or holds, `hold` a power hold is in force. `valid: false` (numbers 0) without fresh torque feedback.
- Governor: above 80 % of the rating motions slow down (`scale` < 1, `motion_limit.reason` `power`); above 95 % for 100 ms while a joint pushes in its torque direction the running action ends `failed` with code `POWER_LIMIT`, every motion ends and the measured pose is held with torque on (`power.hold` true, `motion_limit` `{"reason": "power", "joint"}`); no Fault. During the hold, servo / jog targets that move a pushing joint further in its push direction are clamped; yielding targets pass. The hold ends after the estimate stays below 80 % for 300 ms. Not applied in gravity compensation.
- Planning: every planned motion (jog / joint_move, home, move_to_pose, move_to, move_relative, grasp and place sub-motions, replay, park) is checked with URDF inverse dynamics before it starts; if its estimated peak exceeds 75 % of the rating it is slowed (duration / scale). The action record carries `power_scale` (1 = as planned, < 1 slowed; absent without a budget and for the gripper action) and `expected_duration_s` includes the slowing. If even 20 % speed does not fit, the command is rejected with `422 POWER_BUDGET`.
- `GET /api/v1/diagnostics/power` (no lease): `{"enabled", "estimate_only", "observation", "fast_a", "raw_a", "peak_5s_a", "peak_60s_a", "max_a", "max_at_s", "over_rated_s", "idle_a", "governor": {"scale", "limited_s", "holds_total", "hold"}, "budget"}`; `{"enabled": false}` without a budget. `schema.power_budget` is the budget in force; `GET /api/v1/safety/describe` lists the hold as `power_limit_hold`.

Client pattern: on `POWER_LIMIT`, wait for `power.hold` to clear, then retry slower or with less load; on `POWER_BUDGET`, the motion cannot fit the supply at any allowed speed (e.g. the target pose needs more holding current than the budget): choose another target or a larger supply.

armd 根据实测关节力矩、速度和数据手册电机参数估算电机电源电流（能力 `power_budget`，能力版本 9；profile 段 `power_budget`，缺省为关闭）。没有电流传感器：数值是估算值，不是测量值。B601-DM：明纬 LRS-150-24，额定 6.5 A，约 8.5 A 触发。完整模型、参数与规则见 `docs/control_safety_contract.md`「电源功率预算」。`observation.power` 结构见上：`bus_a` 为估算电源电流（A，0.25 s 低通），`peak_a` 为其 5 s 峰值，`ratio` = `bus_a / rated_a`，`regen_w` 为电机回馈的机械功率（不抵扣），`per_joint_a` 为各关节份额（含待机功率，不含基础负载），`scale` 为本周期调速器对所有运动施加的速度比例，`limiting` 表示正在降速或保持，`hold` 表示功率保持生效；无新鲜力矩反馈时 `valid: false`（数值为 0），无预算时为 null。调速：超过额定值 80 % 时运动降速（`scale` < 1，`motion_limit.reason` 为 `power`）；超过 95 % 持续 100 ms 且有关节沿其力矩方向施力时，正在执行的动作以 `POWER_LIMIT` 失败，所有运动结束，在实测位姿保持力矩（`power.hold` 为 true，`motion_limit` 为 `{"reason": "power", "joint"}`），不锁存 Fault；保持期间使施力关节继续朝施力方向运动的 servo / jog 目标被限制，顺从方向照常通过；估算值低于 80 % 持续 300 ms 后保持结束；重力补偿期间不调速。规划：所有规划运动（jog / joint_move、home、move_to_pose、move_to、move_relative、抓取与放置子运动、回放、收纳）开始前用 URDF 逆动力学检查，估算峰值超过额定值 75 % 时放慢（时长 / 比例）；动作记录带 `power_scale`（1 为原规划，< 1 为已放慢；无预算或夹爪动作时缺省），`expected_duration_s` 已包含放慢；20 % 速度仍不满足时以 `422 POWER_BUDGET` 拒绝。`GET /api/v1/diagnostics/power`（无需租约）字段见上；`schema.power_budget` 为生效的预算；`GET /api/v1/safety/describe` 中保持为 `power_limit_hold`。客户端做法：收到 `POWER_LIMIT` 时等 `power.hold` 清除后放慢或减小负载再试；收到 `POWER_BUDGET` 表示任何允许速度下都超出电源（例如目标位姿所需保持电流超过预算），应换目标或换更大的电源。

## Safety self-description / 安全自描述

`GET /api/v1/safety/describe` (no lease; capability `safety_describe`) lists this armd's timing, joint and Cartesian limits, keep-out boxes, speed cap, stops (`e_stop`, `watchdog` with the outcome for this config, `bus_loss`, `control_deadline`, `following_error`, `thermal`, and `collision_protective_stop` with `collision_guard`), every fault code with its recovery steps, and hardware notes. Values come from the running config and the code's constants. A client or AI assistant reads it before planning motion and keeps within those limits. Field list: `docs/control_safety_contract.md` "Safety self-description".

`GET /api/v1/safety/describe`（无需租约；能力 `safety_describe`）列出本 armd 的时序、关节与笛卡尔限值、禁入盒、速度上限、停止方式（`e_stop`、按本配置给出结果的 `watchdog`、`bus_loss`、`control_deadline`、`following_error`、`thermal`，有 `collision_guard` 时另有 `collision_protective_stop`）、每个故障码及其恢复步骤和硬件说明。数值取自运行中的配置与代码常量。客户端或 AI 助手在规划运动前读取，并在这些限值内运行。字段列表见 `docs/control_safety_contract.md`“安全自描述”。

## Grasp / 点框抓取

`/api/v1/action/grasp` picks up an object the user selected in the camera image. The request names a detection box (normalised `box_norm` from the detector, its `label`, optionally the frame); the action does the rest and ends with the object lifted, or with a failure code.

`/api/v1/action/grasp` 抓取用户在画面中选中的物体：请求给出检测框（归一化 `box_norm`、类别 `label`，可选帧号），动作完成后物体被抬起，或以失败码结束。

Needs a 7-DOF profile with `kinematics`, `gripper_policy` and `grasp` (the built-in `rebot-dm` has all three); otherwise `UNSUPPORTED`.

### Before the ack / 应答之前

Under the lock: lease, epoch, request_id, body, then the same preconditions as other actions (`MOTION_BUSY` etc.). Outside the lock: the box centre ray (setup intrinsics, current commanded pose, `camera_mount`) is intersected with the plane z = `table_z_m + grasp_height_m` to estimate the target; the approach pose above it (look-down, or camera-down, see [Camera-down acquisition](#camera-down-acquisition--相机朝下采集)) is planned with the gripper open, along with the vertical descent column (approach to grasp height) chained through `motion::plan_cartesian`, and paths (with the camera-down transition) are checked against the [table clearance](#table-clearance--桌面间隙). A planning failure is a `command_reject` with the planner's code (`IK_UNREACHABLE`, `IK_BRANCH_FLIP`, `WORKSPACE_VIOLATION`, 422); a ray that does not meet the table in front of the camera, or `acquire_camera_down: "on"` without `camera_mount.offset_m`, is `INVALID_COMMAND`. A request naming a [grasp task](#grasp-tasks--抓取任务) with `models` first has the provider switch models when its resident set differs, then a task with `requires` is checked against the provider's `GET /api/mode` (outside the lock); a refused switch or a mismatch is a `command_reject` `TASK_UNSUPPORTED` (422) and no action starts. Then the action begins and the ack carries `action_id` and a rough `expected_duration_s`.

When `dry_run: true` is set in the request body (supported over WS and via `POST /api/v1/action/grasp`), the prepare and plan steps run to verify reachability without starting an action or requiring a lease (returns 200 OK via REST, WS `command_ack` with `{"reachable": true, ...}` or on failure `{"reachable": false, "code": "...", "message": "..."}`). With a `task`, the reply also carries `task_supported` (bool) and `task_reason` (null, the `TASK_UNSUPPORTED` message, or `needs model switch`); `reachable` stays the geometry's result. A dry run never switches models: with `models` that differ from the resident set it reports `task_supported: false` and the `ION_BUDGET` reason when the switch does not fit the provider's ION budget (computed from `models.catalogue[].ion_mb` and `ion`; skipped when the provider does not report them), else `task_supported: true` with `task_reason: "needs model switch"`; only with the resident set matching are the `requires` checked on it.

锁内校验租约、epoch、request_id、请求体和动作前置条件；锁外用框中心射线与平面 z = `table_z_m + grasp_height_m` 求交估计目标位置，并以夹爪张开状态规划接近位姿（俯视；相机朝下采集时为光轴竖直）及自接近高度至抓取高度的竖直下降列路径（通过 `motion::plan_cartesian` 链式检查），接近路径（相机朝下时含转换路径）按[桌面间隙](#table-clearance--桌面间隙)检查。规划失败直接 `command_reject`（`IK_UNREACHABLE` / `IK_BRANCH_FLIP` / `WORKSPACE_VIOLATION`，422）；射线不与桌面相交、或 `acquire_camera_down: "on"` 而 `camera_mount.offset_m` 未设置，返回 `INVALID_COMMAND`。

当请求体中携带 `dry_run: true` 时（支持 WS 与 `POST /api/v1/action/grasp`），仅执行准备与规划以校验可达性，无需租约且不启动动作（REST 返回 200 OK，WS `command_ack` 携带 `{"reachable": true, ...}`；失败时携带 `{"reachable": false, "code": "...", "message": "..."}`）。请求带 `task` 时回复另带 `task_supported`（bool）与 `task_reason`（null、`TASK_UNSUPPORTED` 的消息或 `needs model switch`），`reachable` 仍只表示几何可达性。dry run 不切换模型：任务的 `models` 与常驻模型不同时，若切换超出提供端 ION 预算（按 `models.catalogue[].ion_mb` 与 `ion` 计算；提供端未报告时跳过）则 `task_supported: false` 并给出 `ION_BUDGET` 原因，否则 `task_supported: true`、`task_reason: "needs model switch"`；只有常驻模型一致时才按当前模型检查 `requires`。

### Phases / 阶段

An async task outside the supervisor lock and the control tick runs the phases; `action.phase` and `action.progress` report them:

| phase | what happens |
|---|---|
| `open` | gripper `open` |
| `approach` | move_to above the estimate at `table_z_m + approach_height_m`, tool axis (end_link x) straight down, heading kept (minimal rotation). Camera-down: optical axis straight down instead, lens centre above the estimate (below) |
| `centring` | closed loop: wait for frames captured `settle_delay_s` after the last motion settled, match the target, take the median centre of `median_frames` frames; done when within `centre_tol_px` of the grip pixel (camera-down: of the image centre) for `stable_frames` consecutive frames; otherwise step = `servo_gain` × (table point of the box centre − table point of the grip pixel / image centre), at most `max_step_m`, as a base-frame move_relative. `iteration` = corrections made, `error_px` = latest error. More than `max_iterations` corrections → `CENTRING_FAILED`. A box cut by the image border at the aim: centred again at an aim inside the image ([Robustness steps](#robustness-steps--稳健性步骤), Border-cut box) |
| `transition` | camera-down only: one Cartesian move to the tool-vertical pose above the target's table point at approach height; then a re-check frame (below) |
| `probe` | height probe (below): straight up by `height_probe_m`, a few frames, back to the start pose; object top from the box scale change. `height_probe_mode: "lateral"`: sideways to −B/2 and +B/2 along the image x axis instead, object top from the parallax |
| `shift` | look-down only, after a centring at a border-free aim (below): one base-frame move of the TCP over the box centre's point on the (top) plane |
| `align` | detector angle (below) when available, else: when the box's long / short side ratio ≥ `align_min_aspect` and the jaws (end_link y in the image) would close across the long side: roll ±90° about the tool axis (the sign that keeps J6 inside its limits). Skipped for an unreliable box (below). When `grasp_width_px` is reported with confidence ≥ `align_min_angle_conf`, its metric length on the plane > `max_grasp_width_m` fails `TOO_WIDE` before descending (jaws open, arm stays). |
| `preopen` | width-based pre-open (below): close the jaws from full open to `width + pre_open_margin_m` before descend; skipped when at/beyond `open_rad`, no width, border/occluded, or uncalibrated (`auto`) |
| `descend` | straight down to `table_z_m + grasp_height_m` (or the close height from the probe) at `descend_speed_mps`; look-down: first to `recentre_height_m`, then `recentre`, then the rest |
| `recentre` | look-down only: the centring loop once more at mid height (below) |
| `close` | gripper `close` with grasp detection; `holding` per `gripper_policy` |
| `release` | not holding: gripper `open`, then `lift`, then `failed` / `NOT_HOLDING` (`holding:false`); no retry |
| `lift` | straight up to `table_z_m + lift_height_m`; then the holding re-check (below), `DROPPED` when the object is gone |
| `done` | `state:"done"`, `holding:true`, `gripper_gap_rad`; the jaw keeps its hold target in `commanded_positions[6]` |

由锁外异步任务按阶段执行，`action.phase` / `action.progress` 报告当前阶段：`open` → `approach` → `centring` →（高度探测）`probe` →（仅俯视、框被画面边界截断时）`shift` →（仅相机朝下采集）`transition` → `align` →（预闭合）`preopen` → `descend` →（仅俯视）`recentre` → `descend` → `close` →（未抓住）`release` → `lift` → `done`。对齐阶段若检测到物体横截面宽度超出 `max_grasp_width_m`，则在下降前以 `TOO_WIDE` 失败（夹爪保持张开，机械臂保持在接近高度）。对中阶段只用运动停稳之后拍到的帧；停稳之前拍到的帧不延长 `lost_timeout_s`（从请求和停稳时刻中较晚者起算），超时为 `TARGET_LOST`；像素误差按粗略内参和 FK 已知高度换算为米，再乘保守增益，所以内参或安装角不准只会多走几步，不会发散。

Target tracking: same label, centre within `match_dist_px` of the predicted centre or IoU > `match_iou`; the first match after the approach uses the wider `acquire_dist_px` around the projection of the estimate. No match in `lost_frames` fresh frames or for `lost_timeout_s` → `TARGET_LOST`; frames captured before the motion settled do not extend `lost_timeout_s` (counted from the later of the request and the settle time). No frames at all for max(3 s, `lost_timeout_s`) → `TARGET_LOST`; a detector error → `DETECTION_UNAVAILABLE`. If inference was off, the grasp turns it on and turns it off again when it ends (any outcome).

Every motion is a sub-motion of the one grasp record: it is installed under the lock only while the grasp is still the running action of the same lease and epoch, and sub-motion results go to the orchestrator, not to `action`. A motion longer than its planned duration × 2 + 5 s (gripper: expected duration + 10 s), capped at `phase_timeout_s`,, or the whole grasp longer than `timeout_s`, stops the motion and ends as `GRASP_TIMEOUT`. Sub-motion failures (`TRACKING_STALL`, `GRIPPER_TIMEOUT`, planner codes) end the grasp with that code.

Ending a grasp from outside:

| cause | state / code |
|---|---|
| `/motion/stop` (during a motion or between motions) | `cancelled` / `STOPPED` |
| new jog / preset / home / park / action | `cancelled` / `SUPERSEDED` |
| lease released, preempted or connection closed | `cancelled` / `LEASE_LOST` |
| E-stop / Fault / lease watchdog | `failed` / `ESTOP_ACTIVE` / `FAULT` / `WATCHDOG` |

Before the ack the grasp is planned and its task checked (with `models`, the model switch can take 7 s or more). On the WebSocket this runs in its own task: `/motion/stop`, E-stop, heartbeats and lease messages on the same connection are handled at once; other messages wait and are answered after the grasp reply, in order. A stop or E-stop in that time answers the grasp `command_reject` 409 `STOPPED` / `ESTOP_ACTIVE` (no action record is created) and every waiting command / preset / servo frame with the same code; the grasp does not begin afterwards.

应答前抓取先规划并检查任务（带 `models` 时模型切换可能需要 7 s 以上）。在 WebSocket 上这一步在独立任务中执行：同一连接上的 `/motion/stop`、急停、心跳和租约消息立即处理；其他消息排队，在抓取应答之后按顺序处理。这期间收到停止或急停时，抓取返回 `command_reject` 409 `STOPPED` / `ESTOP_ACTIVE`（不创建动作记录），排队的 command / preset / servo 帧返回同一代码；之后抓取不会开始。

The record ends in the same tick; a sub-motion still carrying the grasp is stopped, and the orchestrator issues nothing more. Servo frames are rejected with `MOTION_BUSY` for the whole grasp, including the waits between motions.

外部停止（停止、急停、租约丢失、被新指令替代）在同一 tick 内结束动作记录，仍在执行的子运动被停止，编排任务不再下发任何运动。抓取期间（包括两次运动之间的等待）servo 帧一律返回 `MOTION_BUSY`。

### Table clearance / 桌面间隙

Every grasp sub-motion, look-down and camera-down alike (`approach`, each `centring` step, `transition`, `align`, `descend`, `lift`), keeps the envelope at least 5 mm above `table_z_m` along its path. The envelope is the TCP (jaw tips), every `workspace.check_points_end_m` point and, when `camera_mount.offset_m` or `camera_mount.body_size_m` is set, the lens centre (`offset_m`; the end_link origin when only `body_size_m` is set, as the grasp camera model assumes) and the 8 corners of the camera body box (`body_size_m` or its default, see [Camera-down acquisition](#camera-down-acquisition--相机朝下采集)). The general workspace check compares against `workspace.floor_z_m`, not the table, and counts the lens centre only. Paths are sampled as the planner interpolates them (5 mm / 1.1°).

- Before the ack: the approach path from the commanded pose and, camera-down, the transition from the planned acquisition pose. A violation is a `command_reject` `WORKSPACE_VIOLATION` (422).
- During the grasp: every sub-motion, from the commanded pose to its goal, before it is installed. A violation ends the grasp `failed` / `WORKSPACE_VIOLATION` in that phase with nothing installed; the message names the point index, its z and the bound (`table_z_m + 0.005`). The descent is checked here, not before the ack.
- A path that starts below the bound may move as long as no envelope point goes lower than its own start height, and every point that starts above the bound stays above it, so the lift from the grasp height passes. The rule is checked per point: a rotation that lowers one point while another started lower is still rejected.

The bound is the same for every point, the TCP included. `grasp_height_m` is validated ≥ 0.005, so the tool-vertical jaw tips at the grasp height always satisfy it; the default `grasp_height_m` 0.015 leaves 10 mm for points below the jaw-tip plane. With the tool vertical a point's height relative to the TCP is minus its end_link x (the heading and the J6 alignment do not change it), so the descent fails when a point lies more than `grasp_height_m − 0.005` ahead of the jaw tips along the tool axis, for example a lens or camera body that reaches past the jaws. The kit check points have end_link x ≤ 0; with the v8 `offset_m` [−0.0731, 0.0005, 0.066] and the default body box the camera's foremost point is 58.6 mm behind the jaw-tip plane, so default v5 and v8 grasps are unchanged. Covered by `cargo test --test test_grasp look_down_descent` (lens 9 mm ahead: done; 14.5 mm ahead: `WORKSPACE_VIOLATION` in `descend`, TCP still at approach height).

抓取的每个子运动（俯视与相机朝下两种方式下的 `approach`、每个 `centring` 步、`transition`、`align`、`descend`、`lift`）沿整条路径都使包络点高于 `table_z_m` 至少 5 mm。包络点为 TCP（夹爪尖）、所有 `workspace.check_points_end_m` 点，以及在设置了 `camera_mount.offset_m` 或 `camera_mount.body_size_m` 时的镜头中心（取 `offset_m`；只设置 `body_size_m` 时按抓取相机模型取 end_link 原点）和相机机身方盒的 8 个角点（`body_size_m` 或其默认值）。通用工作空间检查比较的是 `workspace.floor_z_m` 而不是桌面，且只计镜头中心。路径按规划器的插值方式采样（5 mm / 1.1°）。应答前检查接近路径（相机朝下时还检查从规划的采集位姿出发的转换路径），违反时为 `command_reject` `WORKSPACE_VIOLATION`（422）；执行中每个子运动在下发前从当前指令位姿到目标再检查一次，违反时抓取以 `failed` / `WORKSPACE_VIOLATION` 结束于该阶段，不下发该运动，消息给出点序号、其 z 值和下限（`table_z_m + 0.005`）；下降只在此时检查，不在应答前检查。起点已低于下限的路径只要没有点变得更低即可执行，因此从抓取高度抬起总能通过。所有点（含 TCP）使用同一下限。`grasp_height_m` 校验为 ≥ 0.005，因此工具竖直时抓取高度处的夹爪尖总满足下限；默认 `grasp_height_m` 0.015 给夹爪尖平面以下的点留 10 mm。工具竖直时某点相对 TCP 的高度等于其 end_link x 的相反数（朝向和 J6 对齐不改变它），所以沿工具轴伸出夹爪尖超过 `grasp_height_m − 0.005` 的点（如伸出夹爪的镜头或机身）会使下降失败。套件检查点的 end_link x ≤ 0；v8 的 `offset_m` [−0.0731, 0.0005, 0.066] 加默认机身方盒时，相机最前端在夹爪尖平面后方 58.6 mm，因此默认的 v5、v8 抓取不变。测试：`cargo test --test test_grasp look_down_descent`（镜头伸出 9 mm：完成；伸出 14.5 mm：`descend` 阶段 `WORKSPACE_VIOLATION`，TCP 仍在接近高度）。

### Camera-down acquisition / 相机朝下采集

For a camera mount pitched toward the jaws (v8 holder: `camera_mount` `rot_deg` 0, `tilt_deg` −38), the table point under the jaw tips is outside the image at approach height when the tool points straight down, so the look-down centring above cannot run. The setup field `acquire_camera_down` selects the acquisition:

| value | acquisition |
|---|---|
| `auto` (default) | camera-down when \|`camera_tilt_deg`\| > 5° and `camera_mount.offset_m` is set; look-down otherwise |
| `on` | camera-down; without `camera_mount.offset_m` the request is `INVALID_COMMAND` |
| `off` | look-down |

Camera-down phases:

- `approach`: orientation = the look-down orientation rotated minimally so the optical axis (camera z) points straight down, i.e. the tool pitched by the mount tilt about x_cam, heading kept. Position: lens centre (FK + `camera_mount.offset_m`) above the estimate in x, y; TCP at `table_z_m + approach_height_m`.
- `centring`: the loop above with the image centre (`image_size_px` / 2) as the aim point instead of `grip_pixel_norm`; gains, limits, `stable_frames`, `max_iterations` unchanged.
- `transition`: the ray through the last matched box centre (within `centre_tol_px` of the image centre) is intersected with the plane z = `table_z_m + grasp_height_m`; one planned Cartesian move (IK, workspace and keep-out checks as every motion) goes to the tool-vertical pose with the TCP above that point at approach height. Then, when the camera model projects the target into the image at the new pose, one fresh frame verifies it before the descent: no match (`lost_frames` / `lost_timeout_s`, gate `acquire_dist_px` around the projection) → `TARGET_LOST`; a detector error → `DETECTION_UNAVAILABLE`; box centre more than `recheck_tol_px` from the projection → `TARGET_DISPLACED`. `final_offset_px` = [dx, dy] of the matched box centre minus `grip_pixel_norm` in pixels (a diagnostic; the displacement check uses the projection, so an uncalibrated grip pixel does not fail it). When the target is not expected in view (for example the v8 holder at a 0.15 m approach) nothing is checked and `final_offset_px` is absent.
- `align`, `descend`, `close`, `lift`: as above; J6 alignment uses the last box of the centring.

Table clearance at the camera-down acquisition (the rule for every phase is in [Table clearance](#table-clearance--桌面间隙)): the pitched gripper reaches below the TCP (with the kit check points up to 57 mm at a 38° pitch about the end_link z axis, 21 mm about the y axis), and the workspace check compares against `workspace.floor_z_m`, not the table. The acquisition therefore raises the TCP above `table_z_m + approach_height_m` when needed so that the TCP, every `workspace.check_points_end_m` point, the lens centre and the 8 corners of the camera body box stay at least 5 mm above `table_z_m` at the camera-down orientation and along the transition (the raised height is `action.acquire_height_m`, above the table; absent when not raised). The camera body box is `camera_mount.body_size_m` [width along x_cam, height along y_cam, depth behind the lens along −z_cam] (m, optional, each in (0, 0.2]); the default 0.055 x 0.047 x 0.040 is the reCamera housing (40 x 40 x 36.5 mm) in the v8 holder (walls, ears, support, top bar and rear lip from the holder's generator), lens at the centre of the front face. It is used for the grasp table clearance only, not in the general workspace check, so other motions are unchanged; the general check still counts the lens centre only. With the kit check points and the v8 mount the gripper points, not the body, set the raised height; a mount whose body reaches lower than the gripper is rejected or raised by the same rule. The approach path, each centring step and the transition path are checked against the same bound as every grasp sub-motion.

The accuracy of the transition depends on `camera_tilt_deg`, `camera_mount.rot_deg` and `offset_m`: an error in them moves the grasp point (in the simulated-camera test, a 2° tilt, 1° rot, 5 % focal length and (6, −4) px principal point error gave a 9 mm grasp point error at a 0.15 m approach). `expected_duration_s` adds the transition move and 1.5 s for the re-check frame. With \|`camera_tilt_deg`\| ≤ 5° (v5 mount) `auto` keeps the look-down acquisition unchanged. Validated in simulation only (`cargo test --test test_grasp camera_down`, `sim/mujoco/tests/test_camera_grasp.py` v8 cases); not run on the arm.

相机安装向夹爪方向俯仰时（v8 支架：`camera_mount` `rot_deg` 0、`tilt_deg` −38），工具竖直朝下时夹爪尖正下方的桌面点在接近高度处不在画面内，上面的俯视对中无法进行。抓取设置字段 `acquire_camera_down` 选择采集方式：`auto`（默认）在 \|`camera_tilt_deg`\| > 5° 且 `camera_mount.offset_m` 已设置时用相机朝下采集，否则俯视；`on` 始终相机朝下，`camera_mount.offset_m` 未设置时请求返回 `INVALID_COMMAND`；`off` 始终俯视。

相机朝下采集的阶段：`approach` 将俯视姿态做最小旋转使光轴竖直向下（工具绕 x_cam 俯仰安装倾角，朝向不变），镜头中心（FK + `camera_mount.offset_m`）在 x、y 上位于估计点正上方，TCP 高度为 `table_z_m + approach_height_m`；`centring` 与上面的闭环相同，目标点改为画面中心（`image_size_px` / 2），增益、步长上限、`stable_frames`、`max_iterations` 不变；`transition` 用最后一次匹配框中心（距画面中心不超过 `centre_tol_px`）的射线与平面 z = `table_z_m + grasp_height_m` 求交，一次规划的笛卡尔运动（与其他运动一样做 IK、工作空间和禁入区检查）移到 TCP 位于该点上方接近高度、工具竖直的位姿；之后若相机模型预测目标在新位姿的画面内，下降前取一帧新图复查：未匹配到（`lost_frames` / `lost_timeout_s`，以投影为中心、门限 `acquire_dist_px`）为 `TARGET_LOST`，检测器出错为 `DETECTION_UNAVAILABLE`，框中心距投影超过 `recheck_tol_px` 为 `TARGET_DISPLACED`；`final_offset_px` = 匹配框中心减 `grip_pixel_norm` 的像素差 [dx, dy]（诊断用；位移判断以投影为准，抓取像素未标定不会导致失败）；预测目标不在画面内时（如 v8 支架、0.15 m 接近高度）不做复查，`final_offset_px` 缺省；`align`、`descend`、`close`、`lift` 不变，J6 对齐使用对中阶段最后一个框。相机朝下采集时的桌面间隙（所有阶段的规则见[桌面间隙](#table-clearance--桌面间隙)）：俯仰后的夹爪会低于 TCP（套件检查点在绕 end_link z 轴俯仰 38° 时最多低 57 mm，绕 y 轴时 21 mm），而工作空间检查比较的是 `workspace.floor_z_m`，不是桌面。因此采集时在需要时把 TCP 抬高到 `table_z_m + approach_height_m` 以上，使 TCP、所有 `workspace.check_points_end_m` 点、镜头中心和相机机身方盒的 8 个角点在相机朝下姿态及整个转换过程中都高于 `table_z_m` 至少 5 mm（抬高后的高度见 `action.acquire_height_m`，相对桌面；未抬高时缺省）。相机机身方盒为 `camera_mount.body_size_m` [沿 x_cam 宽、沿 y_cam 高、沿 −z_cam 镜头后方深度]（米，可选，每项 (0, 0.2]），默认 0.055 x 0.047 x 0.040，即 reCamera 外壳（40 x 40 x 36.5 mm）装在 v8 支架内（壁厚、耳、底托、顶杆和后唇取自支架生成脚本），镜头位于前面中心。它只用于抓取的桌面间隙，不进入通用工作空间检查，因此其他运动不变；通用检查仍只计镜头中心。使用套件检查点和 v8 支架时，决定抬高量的是夹爪检查点而不是机身；机身比夹爪更低的安装按同一规则抬高或拒绝。接近路径、每个对中步和转换路径与抓取的其他子运动按同一下限检查。转换的精度取决于 `camera_tilt_deg`、`camera_mount.rot_deg` 和 `offset_m`（模拟相机测试中倾角差 2°、旋转差 1°、焦距差 5 %、主点偏 (6, −4) px，在 0.15 m 接近高度下抓取点偏差 9 mm）。`expected_duration_s` 增加转换运动时长和 1.5 s 复查帧。\|`camera_tilt_deg`\| ≤ 5°（v5 支架）时 `auto` 保持原俯视流程不变。仅在仿真中验证（`cargo test --test test_grasp camera_down`、`sim/mujoco/tests/test_camera_grasp.py` 的 v8 用例），未在真机上运行。

### Robustness steps / 稳健性步骤

Steps added 2026-11-12. Each one has setup fields (table below); when it cannot run it is skipped, the reason goes into the action status and the grasp continues as without it, except `OBJECT_TOO_TALL`, `TOO_WIDE`, and `DROPPED`, which end the grasp. Every extra motion is checked against the [table clearance](#table-clearance--桌面间隙) like the other sub-motions. Validated in simulation only (`cargo test --test test_grasp`: `align_`, `height_probe`, `recentre`, `descend_logs`, `post_lift`); not run on the arm.

- **J6 alignment guard and detector angle** (`align`). No turn when the last centring box has an edge within 2 px of the image border, or its area differs by more than 40 % from the median area of the centring frames at the final pose (the jaws or a hand cover it). Detections may carry `angle_deg` (long side in the image, from +x toward +y, y down, deg, wrapped to [−90, 90)) and `angle_conf` [0, 1]. When frames have `angle_conf` ≥ `align_min_angle_conf`, their mean angle (on doubled angles) is mapped onto the table plane from the centring pose, and the roll turns the jaw closing direction (end_link y) perpendicular to the long side; of the equivalent rolls (±π) the smallest one that keeps J6 0.1 rad inside its limits is used. Circular dispersion of accepted angles is gated by `align_max_angle_spread_deg` (default 15.0°): when dispersion exceeds this limit, alignment is skipped with status `align: "skipped:angle_spread"` (recording `angle_spread_deg` on the action status, no fallback to box aspect), and width check projects along the jaw closing axis seen in the image. Without angle data the aspect rule above applies (`align_min_aspect` is checked only there: an oriented object at 45° has an axis-aligned box near aspect 1). Status `align`: `turned:angle`, `turned:box`, `kept:angle`, `kept:box`, `off`, or `skipped:border` / `occluded` / `aspect` / `j6_limits` / `ray` / `angle_spread`; `align_turn_rad` = the roll. MuJoCo check (`axis_block` in `sim/mujoco/tests/test_camera_grasp.py`: 6 x 3 cm block turned 36.5°, angle from the ground-truth mask, 0.20 m approach): `turned:angle` with a roll of −0.629 rad (−36.1°); after the lift the block's long side was at 90.0° to the jaw closing direction. At a 0.15 m approach its box reached the image border and the alignment was skipped.
- **Height probe** (`probe`). After the centring (look-down at approach height; camera-down at the camera-down pose, before the transition), when the optical axis is within 5° of vertical and `camera_mount.offset_m` is set: straight up by `height_probe_m` (when the planner rejects that pose for IK or the workspace, by 0.06 m; the move used is `probe_dz_m`), `median_frames` fresh matched frames, then back to the start pose. Box size s = √(w·h) px of the centring frames (s_low, at the start pose) against the raised frames (s_high): D_low = Δz · s_high / (s_low − s_high) (lens to the object's top at the start pose), object top = lens z − D_low − `table_z_m`. Accepted when s_low / s_high ≥ 1.03, the height uncertainty from the frames' size spread is at most 0.01 m, finite and ≥ 0; then box centres map onto the plane z = `table_z_m` + max(`grasp_height_m`, top) (transition ray, alignment, re-centre), and the jaws close at clamp(top · `height_grasp_fraction`, `grasp_height_m`, `max_grasp_height_m`) above the table. A top ≥ `approach_height_m` − 0.02 fails `OBJECT_TOO_TALL` (the arm stays at the start pose). Status: `height_source` `scale` with `object_height_m`, or `setup` with `height_reason` (`disabled`, `no_lens_centre`, `camera_not_vertical`, `border`, `table_clearance`, `ray`, `probe_unreachable` (both raised poses fail IK or the workspace check; nothing moved), `target_lost`, `scale_change:<ratio>`, `scale_noise:<m>` (box size spread of the frames gives a height uncertainty above 0.01 m), `below_table:<h>`, `not_finite`); `close_height_m` = TCP height at the close. The probe moves up (2026-11-12, replacing a downward probe that could reach an object taller than `approach_height_m` − `height_probe_m` before its height was known), so the jaws never go below the start height during it. For the same Δz the upward move sees a smaller scale change, so the default raise is 0.10 m: in a synthetic comparison (lens 0.13 m above the top, 3 frames per pose, 3 % size jitter, 2000 draws) the median distance error was 5.7 mm for the former 0.04 m downward probe and 7.9 / 6.7 / 5.8 mm for 0.06 / 0.08 / 0.10 m up, with 868 and 357 / 601 / 790 of 2000 estimates passing the noise check (`cargo test --lib up_and_down -- --nocapture`). In the MuJoCo test with the lens 45 mm off the tool axis (`axis_cube`, `axis_cup` in `sim/mujoco/tests/test_camera_grasp.py`, ground-truth boxes) the probe estimated the 0.04 m cube at 0.046 m and the 0.07 m cup at 0.074 m; with the v8 holder's 66 mm lens offset the box of the object under the jaws reaches the image border at a 0.15 m approach and the probe falls back (`border`).
- **Lateral height probe** (`height_probe_mode: "lateral"`, 2026-11-13; default `up`). Same preconditions as the up probe (`height_probe_m` > 0, optical axis within 5° of vertical, `camera_mount.offset_m` set, no centring box at the border). From the centring pose the tool moves horizontally, orientation unchanged, to −B/2 and then +B/2 (B = `lateral_probe_m`) along the base-frame direction of the image x axis, takes `median_frames` fresh matched frames at each pose and returns to the start pose. D = fx · B_meas / \|du\|: du = median u at the +B/2 pose minus the −B/2 pose; B_meas = the image-x component of the lens displacement between the two poses from FK of the measured joints plus `camera_mount.offset_m`; object top = mean measured lens z of the two poses − D − `table_z_m`. The u feature must lie on the object's top face at both poses: the box centre when every box straddles the principal point, else the box edge on the far side of the principal point when it is on that side in every box (looking down, the edge on the near side is the bottom of a side face; with the box centre the MuJoCo cube at u 0.3 came out at 0.023 m instead of 0.04 m). Accepted under the up probe's rules: \|du\| ≥ 5 px, height uncertainty D / \|du\| · √(e₋² + e₊²) ≤ 0.01 m (e = half range of the feature's u over the frames of a pose), finite and ≥ 0, `OBJECT_TOO_TALL` at ≥ `approach_height_m` − 0.02. Falls back to the up probe, `height_reason` `lateral_fallback:<why>` (`border`: the box shifted by the predicted parallax fx · B/2 / D0, D0 = lens height above `table_z_m + grasp_height_m`, comes within 2 px of the image border at either pose, or a box seen at a lateral pose touches it; `edge`: no feature on the top face at both predicted or seen poses; `unreachable`: a lateral pose fails the table clearance, IK or the workspace check; `target_lost`), joined as `lateral_fallback:<why>,<up reason>` when the up probe fails too. Status: `height_source` `parallax`, `probe_mode` `lateral` or `up` (the probe that ran last; absent when none moved), `lateral_baseline_m` (B_meas) and `lateral_baseline_err_mm` (B_meas minus the image-x component of the commanded lens displacement, = `lateral_probe_m` with a vertical optical axis); `height_reason` adds `parallax_shift:<px>`, `parallax_noise:<m>`, `parallax_baseline:<m>`. `expected_duration_s` adds 2 · 1.875 · B / `approach_speed_mps` + 1.5 s. MuJoCo comparison (`_scratch/parallax/sim_parallax.py`; lens 45 mm off the tool axis, rot −90, tool down, lens above the object at lens-to-top distances 0.13 and 0.20 m; 3 px centre jitter and 5 % size jitter, seeds 1–5): median height error up to −12.7 mm (worst 62 mm) for the 0.10 m up probe, within 2 mm (worst 10.6 mm) for ±20 mm lateral (box centre); without noise both within 2 mm; the 6 cm block at 0.13 m touched the border at the lateral poses; measured and commanded baselines differed by < 0.05 mm. In `axis_cube_lateral` (`sim/mujoco/tests/test_camera_grasp.py`, ground-truth boxes, approach 0.20 m) the 0.04 m cube came out at 0.0424 / 0.0425 m (two runs) from the left edge, `lateral_baseline_err_mm` 0.02–0.03; at the 0.15 m approach of `axis_cube` the predicted shift reaches the border and the probe falls back (`lateral_fallback:border`, up result 0.046 m). The default stays `up` until the baseline error is measured on the real arm (the sim pose error is not the real arm's); see [real-arm calibration](#real-arm-calibration-v8-mount--真机标定v8-支架). Tests: `cargo test --lib parallax top_face`, `cargo test --test test_grasp lateral_probe`.
- **Height sources** (`height_sources`, `height_record`, `height_priors`, 2026-11-14). The object height comes from the first source in `height_sources` that accepts: `depth` (depth inference: `depth_anchor` `metric_table`, `oblique_ransac` or `two_height_fk`), `probe` (the up or lateral probe above), `prior` (`height_priors` for the target's label, case-insensitive); each accepted height passes the probe's rules (finite, ≥ 0, `OBJECT_TOO_TALL` at ≥ `approach_height_m` − 0.02). When none accepts, the grasp goes on at `grasp_height_m` (`height_source` `setup`, `height_reason` = the reasons of the non-depth sources joined by `,`). A too-tall height from a deciding source ends the grasp with `OBJECT_TOO_TALL` only when no later source accepts; a stop, fault or other failure during the probe ends it at once. Sources in `height_record` (not in `height_sources`) are evaluated first and only reported: they never choose the height and never end the grasp. Default: `height_sources` `["probe"]`, `height_record` `["depth"]`: depth is measured and recorded, the probe decides (rollout: collect depth against probe heights on the real arm first; `height_sources: ["depth", "probe"]` restores the behaviour before 2026-11-14, where depth decided and the probe measured when depth did not accept). The depth capture (a triggered yolo+depth frame at the start pose and one at the centring pose) runs when `depth` is in either list, the provider has depth inference, frames are triggered and `camera_mount.offset_m` is set; its frame at the centring pose replaces the last centring box (alignment and width use it) also when depth is record-only, and the depth width is the width fallback whenever a depth measurement exists. `depth_anchor`, `object_depth_m`, `object_length_m` and `jaw_clear` are reported when depth decided or is record-only. Status `height_estimates`: one entry per evaluated source in evaluation order, `{source, value, used, record_only, reason}`: `source` `depth:<anchor>` (or `depth` without a measurement: `reason` `unavailable`, `no_lens_centre`, or why the capture gave none, see [yaw and width sources](#robustness-steps--稳健性步骤)), `scale` / `parallax` (accepted probe) or `probe` (rejected or too tall), `prior` (`no_prior` without a prior); `value` the measured height (m), also when rejected or too tall; `reason` the reject reason or `OBJECT_TOO_TALL`. Sources after the chosen one are not evaluated. Tests: `cargo test --lib -- estimate height_source_settings`, `cargo test --test test_grasp -- depth_ record_only prior_ height_selection stop_during_the_probe`.
- **Yaw and width sources** (`yaw_sources`, `yaw_record`, `width_sources`, `width_record`, 2026-11-14). rebot-vision reports the depth pipeline's own angle and width as `depth_angle_deg`, `depth_angle_conf`, `depth_width_px` and no longer writes them into `angle_deg` / `angle_conf` / `grasp_width_px` (a plain detection model with depth used to turn J6 from the depth angle; it now aligns from the box aspect and records the depth angle). J6 yaw: the alignment guard (`skipped:border` / `skipped:occluded`) runs first. Sources in `yaw_record` (not in `yaw_sources`) are then evaluated and only reported. The `yaw_sources` run in order: `mask` (`angle_deg` with `angle_conf` ≥ `align_min_angle_conf`) and `depth` (`depth_angle_deg` with `depth_angle_conf` ≥ `align_min_angle_conf`, on the frames of the depth trigger) pass to the next source without such an angle (`no_angle`); with one they decide: `skipped:angle_spread` (dispersion > `align_max_angle_spread_deg`; no fallback to the box), `skipped:ray`, `skipped:j6_limits`, else `turned:angle` / `kept:angle` (`mask`) or `turned:depth` / `kept:depth` (`depth`). `box` passes on `aspect` (ratio < `align_min_aspect`), else `turned:box` / `kept:box`. When every source passes, `align` is `skipped:<reason of the last source>` (`skipped:aspect` with the default). `angle_spread_deg` is written only by a deciding `mask` source. The depth trigger runs when `depth` is in `height_sources`, `height_record` or `yaw_sources`; `depth` in `yaw_record` or `width_sources` uses it only when it ran. Pre-open counts only `turned:angle` / `kept:angle` as aligned to the mask: with `turned:depth` and a confident mask angle the pre-open is `skipped:not_aligned`. Width: `width_record` sources are reported first, then `width_sources` in order until one accepts: `mask` (median `grasp_width_px` of the centring frames across the mask angle, as before; `no_width`, `ray`), `depth` (the depth measurement's width: the detector's `grasp_width_px` / `angle_deg` when it reports them, else `depth_width_px` / `depth_angle_deg`; `no_width`, or the depth reason). The chosen width is `grasp_width_m`; one TOO_WIDE check applies to it (the calibrated opening minus `pre_open_margin_m`, at most `max_grasp_width_m`). Status `yaw_estimates` (value: the long side in the image, deg; `box`: 0 or −90) and `width_estimates` (value: m) use the `height_estimates` entry format. The depth entry of `height_estimates` now gives why there is no measurement: `no_depth_frame`, `target_lost`, `too_few_samples`, `table_contradicts_fk`, `no_oblique_spread`, `no_two_height_spread`, `two_height_fit`, `two_height_mismatch`, `low_conf`, `no_disparity`, `bad_disparity`, `too_flat` (before: `no_measurement`). `jaw_clear` (rebot-vision) is checked across the mask angle's closing direction when the detection has a mask angle, else across the depth PCA minor axis; armd reports it and does not act on it. Tests: `cargo test --lib -- yaw_ depth_angle depth_measurement_width depth_calibration_and_measurement_report`, `cargo test --test test_grasp -- yaw_and_width_estimates depth_entry_reports`, MuJoCo `axis_block_detect_depth_record` / `axis_block_detect_depth_yaw`.
- **Mid-height re-centre** (`recentre`, look-down only, `camera_mount.offset_m` set). Descend to `recentre_height_m`, then the centring loop with at most `recentre_max_iterations` corrections, aimed at the model's projection of the point under the TCP on the (top) plane plus the calibration offset (`grip_pixel_norm` minus the model's projection of that point at the centring pose). Runs only when `recentre_height_m` is above the close height + 0.02 and below the current TCP height. Status `recentre`: `done` (with `recentre_iterations`), `unconverged` (corrections ran out; the descent goes on), `skipped:disabled` / `no_lens_centre` / `height` / `projection` / `table_clearance` / `aim_outside_image` / `target_lost`. Its `error_px` is not published (`iteration` / `error_px` stay those of the main centring).
- **Border-cut box** (`border`, `shift`, 2026-11-13). When the centring has converged on the grip pixel (camera-down: the image centre) and the median edge of the target's box over the frames at that pose is within 2 px of one image border, the box is cut and its centre is not the target's. The centring then runs again on an aim pixel inside the image: on each cut axis the estimated full extent (the larger of the visible extent and the box's extent along the other axis when that one is uncut, × 1.25, × 1.5, × 1.75 on attempts 1–3) placed `centre_tol_px` + 4 px inside that border; at most 3 attempts, stopping once the box is uncut. While the predicted box touches the border, target matching uses at least `acquire_dist_px` (a cut box's centre moves by up to half the hidden part as it comes into view). The height probe, the alignment, the width check and the pre-open use the frames of that pose. Look-down: after the probe, the `shift` phase moves the TCP in the base frame over the point where the ray of the median box centre meets the plane z = `table_z_m` + max(`grasp_height_m`, top), seen from the centring pose. The point under the TCP on that plane is taken as `grip_pixel_norm` (the table point under the jaws) plus the model's parallax between the table and that plane (the model's projections of the point under the TCP on the plane and on the table), so the grip-pixel calibration still corrects the model. This move is open loop (model intrinsics and lens position). Camera-down: no `shift` (the transition starts from the box centre's ray). Not possible when an axis is cut on both sides or the estimate does not fit the image: the grasp goes on centred on the cut box, as before. Status `border`: `shifted` (`border_shift_px` = aim − grip pixel, px) or `cut` (still cut after the attempts, or no aim possible; `align` / `pre_open` / `height_reason` then report `border`); absent when the box was not cut. Unit and orchestrator tests: `border_free_aim_moves_a_cut_axis_inside`, `tracker_widens_the_gate_for_a_box_at_the_border` (`cargo test --lib`), `border_cut_box_is_centred_uncut_then_shifted` (`cargo test --test test_grasp`: lens 4 cm off the tool axis, box under the jaws 223..424 px of 360; TCP 0.1 mm from the object after the shift; without it 1.96 mm, height probe and alignment skipped `border`). MuJoCo (`seed3_cube_cup` in `sim/mujoco/tests/test_camera_grasp.py`: v5 mount, 0.25 m approach, 4 cm cube turned 54°, ground-truth boxes): before, `border` / `align: skipped:border`, the jaws pushed the cube, `GRIPPER_TIMEOUT`; with the shift (2 border-free attempts), height 0.042 m from the probe, TCP 0.3 mm from the cube's start position, `done` / holding. The mid-height re-centre (`recentre`) does not apply this rule. Not run on the arm.
- **Descent contact logging.** Each poll of the final descent records `descend_peak_residual_nm` [J2, J3] (|residual torque|, absent without residuals) and `descend_peak_tracking_rad` (largest |commanded − measured| of J1..J6). With `descend_contact_stop_nm` set (default null = off; thresholds not calibrated), a J2 or J3 |residual| above it ends the descent at the measured position and the jaws close there: `descend_contact: true`, `descend_contact_height_m`.
- **Holding re-check after the lift.** Wait `post_lift_settle_ms`, then the `gripper_policy` holding rule on the measured J7 (gap from closed ≥ `holding_gap_rad` and median |J7 torque| over the window ≥ `holding_torque_nm`). When it fails, a re-grip (gripper `close` with grasp detection, same policy) decides: under position control the jaw settles on its hold target and the grip torque fades when the object only shifted or turned in the jaws (MuJoCo seed-3 cube: J7 torque 0.99 → 0.02 N·m during the lift, object still between both jaws). The re-grip stopping on the object keeps the grasp; closing fully is `failed` / `DROPPED`, `holding: false`, `gripper_gap_rad`; the arm stays at lift height and the gripper is not opened. Status `post_lift`: `held`, `regripped` or `dropped`.
- **Width check** (`TOO_WIDE`, 2026-11-13). Detections may carry `grasp_width_px`: the narrowest cross-section of the object's mask (the detector searches closing directions in 5° steps through the mask centroid, within an 8 px finger band). In the align phase the median width of the centring frames (any `angle_conf`: a disc or a square has a valid width without an angle) is laid across the box centre along the closing direction and both ends are mapped onto the same plane as the alignment; above `max_grasp_width_m` the grasp fails `TOO_WIDE` before the descent, the arm at its pose. Status `grasp_width_m`. A mask cut by the image border gives a width that is only a lower bound: the check then fails correctly when even that exceeds the limit and does nothing otherwise. MuJoCo (lens 45 mm off the tool axis, ground-truth masks): 4 cm cube 0.039–0.044 m, 5 cm cup 0.049 m, 3 cm block 0.031 m; the 10 cm slab, cut by the border, 0.082 m (`TOO_WIDE`). The default 0.075 m assumes the simulated 85 mm opening at `open_rad`; the real B601-DM opening is not measured.

- **边界截断的框**（`border`、`shift`，2026-11-13）：对中在夹爪抓取像素（相机朝下时为画面中心）收敛后，若该位姿下各帧目标框某一边的中位数距画面边界 2 px 以内，说明框被截断，框中心不是目标中心。此时在画面内的目标像素上再做一次对中：每个被截断的轴上，取估计完整尺寸（可见尺寸与另一轴未截断时该轴框尺寸中的较大者，第 1–3 次分别 × 1.25、× 1.5、× 1.75），放在距该边界 `centre_tol_px` + 4 px 处；最多 3 次，框不再截断即停止。预测框贴边时目标匹配门限至少取 `acquire_dist_px`（截断框进入画面时中心最多移动被遮部分的一半）。高度探测、对齐、宽度检查和预闭合使用该位姿的帧。俯视：探测后 `shift` 阶段在基座坐标系中把 TCP 移到框中心中位数射线与平面 z = `table_z_m` + max(`grasp_height_m`, 顶面高度) 交点的正上方（从对中位姿看）。TCP 在该平面上正下方点对应的像素取 `grip_pixel_norm`（夹爪下方的桌面点）加上模型在桌面与该平面之间的视差（模型对 TCP 正下方的平面点与桌面点的投影之差），因此抓取像素标定仍修正模型误差。这一步为开环（依赖模型内参与镜头位置）。相机朝下：不执行 `shift`（转换本就从框中心射线出发）。某轴两侧都被截断或估计尺寸放不进画面时无法处理，抓取按原流程以截断框对中继续。状态 `border`：`shifted`（`border_shift_px` = 目标像素 − 抓取像素，px）或 `cut`（多次尝试后仍截断或无可用目标像素；此时 `align` / `pre_open` / `height_reason` 报 `border`）；框未截断时不出现。单元与编排测试：`border_free_aim_moves_a_cut_axis_inside`、`tracker_widens_the_gate_for_a_box_at_the_border`（`cargo test --lib`），`border_cut_box_is_centred_uncut_then_shifted`（`cargo test --test test_grasp`：镜头距工具轴 4 cm，夹爪下方物体框在 360 px 高的画面中占 223..424 px；shift 后 TCP 距物体 0.1 mm；不做 shift 为 1.96 mm，高度探测与对齐因 `border` 跳过）。MuJoCo（`sim/mujoco/tests/test_camera_grasp.py` 的 `seed3_cube_cup`：v5 支架，接近高度 0.25 m，4 cm 立方体斜放 54°，真值检测框）：修改前为 `border` / `align: skipped:border`，夹爪推动立方体，`GRIPPER_TIMEOUT`；加入 shift 后（2 次边界内目标像素尝试）探测高度 0.042 m，TCP 距立方体初始位置 0.3 mm，`done` 且夹持。中途再对中（`recentre`）不使用此规则。未在真机上运行。
- **下降接触记录**：最后一段下降每次轮询记录 `descend_peak_residual_nm` [J2, J3]（残差力矩绝对值峰值，无残差时缺省）和 `descend_peak_tracking_rad`（J1..J6 |指令 − 实测| 最大值）。设置 `descend_contact_stop_nm`（默认 null 即关闭；阈值未标定）后，J2 或 J3 残差绝对值超过该值即在实测位置结束下降并在该处闭合：`descend_contact: true`、`descend_contact_height_m`。
- **抬起后夹持复查**：等待 `post_lift_settle_ms` 后按 `gripper_policy` 的夹持规则用实测 J7 再判一次（距闭合位置的间隙 ≥ `holding_gap_rad` 且窗口内 |J7 力矩| 中位数 ≥ `holding_torque_nm`）。判定失败时以一次重新夹紧（带夹持检测的 `close`，同一策略）决定：位置控制下物体只是在夹爪中移动或转动时，夹爪停在保持目标上，夹持力矩衰减（MuJoCo seed 3 立方体：抬起过程中 J7 力矩 0.99 → 0.02 N·m，物体仍在两侧夹爪之间）。重新夹紧停在物体上则保持抓取；夹到闭合为 `failed` / `DROPPED`，`holding: false`，给出 `gripper_gap_rad`；机械臂停在抬起高度，夹爪不张开。状态 `post_lift`：`held`、`regripped` 或 `dropped`。
- **宽度检查**（`TOO_WIDE`，2026-11-13）：检测结果可带 `grasp_width_px`，即物体 mask 最窄的截面宽度（检测端以 5° 步长、过 mask 质心、在 8 px 指宽带内搜索闭合方向）。对齐阶段取对中帧宽度的中位数（不限 `angle_conf`：圆盘或正方形没有角度，但宽度有效），以框中心为中点沿闭合方向展开，两端映射到与对齐相同的平面；超过 `max_grasp_width_m` 时在下降前失败 `TOO_WIDE`，机械臂停在当前位姿。状态字段 `grasp_width_m`。mask 被画面边界截断时宽度只是下限：下限已超限时判定正确，未超限时检查不起作用。MuJoCo（镜头距工具轴 45 mm，真值 mask）：4 cm 立方体 0.039–0.044 m，5 cm 杯子 0.049 m，3 cm 方块 0.031 m；10 cm 扁平方块被画面边界截断，测得 0.082 m（`TOO_WIDE`）。默认 0.075 m 按仿真中 `open_rad` 处 85 mm 开口设定，真机 B601-DM 开口未实测。
- **Width-based pre-open / 基于宽度的预闭合** (`preopen`, 2026-11-13): closes the jaws to `width + pre_open_margin_m` before descending, so the jaws close across the object from just outside it rather than from full open (`open_rad`). `pre_open` setting: `auto` (default, only when `gripper_policy.jaw_opening` is calibrated), `on` (also uncalibrated, using the built-in sim model), `off`. Skipped (`skipped:<reason>`) when at or beyond `open_rad` (`open_rad`), no width was measured (`no_width`), or the alignment guard fails with `border` or `occluded` (the width is only a lower bound and a too-narrow pre-open could hit the object). Pre-open is allowed without an accepted detector angle (disc/square: width measured along the closing direction). No pre-open on the post-lift re-grip. When calibrated, `TOO_WIDE` limit becomes `min(max_grasp_width_m, opening_m(open_rad) - pre_open_margin_m)`. Status fields: `pre_open` (`done`, `off`, `skipped:<reason>`), `pre_open_m`, `held_width_m` (`opening_m` of measured J7 after close).
在下降前先将夹爪收拢至 `width + pre_open_margin_m`，避免从全开（`open_rad`）直接下冲并在目标旁大行程闭合。`pre_open` 设置：`auto`（默认，仅当 `gripper_policy.jaw_opening` 已标定时启用）、`on`（未标定时也启用，使用内置仿真模型）、`off`。跳过原因（`skipped:<reason>`）：目标宽度加余量已达或超过全开开度（`open_rad`）、未测得宽度（`no_width`）、或对齐保护判定为边界截断/遮挡（`border` / `occluded`，此时测得宽度仅为下限，过窄预闭合会碰撞物体）。目标无有效角度时仍允许预闭合（圆盘/正方形沿实际闭合方向测量）。抬起后的重新夹紧不进行预闭合。标定状态下 `TOO_WIDE` 门限自动与物理开度对齐：`min(max_grasp_width_m, opening_m(open_rad) - pre_open_margin_m)`。状态字段：`pre_open`（`done`、`off`、`skipped:<reason>`）、`pre_open_m`、`held_width_m`（闭合后实测 J7 对应的物理开度）。

### Grasp setup / 抓取设置

`ArmConfig.grasp` holds the defaults; the runtime setup is read with `GET /api/v1/grasp/setup` (`{"supported":bool, "setup":{...}, "path":str|null, "revision":int, "camera_down":bool|null}`; `camera_down` is whether a grasp on the current mount acquires camera-down (`acquire_camera_down`, then `grip_pixel_norm` is not the centring aim), null with `camera_down_error` when `acquire_camera_down: "on"` lacks `camera_mount.offset_m`) and changed with the WS command `/api/v1/grasp/setup` (body = fields to change; unknown fields, non-finite or out-of-range values → `INVALID_COMMAND`). `{"table_z_from_tcp": true}` sets `table_z_m` to the current commanded end_link height (jog the jaw tips onto the table first). The ack carries the new `setup` and `persisted: true|false` (`persist_error` on failure). Every field can also be overridden for one grasp with `overrides`.

Persistence: `ARMD_GRASP_SETUP` (default `/userdata/rebot-teleop/grasp_setup.json`), written atomically (temp file + rename, directory created). At startup a missing file keeps the defaults; an unreadable, malformed or invalid file is logged and ignored (defaults kept, file untouched); a partial file overrides only its fields.

`camera_tilt_deg` is `camera_mount.tilt_deg`: setting it changes the mount used by camera-frame moves and published in the schema. A change of `camera_tilt_deg` while a trajectory, macro action, servo stream or park runs is `409 MOTION_BUSY` (the camera point is part of the workspace check); other fields can change at any time. For the default mount (`flip:false`) a negative tilt turns the optical axis toward the jaws (image down).

设置默认值来自 `ArmConfig.grasp`；运行时用 `GET /api/v1/grasp/setup` 读取（`camera_down` 表示当前安装下抓取是否用相机朝下对准，此时 `grip_pixel_norm` 不作为对准点；`acquire_camera_down: "on"` 缺少 `camera_mount.offset_m` 时为 null 并附 `camera_down_error`），用 WS 指令 `/api/v1/grasp/setup` 修改（`table_z_from_tcp: true` 以当前夹爪尖高度作为桌面高度），保存到 `ARMD_GRASP_SETUP`（默认 `/userdata/rebot-teleop/grasp_setup.json`）。文件缺失用默认值；文件损坏或数值无效时记日志并忽略。`camera_tilt_deg` 即 `camera_mount.tilt_deg`；轨迹、宏动作、servo 流或收纳进行中修改 `camera_tilt_deg` 返回 `409 MOTION_BUSY`（相机点属于工作空间检查），其他字段随时可改；默认安装（`flip:false`）下负值表示光轴朝夹爪方向（画面下方）倾斜。

### Grasp tasks / 抓取任务

A grasp task is a named, stored set of setup overrides plus the perception it needs. `tasks` in the setup maps a name (1..32 characters of `a-z`, `0-9`, `_`, `-`) to `{"overrides": {...}, "requires": {...}, "description": "..."}` (all optional; `description` at most 200 bytes). A grasp request (and its dry run) selects one with `"task": "<name>"`; its setup is the setup, then the task's `overrides`, then the request's `overrides` (the request wins). Example (not in the kit profile, which has no tasks):

```json
"tasks": {
  "cup":  {"description": "upright cup, mask yaw",
           "requires": {"model_kind": "segment"},
           "overrides": {"yaw_sources": ["mask"], "height_priors": {"cup": 0.095}, "height_sources": ["probe", "prior"]}},
  "flat": {"description": "thin part, depth height",
           "requires": {"depth": "metric"},
           "overrides": {"height_sources": ["depth", "probe"], "yaw_sources": ["mask", "depth", "box"]}},
  "box":  {"description": "box, detection model and depth",
           "requires": {"model_kind": "detect", "depth": "metric"},
           "models": {"detector": "yolo11n_detection_cv181x_int8", "depth": "zipdepth_metric_384x224_bf16_rgb"}}
}
```

- Stored: `tasks` is set through the setup (WS `/api/v1/grasp/setup` or the setup file) and replaces the whole map; `{"tasks": {}}` deletes all tasks. Each task's overrides must name setup fields (not `tasks`) and give a valid setup on top of the setup without tasks. A setup change or setup file that makes any stored task invalid is rejected as a whole (`INVALID_COMMAND` naming the task; a file is ignored). `GET /api/v1/grasp/setup` always reports `tasks`.
- Request: an unknown task, a non-string `task`, `tasks` in the request's `overrides`, or overrides that make the task's setup invalid → `INVALID_COMMAND`.
- `requires.model_kind`: `detect`, `segment` or `obb`, compared exactly with the provider's `model.kind` (segment models give the mask angle and width; obb models give the oriented box angle, width and corners). `requires.depth`: `any` (`available.depth`) or `metric` (also `depth_model.metric`). A task without `requires` triggers no check. The check reads `GET /api/mode` once; the grasp reuses that reading, so a grasp reads `/api/mode` once with or without a task (dry run: once with a task that has requirements, never otherwise). Mismatch → command rejected with `TASK_UNSUPPORTED` (422), e.g. `task cup needs model_kind segment, provider has detect`; an older provider without `/api/mode` (404) → `... provider does not report model.kind` / `... depth`; a provider whose detector slot is empty (`available.yolo` false) → `... provider has no detector loaded` (rebot-vision 1.3.10 and earlier report `model.kind` `detect` with the slot empty, so armd reads `available.yolo` first). A provider that cannot be reached is not a task failure: the grasp starts and fails as without a task (`DETECTION_UNAVAILABLE`).
- `models` (optional): the provider's model slots the task needs, `{"detector"?: name|null, "depth"?: name|null}` with names from the provider's catalogue (`GET /api/v1/vision/mode` `models.catalogue`, [Model switching](detection_api.md#model-switching--模型切换)); per slot absent = keep, `null` = unload, a name = load; at least one slot, names 1..64 bytes. armd does not know the catalogue when the task is stored, so an unknown name is refused by the provider at grasp time. A task with only `models` is processed (switch) without `requires`.
- Switch (before the ack): when the provider's `models.resident` differs from the task's slots, armd sends `POST /api/models` with the slots the task names, then polls `GET /api/mode` until `models.generation` reaches the returned generation and `models.swap.state` is `idle` or `failed` (at most 5 s), and checks `requires` on that reading (the grasp reuses it). One model-changing preflight runs at a time. The switch time is part of the grasp's start latency. Refusals → `TASK_UNSUPPORTED` (422), no action: `task <t>: model switch refused: ION_BUDGET (need 69.5 MB, limit 62.9 MB)`, `... model switch refused: <provider error>` (unknown name, wrong slot), `... model switch busy` (`SWAP_BUSY`), `... model switch failed: LOAD_FAILED:<slot>` (the provider's load failed), `... provider cannot switch models` (no `/api/models`, 404). A provider that is unreachable, answers 5xx or does not finish within 5 s is not a task failure: the grasp starts and fails with `DETECTION_UNAVAILABLE`, as other provider errors.
- Allowed combinations with rebot-vision's default budget (base 21.5 MB, reserve 8 MB, total 62.9 MB; measured ion_mb: detect 8.5, segment 19.5, obb 8.0, depth 20.5): detect + depth, obb + depth, any YOLO model alone, depth alone. segment + depth is accepted by armd's task validation and refused by the provider (`ION_BUDGET`).
- Generation pin (every grasp, when the provider reports `models`): the grasp keeps the `models.generation` it started with; a detection frame whose `model_generation` differs (another client switched models during the grasp) fails the grasp with `DETECTION_UNAVAILABLE` `model changed during grasp`.
- No switch back after the grasp: the provider keeps the last set (`models.resident` in `/api/v1/vision/mode`). Without `models` armd does not load or switch models: the user loads the model the task needs (rebot-vision `vision.json`).
- Clients detect the feature with `capabilities.grasp_tasks`.

抓取任务是按名称保存的一组设置覆盖项及其所需的感知能力。设置中的 `tasks` 把名称（1..32 个 `a-z`、`0-9`、`_`、`-` 字符）映射到 `{"overrides": {...}, "requires": {...}, "description": "..."}`（均可选；`description` 最多 200 字节）。抓取请求（及其 dry run）用 `"task": "<名称>"` 选择任务，生效设置依次为：设置、任务的 `overrides`、请求的 `overrides`（请求优先）。`tasks` 只能通过设置（WS `/api/v1/grasp/setup` 或设置文件）整体替换，`{"tasks": {}}` 删除全部任务；每个任务的覆盖项只能是设置字段（不能含 `tasks`），并且叠加到不含任务的设置上必须有效。使任何已存任务失效的设置修改或设置文件整体被拒绝（`INVALID_COMMAND`，消息含任务名；文件被忽略）。请求中任务不存在、`task` 不是字符串、请求 `overrides` 含 `tasks`、或覆盖后设置无效，均返回 `INVALID_COMMAND`。`requires.model_kind` 为 `detect`、`segment` 或 `obb`，与提供端 `model.kind` 精确比较（segment 模型给出掩码角度与宽度，obb 模型给出旋转框角度、宽度与角点）；`requires.depth` 为 `any`（`available.depth`）或 `metric`（另需 `depth_model.metric`）。没有 `requires` 的任务不做检查。检查读取一次 `GET /api/mode`，抓取复用这次读取，因此有无任务每次抓取都只读一次 `/api/mode`（dry run 仅在任务有要求时读一次）。不满足时指令以 `TASK_UNSUPPORTED`（422）拒绝，不启动动作；没有 `/api/mode`（404）的旧提供端返回 `... provider does not report model.kind` / `... depth`；检测模型槽位为空（`available.yolo` 为 false）的提供端返回 `... provider has no detector loaded`（1.3.10 及更早的 rebot-vision 在槽位为空时仍报告 `model.kind` 为 `detect`，因此 armd 先读 `available.yolo`）。提供端无法连接不算任务失败：抓取照常开始并像无任务时一样失败（`DETECTION_UNAVAILABLE`）。

`models`（可选）：任务所需的提供端模型槽位，`{"detector"?: 名称|null, "depth"?: 名称|null}`，名称取自提供端目录（`GET /api/v1/vision/mode` 的 `models.catalogue`，见[模型切换](detection_api.md#model-switching--模型切换)）；每个槽位缺省 = 保持，`null` = 卸载，名称 = 加载；至少一个槽位，名称 1..64 字节。保存任务时 armd 不知道目录，未知名称在抓取时由提供端拒绝。只有 `models` 的任务也会处理（切换），无需 `requires`。切换（应答之前）：提供端 `models.resident` 与任务槽位不同时，armd 以任务给出的槽位发送 `POST /api/models`，再轮询 `GET /api/mode`，直到 `models.generation` 达到返回的代号且 `models.swap.state` 为 `idle` 或 `failed`（最多 5 秒），然后用这次读取检查 `requires`（抓取复用该读取）。同一时刻只运行一个改动模型的预检。切换耗时计入抓取的启动延迟。拒绝 → `TASK_UNSUPPORTED`（422），不启动动作：`task <t>: model switch refused: ION_BUDGET (need 69.5 MB, limit 62.9 MB)`、`... model switch refused: <提供端错误>`（未知名称、槽位不符）、`... model switch busy`（`SWAP_BUSY`）、`... model switch failed: LOAD_FAILED:<槽位>`（提供端加载失败）、`... provider cannot switch models`（无 `/api/models`，404）。提供端不可达、返回 5xx 或 5 秒内未完成不算任务失败：抓取照常开始并以 `DETECTION_UNAVAILABLE` 失败，与其他提供端错误一致。rebot-vision 默认预算（基础 21.5 MB、预留 8 MB、总量 62.9 MB；实测 ion_mb：detect 8.5、segment 19.5、obb 8.0、depth 20.5）下允许的组合：detect + depth、obb + depth、单个 YOLO 模型、单独 depth。segment + depth 能通过 armd 的任务校验，但会被提供端拒绝（`ION_BUDGET`）。代号固定（提供端报告 `models` 时的每次抓取）：抓取记录开始时的 `models.generation`，若检测帧的 `model_generation` 不同（抓取期间其他客户端切换了模型），抓取以 `DETECTION_UNAVAILABLE` `model changed during grasp` 失败。抓取结束后不切回：提供端保持最后一组模型（`/api/v1/vision/mode` 的 `models.resident`）。没有 `models` 时 armd 不加载或切换模型，任务所需的模型由用户在 rebot-vision `vision.json` 中加载。客户端用 `capabilities.grasp_tasks` 判断是否支持。

Tests: `cargo test --lib -- task_registry grasp_request_applies mode_info_parse task_models`, `cargo test --test test_grasp -- task dry_run_reports dry_run_task_models a_frame_from_another capabilities_advertise`, `cargo test --test test_detection_proxy -- mode_once`, MuJoCo `task_requires_depth_unsupported` / `task_depth_decides` / `task_swap_det` / `task_seg_depth_budget`.

### Depth measurement / 深度测量

`POST /api/v1/grasp/measure` and the WS command of the same path measure with depth at the current pose: no lease, no motion, nothing written. Body `{"label"?: str, "min_score"?: number (0..1, default 0.3), "pipelines"?: ["yolo", "depth"] (default) | ["depth"]}`; other fields → `INVALID_COMMAND`. Over WS the command needs a strictly increasing `request_id` (no `generation`, `epoch_id`); the reply is a `command_ack` carrying the fields below, or a `command_reject` with `code`. Capability `grasp_measure` (same value as `grasp`; absent = false in older armd).

- Refused with `ARM_MOVING` (409) when a trajectory or servo stream runs or a joint J1..J6 moves faster than 0.02 rad/s (measured), before the trigger; and when the commanded positions change by more than 1e-3 rad while the frame is captured. `UNSUPPORTED` (422): no grasp setup, or a provider without per-request pipelines. `DETECTION_UNAVAILABLE` (503 / 504): the trigger failed or returned no frame.
- One trigger (`POST /api/trigger` of the provider) with the request's pipelines; `["depth"]` alone leaves the YOLO boxes out, so the table samples cover the whole frame (8..92 %).
- The camera model and the pose are the grasp's: `CamModel::assumed` (grasp setup intrinsics, live camera mount; pinhole, the stored k1 / k2 are not applied) at the FK pose of the commanded positions. The table fit is `calibrate_depth_why` and each detection's measurement `measure_detection_depth_with_cal_why`, the functions the grasp's depth height source calls on the overhead frame (here without a start-frame prior, so no `two_height_fk`).
- Reply: `frame_id`, `age_ms`, `image_size_px`, `pipelines`; `camera` `{pose_source: "commanded", commanded_rad, measured_rad, tcp {xyz_m, quat_wxyz}, origin_m, quat_wxyz (R_base_cam), fx, fy, cx, cy, size, lens_known}`; `calibration` `{calibrated, solved_at, stale, intrinsics (as stored in calibration.json), intrinsics_hash (FNV-1a 64 of their JSON), camera_mount, grasp (fx_px .. grip_pixel_norm), table_z_m, kinematics_corrected, kinematics_level (calibration.json kinematics.fit.level), calibration_revision, distortion_modelled: false}`; `table_fit` `{ok, source (metric_table | oblique_ransac), a, b (1/z = a·disp + b) or why, metric_model, n_samples (in the frame), n_valid (positive disparity, ray meets the table at 0.08..2.5 m), inv_z_span, residual {n, inliers (≤ 8 % depth error), rms_mm, median_abs_mm, max_abs_mm} (z_pred − z_fk per valid sample), least_squares {a, b, r2_inv_z, residual} (plain least squares, a diagnostic)}`; `detections` (score ≥ `min_score`, label case-insensitive) `[{label, score, box_norm, disp_fg, disp_bg, depth_conf, angle_deg, angle_conf, grasp_width_px, length_px, jaw_clear, depth_angle_deg, depth_angle_conf, depth_width_px, measurement {height_m, depth_m, width_m, length_m, source, jaw_clear} | null, why}]`. `why` is the grasp's reject reason: the fit's (`no_depth_frame`, `too_few_samples`, `table_contradicts_fk`, `no_oblique_spread`), the measurement's (`low_conf`, `no_disparity`, `bad_disparity`, `too_flat`) or `no_lens_centre` (`camera_mount.offset_m` unset: the grasp does not use depth then).
- SDK: `rebot.Arm` has no call for it yet; it would need `measure_depth(label=None, min_score=0.3, pipelines=("yolo", "depth"))` sending the WS command without the lease check and returning the reply (a `DepthMeasure` with `table_fit`, `calibration`, `detections`), `ARM_MOVING` mapped to an `ActionFailed`-like error, and the capability check `grasp_measure`.

Tests: `cargo test --lib depth_measure`, `cargo test --test test_grasp -- measure_ capabilities_advertise_grasp_measure`.

`POST /api/v1/grasp/measure` 与同路径的 WS 指令在当前姿态做一次深度测量：无需租约，不运动，不写入任何数据。请求体 `{"label"?: 字符串, "min_score"?: 数值（0..1，默认 0.3）, "pipelines"?: ["yolo", "depth"]（默认）| ["depth"]}`，其他字段返回 `INVALID_COMMAND`。WS 指令需要严格递增的 `request_id`（不需要 `generation`、`epoch_id`）；回复为携带下列字段的 `command_ack`，或带 `code` 的 `command_reject`。能力 `grasp_measure`（与 `grasp` 同值；旧版 armd 缺省为 false）。

- 触发前若有轨迹或伺服流在运行，或 J1..J6 任一关节实测速度超过 0.02 rad/s，返回 `ARM_MOVING`（409）；采帧期间指令位置变化超过 1e-3 rad 同样返回 `ARM_MOVING`。`UNSUPPORTED`（422）：没有抓取设置，或提供端不支持按请求指定流水线。`DETECTION_UNAVAILABLE`（503 / 504）：触发失败或没有返回帧。
- 用请求的流水线触发一次（提供端 `POST /api/trigger`）；只用 `["depth"]` 时没有 YOLO 框，桌面采样覆盖整帧（8..92 %）。
- 相机模型与位姿与抓取相同：`CamModel::assumed`（抓取设置的内参、当前相机安装；针孔模型，不使用已存的 k1 / k2），位姿为指令位置的 FK。桌面拟合为 `calibrate_depth_why`，每个检测的测量为 `measure_detection_depth_with_cal_why`，即抓取的深度高度来源在俯视帧上调用的函数（此处没有起始帧先验，因此不会出现 `two_height_fk`）。
- 回复：`frame_id`、`age_ms`、`image_size_px`、`pipelines`；`camera` `{pose_source: "commanded", commanded_rad, measured_rad, tcp {xyz_m, quat_wxyz}, origin_m, quat_wxyz（R_base_cam）, fx, fy, cx, cy, size, lens_known}`；`calibration` `{calibrated, solved_at, stale, intrinsics（calibration.json 中保存的值）, intrinsics_hash（其 JSON 的 FNV-1a 64）, camera_mount, grasp（fx_px .. grip_pixel_norm）, table_z_m, kinematics_corrected, kinematics_level（calibration.json kinematics.fit.level）, calibration_revision, distortion_modelled: false}`；`table_fit` `{ok, source（metric_table | oblique_ransac）, a, b（1/z = a·disp + b）或 why, metric_model, n_samples（帧中数量）, n_valid（视差为正且射线在 0.08..2.5 m 处与桌面相交）, inv_z_span, residual {n, inliers（深度误差 ≤ 8 %）, rms_mm, median_abs_mm, max_abs_mm}（每个有效采样的 z_pred − z_fk）, least_squares {a, b, r2_inv_z, residual}（普通最小二乘，仅供诊断）}`；`detections`（得分 ≥ `min_score`，标签不区分大小写）`[{label, score, box_norm, disp_fg, disp_bg, depth_conf, angle_deg, angle_conf, grasp_width_px, length_px, jaw_clear, depth_angle_deg, depth_angle_conf, depth_width_px, measurement {height_m, depth_m, width_m, length_m, source, jaw_clear} | null, why}]`。`why` 为抓取的拒绝原因：拟合的（`no_depth_frame`、`too_few_samples`、`table_contradicts_fk`、`no_oblique_spread`）、测量的（`low_conf`、`no_disparity`、`bad_disparity`、`too_flat`），或 `no_lens_centre`（未设置 `camera_mount.offset_m`，此时抓取不使用深度）。
- SDK：`rebot.Arm` 尚无对应调用；需要新增 `measure_depth(label=None, min_score=0.3, pipelines=("yolo", "depth"))`，不经租约检查发送该 WS 指令并返回回复（含 `table_fit`、`calibration`、`detections` 的 `DepthMeasure`），把 `ARM_MOVING` 映射为类似 `ActionFailed` 的错误，并检查能力 `grasp_measure`。

### Multi-view measurement / 多视角测量

WS action `/api/v1/action/measure_multiview` (lease, epoch, `request_id`; operator session when armd enforces the PIN, it moves the arm and triggers the camera; REST `POST` → `OPERATOR_REQUIRED` / `LEASE_REQUIRED`). Capability `measure_multiview` (same value as `grasp`; absent = false in older armd). `GET /api/v1/safety/describe` lists it under `limits.measure_multiview` (`speed_scale`, `baseline_m`, `views`, `motions`, `default_motion`, `axes`, `min_frame_margin_px`, `min_settle_s`, `max_settle_s`, `still`, `snapshot_bracket_rad`, `snapshot_tries`, `debug_dir`, `ends_on`, `return_after`).

- Body `{"label"?: str, "min_score"?: 0..1 (default 0.3), "target"?: {"box_norm": [x0, y0, x1, y1], "frame_id"?: int}, "motion"?: "orbit" (default) | "translate", "axes"?: "x" | "xy" (default "x" for orbit, "xy" for translate), "views"?: int (axes "x": 2..5, default 3; "xy": 3..5, default 5), "baseline_m"?: 0.03..0.12 (default 0.08), "speed_scale"?: 0.1..0.5 (default 0.3), "return_to_start"?: bool (default true), "debug"?: bool (default false; see Debug bundle)}`; other fields or values out of range → `INVALID_COMMAND`. `target` picks the start detection with the largest IoU (≥ 0.3) with `box_norm`; without it the best-scoring detection with the label. `frame_id` is accepted and not used. The default `motion` stays `orbit` until the two motions are compared on the real arm.
- Start: the camera sees the object at the current pose; torque on (else `NOT_ARMED`) and a grasp setup with the camera intrinsics (else the command is rejected with `UNSUPPORTED`); a provider without per-request pipelines ends the action with `UNSUPPORTED`.
- View offsets, in the image plane of the start camera: `axes` "x" spreads them evenly over [−`baseline_m`/2, +`baseline_m`/2] on the image x axis (3 views: −B/2, 0 = the start pose, +B/2); "xy" uses the start pose and `views` − 1 offsets on the circle of radius `baseline_m`/2 (5 views: +x, +y, −x, −y; 4 views: 0°, 120°, 240°), so that edges of every direction cross an epipolar line. Visit order: the start view, then on "x" the negative side outward and the positive side outward, on "xy" by angle.
- `motion` "orbit": the start pose turned about the look-at point X (ray through the target box centre at 0.02 m above `table_z_m`) so that the camera centre moves by the chord |offset| in the offset's direction; X keeps its pixel and the camera its distance to X. "translate": the camera keeps its orientation and moves by the offset parallel to the image plane; the object shifts in the image by about fx · |offset| / Z (B/2 = 0.04 m at Z = 0.35 m: 92 px at fx 804, 69 px at fx 600). Before each move armd predicts that shift (projection of X in the planned view) and refuses the view with `OUT_OF_FRAME` when the start box moved by it would come within 8 px of the image border; each view reports `predicted_shift_px` and `frame_margin_px`. In the simulated test (fx 600, Z ≈ 0.33 m, 50 x 30 x 40 mm box) translate shifted X by 72 px and left 26–98 px of margin.
- Motion: IK of each view pose, then the joint-space quintic of `path: "joint"` at `speed_scale` (≤ 0.5) with the checks of every joint move (swept workspace, keep-out boxes, link capsules, power budget, torque and collision holds). A view refused before it moves (`IK_UNREACHABLE`, `IK_BRANCH_FLIP`, `WORKSPACE_VIOLATION`, `SOFT_LIMIT_EXCEEDED`, `OUT_OF_FRAME`) is retried at the mirrored offset (when no view uses it), then at 0.75 and 0.5 of the offset on either side; each retry is listed in `measurement.fallbacks` `{offset_m: [x, y], used_offset_m: [x, y], code}`. When all are refused, or the two farthest views end up less than 0.02 m apart, the action fails with the refusal code.
- Capture per view: after the motion settled, 1.0 s, then the settle rule: a window of 10 joint samples 20 ms apart is still when, for every arm joint, the median |velocity| is ≤ 0.03 rad/s and the position range ≤ 3 mrad; windows slide until 4 s after the motion, then `NOT_SETTLED`. Then 2 snapshots discarded (150 ms apart) and one snapshot (`GET /snapshot.jpg` on the detector host, port 8001 or `ARMD_SNAPSHOT_PORT`; the 640x640 letterbox is cropped to the 640x360 frame before any processing; zune-jpeg has no region or reduced-scale decode, so armd decodes the full luma) bracketed by joint samples taken 100 ms before the request and after the reply. The view's pose is the FK of the bracket's mean joints (kinematic correction included). When an arm joint differs by more than 2 mrad across the bracket, the snapshot is retried 0.5 s later, at most 3 times, then `MOVED` (the message lists the spread of each try). Then one YOLO trigger (a frame newer than the request) for the target box. A view where the target (same label, centre within 0.2 of where the start view saw it, moved by the shift of X in that view) is not detected → `TARGET_LOST`. Real B601-DM (2026-11-22, speed_scale 0.3): after a joint move the joints creep 2–4 mrad over seconds and J4 / J5 can hold a limit cycle of a few mrad, with single |velocity| samples up to 0.037 rad/s; the earlier rule (one |velocity| sample ≤ 0.02 rad/s, every joint within 3 mrad of the settle sample through the whole capture, FK of the settle sample) ended 4 of 6 runs with `MOVED`. A 3.5 mrad error on J4 moves the image by 4.5 px at Z 0.45 m (fx 804), 14 mm of depth at baseline 0.08 m (J1 3.0, J2 2.7, J3 4.3, J5 4.0 px; `cargo test --lib joint_errors_in_pixels -- --nocapture`), so the pose is taken at the snapshot.
- Features (crates/mview-stereo), in the reference view (the view closest to the start pose; its detection box grown by 25 % + 12 px per side):
  - Shi-Tomasi corners: at most 200 in the box and 60 outside it, strongest first, 5 px apart.
  - Edge points for objects without texture: gradient maxima across the edge (≥ 6 grey levels per px and ≥ 10 % of the region's largest) in the box grown by 25 %, 4 px apart and 3 px from the corners. Edges with a uniform side (7x7 standard deviation below 5 grey levels 5 px across: the outline of a plain face) come first, up to 120; edges textured on both sides up to 40 less a fifth of the corners in the box. An outline edge (one side uniform, the other textured) uses a one-sided patch: the pixels on the textured side, which changes with the background, get no weight.
- Matching: a feature in the box is swept from 0.02 m below to 0.25 m above `table_z_m`, one outside the box (table) to 0.01 m above it. A corner is matched in every other view; an edge point only in the views whose epipolar line crosses the edge at more than 30° (a line along the edge does not locate it). Of those, the 2 views farthest apart are swept:
  - coarse: inverse depth on the 2x downsampled images, 5x5 patches, a depth sample per 1.5 px of image motion, mean NCC ≥ 0.6 and the ratio `(1 − best) ≤ 0.7 (1 − second)` against the best separate peak;
  - fine: 9x9 patches at full resolution (bilinear), parabola. Edge patches are weighted by each pixel's gradient across the edge (+ 5 % of the largest).
  Every matched view then refines the match at full resolution: a corner in 2D, an edge point along that view's epipolar direction only; NCC ≥ 0.8. The 2 swept views pass a left-right check (their patch swept back along their own ray lands within 2 px of the feature). Least-squares midpoint triangulation over all matched views; points with a reprojection error above 2 px in any view are dropped.
- Edge points and silhouettes: the outline of a curved object is view dependent (the contour moves over the surface as the camera moves). An edge point sets the top height only when at least two other views matched it and the points triangulated from the reference with each of them agree within max(4 mm, the depth of 3 px of disparity at the shorter baseline). Edge points that fail it still count for the footprint, not for `top_z_m`. A box's outline consists of real edges and passes; a curved silhouette is not tested synthetically.
- Object and table: points more than 5 mm above `table_z_m` whose reference pixel lies in the detection box are object points, less isolated ones (farther than max(3 × the median, 4 mm) from their 3rd-nearest object point); at least 8, of which at least 4 corners or consistent edge points, else `TOO_FEW_POINTS`. Points from 50 mm below to 5 mm above the plane are table points. `top_z_m` = p90 of the heights of the corners and consistent edge points after a local median (median of the 9 nearest in x, y); `width_m` / `length_m` / `yaw_deg` from the 2nd to 98th percentile extent of all object points along their principal axes in x, y (yaw of the long side from base x, [−90, 90)); `centroid_m` = centre of that extent, z = (`top_z_m` + `table_z_m`) / 2.
- Compute: off the supervisor lock and the control tick (`spawn_blocking`), while the arm returns to the start joints. `return_to_start` (default true) is the same joint-space move back to the start joints; once the arm moved it also runs after `TARGET_LOST`, `TOO_FEW_POINTS`, `DETECTION_UNAVAILABLE`, `UNSUPPORTED` and a refused later view, not after any other failure (stop, E-stop, fault, collision, torque limit, `NOT_SETTLED`, `MOVED`, lease loss, watchdog: those end the action where the arm is).
- Result in the action record: `measurement` `{"method": "motion_stereo", "motion", "axes", "objects": [{label, score, centroid_m: [x, y, z], top_z_m, height_m, width_m, length_m, yaw_deg, n_points, n_edge_points, n_top_points, reproj_rms_px, views_used}], "table_check": {n_points, median_abs_mm, p90_abs_mm, median_mm}, "views": [{tcp: {xyz_m, quat_wxyz}, frame_id, offset_m: [x, y], predicted_shift_px: [x, y], frame_margin_px, decode_ms, joints_rad, bracket_rad, snapshot_tries_mrad, settle_s}], "in_box": {n, n_above, min_mm, median_mm, max_mm} (triangulated points in the target box and their height above the table; n_above: more than 5 mm), "outcomes": {corner_box | corner_out | edge_box | edge_out: {point | no_peak | flat | ambiguous | edge_no_view | refine | left_right | reprojection: count}}, "debug"?: {dir, written, error?}, "why": null | "too_few_points", "table_z_m", "baseline_m" (largest distance between two captured offsets), "fallbacks", "stats" {features, corners, edges, edge_no_view, no_peak, ambiguous, refine_rejected, lr_rejected, reproj_rejected, points, edge_points, edge_consistent, pyramid_ms, features_ms, sweep_ms (left-right back sweeps included), refine_ms, triangulate_ms, total_ms, decode_ms (all views)}, "compute_ms"}`. Base frame, metres. `views[].offset_m` was a number (the x offset) before `motion` / `axes` existed. `height_m` = `top_z_m` − `table_z_m`. `table_check` compares the triangulated table points with the calibrated table plane: `median_mm` (signed) is a bias common to the views (camera, hand-eye or kinematic calibration); `height_m` − `median_mm` / 1000 is the height above the triangulated table. With `TOO_FEW_POINTS` the record carries the measurement with `objects: []` and `why`. `TOO_FEW_POINTS` names the in-box count and its height distribution in the message, so a calibration offset (points just below the 5 mm cut) shows apart from a matching failure (few points at all).
- Accuracy: depends only on the camera intrinsics, the hand-eye mount and the kinematic calibration (and on texture or visible edges); no depth model and no depth calibration are used. Lens distortion is not modelled. Synthetic tests (`tests/test_mview_stereo.rs`; rendered table and a 50 x 30 mm box, baseline 0.08 m, distance 0.35 m, fx 804, intensity noise σ 2 grey levels):
  - textured box on a textured table, orbit x3, Gaussian noise of 1 px per axis on every matched pixel: height error ≤ 1.07 mm over 20 / 40 / 80 mm (9 runs; ≤ 1.08 mm before the coarse-to-fine sweep). With a systematic 1 px shift of each view instead (a pose / calibration error) the error reaches +2.39 mm and `table_check.median_mm` shows the same bias (height relative to the triangulated table within 1.45 mm). Width and length come out 1–6 mm short (features keep a patch radius from the outline);
  - plain (uniform grey, faces shaded 0.85 / 0.92 / 1.0) box on a textured table: measured in all 9 cases without pixel noise (error ≤ 0.20 mm, 10–31 object points; orbit x3 gives the fewest, 10–16) and with 1 px noise (error ≤ 1.56 mm, 8–27 points; orbit x3 at the 8-point minimum for 20 mm);
  - plain box on a plain table (outline edges and the box's own corners only): measured in all 9 cases (error ≤ 0.15 mm without, ≤ 0.88 mm with 1 px noise; 29–65 object points).
  Not measured on the real arm.
- Compute: the stereo matching is the workspace crate `crates/mview-stereo` (re-exported as `armd::mview_stereo`), built at opt-level 3 while armd stays at opt-level "z" (riscv64 armd 16,390,688 → 16,404,256 bytes; armd as a whole at opt-level 3 would be 34,482,936). Measured on the device (rc21, the real banana run, opt-level "z", before this change): orbit xy5 total 993 ms (pyramid 61, features 302, sweep 225, refine 338), orbit x3 1193 ms (31, 316, 341, 454). Host now (Cortex-X925, synthetic textured box, 3 views): 6.9 ms (14.8 ms before). The estimate assumes the qemu ratio of a stage carries over to the C906; qemu does not model its caches or pipeline, and the real images (glossy, dim) may iterate the refinement more than the synthetic ones. Not measured on the device. JPEG decode of a 640x640 snapshot 1.2–1.5 ms per view on the host. Extra memory: the grayscale frames (230 KB each at 640x360) and their half-resolution copies (58 KB), the JPEG of one capture at a time (all of them with `debug`) and the gradients of the feature region (< 3 MB).
- Debug bundle (`debug: true`; the action already needs the operator session): after the captures armd writes `$ARMD_MVIEW_DEBUG_DIR/<action_id>/`, default `/userdata/rebot-teleop/mview-debug/<action_id>/` (an existing directory of that id is replaced; the newest 5 bundles are kept): `view_<k>.jpg` (each snapshot as received) and `bundle.json` `{version, action_id, armd_version, created_at, request, intrinsics {fx, fy, cx, cy, size}, cam_mount {r_end_cam, offset_m}, table_z_m, reference, ref_box_px, region_px, views [{file, offset_m, frame_id, joints_rad, bracket_rad, snapshot_tries_mrad, tcp {xyz_m, r}, camera {r_base_cam, c_m}, detections}], stats, points [{x_m, h_mm, ref_px, in_box, edge, consistent, reproj_rms_px, views}], outcomes [{x, y, edge, outcome}], measurement}`. `measurement.debug` says where it went or why it was not written. Host replay: `cargo run --release --features mview-replay --bin mview-replay -- <bundle dir> [--points]` reruns the reconstruction on the stored JPEGs and camera poses and prints the stage counts and times, the in-box heights, the outcomes and the measurement; the same binary cross-compiles for riscv64 (not part of the device package).
- Thresholds against the real scene (16:9 640x360 JPEG, Z ≈ 0.5 m, dim, glossy): a synthetic study (`thresholds_on_a_dim_glossy_scene`, ignored test; grey levels 20 + 0.35 x, per-view gain up to 8 %, JPEG q75, object filling ~80 % of the height, orbit x3) measures a textured object within 0.23 mm (156–166 points); a plain object on a noise-textured table ends `TOO_FEW_POINTS` with 20 points in the box of which 4 above 5 mm (the rest are the table seen inside the box); on a periodic, board-like table a plain object reads 5 mm low (29 points). - Without texture and without visible edges (for example a plain object whose faces have the same brightness as the table) the result is `TOO_FEW_POINTS`. A periodic texture along the epipolar lines is mostly rejected by the ratio test.

WS 动作 `/api/v1/action/measure_multiview`（需要租约、epoch、`request_id`；armd 启用 PIN 时还需要操作员会话，因为它会移动机械臂并触发相机；REST `POST` 返回 `OPERATOR_REQUIRED` / `LEASE_REQUIRED`）。能力 `measure_multiview`（与 `grasp` 同值；旧版 armd 缺省为 false）。`GET /api/v1/safety/describe` 在 `limits.measure_multiview` 下列出它（`speed_scale`、`baseline_m`、`views`、`motions`、`default_motion`、`axes`、`min_frame_margin_px`、`min_settle_s`、`max_settle_s`、`still`、`snapshot_bracket_rad`、`snapshot_tries`、`debug_dir`、`ends_on`、`return_after`）。

- 请求体 `{"label"?: 字符串, "min_score"?: 0..1（默认 0.3）, "target"?: {"box_norm": [x0, y0, x1, y1], "frame_id"?: 整数}, "motion"?: "orbit"（默认）| "translate", "axes"?: "x" | "xy"（orbit 默认 "x"，translate 默认 "xy"）, "views"?: 整数（axes "x"：2..5，默认 3；"xy"：3..5，默认 5）, "baseline_m"?: 0.03..0.12（默认 0.08）, "speed_scale"?: 0.1..0.5（默认 0.3）, "return_to_start"?: 布尔（默认 true）, "debug"?: 布尔（默认 false；见调试包）}`；其他字段或超出范围的值返回 `INVALID_COMMAND`。`target` 选择起始帧中与 `box_norm` IoU 最大（≥ 0.3）的检测；未给出时选该标签得分最高的检测。`frame_id` 被接受但不使用。在真机上比较两种运动之前，`motion` 默认保持 `orbit`。
- 起始条件：当前姿态下相机能看到物体；扭矩已开启（否则 `NOT_ARMED`）；有包含相机内参的抓取设置（否则指令以 `UNSUPPORTED` 拒绝）；提供端不支持按请求指定流水线时，动作以 `UNSUPPORTED` 结束。
- 视点偏移位于起始相机的像平面内：`axes` 为 "x" 时在图像 x 轴上均匀分布于 [−`baseline_m`/2, +`baseline_m`/2]（3 个视点：−B/2、0 即起始姿态、+B/2）；为 "xy" 时取起始姿态和半径 `baseline_m`/2 的圆上的 `views` − 1 个偏移（5 个视点：+x、+y、−x、−y；4 个视点：0°、120°、240°），使各方向的边缘都与某条极线相交。访问顺序：起始视点；"x" 先负侧由内向外再正侧由内向外，"xy" 按角度。
- `motion` 为 "orbit"：把起始姿态绕注视点 X（经过目标框中心的射线在 `table_z_m` 上方 0.02 m 处的点）旋转，使相机中心沿偏移方向移动弦长 |offset|；X 的像素位置不变，相机到 X 的距离不变。为 "translate"：相机姿态不变，平行于像平面移动偏移量；物体在图像中移动约 fx · |offset| / Z（B/2 = 0.04 m、Z = 0.35 m 时：fx 804 为 92 px，fx 600 为 69 px）。每次移动前 armd 预测这一位移（X 在规划视点中的投影），若起始框按此位移后距图像边界不足 8 px，则以 `OUT_OF_FRAME` 拒绝该视点；每个视点报告 `predicted_shift_px` 和 `frame_margin_px`。仿真测试中（fx 600，Z ≈ 0.33 m，50 x 30 x 40 mm 盒子）translate 使 X 移动 72 px，边距为 26–98 px。
- 运动：对每个视点姿态求 IK，然后以 `speed_scale`（≤ 0.5）执行 `path: "joint"` 的关节空间五次轨迹，与所有关节运动一样做检查（扫掠工作空间、禁入盒、连杆胶囊体、电源预算、力矩与碰撞保持）。运动前被拒绝的视点（`IK_UNREACHABLE`、`IK_BRANCH_FLIP`、`WORKSPACE_VIOLATION`、`SOFT_LIMIT_EXCEEDED`、`OUT_OF_FRAME`）先改用镜像偏移（未被其他视点占用时），再依次用两侧 0.75 和 0.5 倍的偏移重试；每次替换记录在 `measurement.fallbacks` `{offset_m: [x, y], used_offset_m: [x, y], code}` 中。全部被拒绝，或最远的两个视点相距不足 0.02 m 时，动作以拒绝码失败。
- 每个视点的采集：运动稳定后先等 1.0 s，再按静止规则判断：10 个间隔 20 ms 的关节采样构成一个窗口，每个手臂关节的 |速度| 中值 ≤ 0.03 rad/s 且位置范围 ≤ 3 mrad 时为静止；窗口滑动直到运动结束后 4 s，仍不静止则 `NOT_SETTLED`。随后丢弃 2 张快照（间隔 150 ms），再取一张快照（检测器主机端口 8001 或 `ARMD_SNAPSHOT_PORT` 的 `GET /snapshot.jpg`；处理前先把 640x640 信箱图裁剪为 640x360 画面；zune-jpeg 不支持区域解码或缩小解码，因此 armd 解码完整亮度通道），在请求前 100 ms 和收到回复后各采一次关节值作为区间。视点位姿为区间两次采样平均值的正运动学（含运动学修正）。任一手臂关节在区间内变化超过 2 mrad 时，0.5 s 后重取快照，最多 3 次，之后返回 `MOVED`（消息列出每次的变化量）。然后触发一次 YOLO（帧比请求新）得到目标框。某视点检测不到目标（同标签，中心距起始视点所见位置加上 X 在该视点中的位移不超过 0.2）时返回 `TARGET_LOST`。真机 B601-DM（2026-11-22，speed_scale 0.3）：关节运动后关节在数秒内蠕动 2–4 mrad，J4 / J5 可能保持几 mrad 的极限环，单次 |速度| 采样可达 0.037 rad/s；之前的规则（单次 |速度| ≤ 0.02 rad/s、整个采集期间每个关节距稳定采样不超过 3 mrad、用稳定采样做正运动学）使 6 次中 4 次以 `MOVED` 结束。J4 有 3.5 mrad 误差时，Z 0.45 m（fx 804）处图像移动 4.5 px，基线 0.08 m 下相当于 14 mm 深度（J1 3.0、J2 2.7、J3 4.3、J5 4.0 px；`cargo test --lib joint_errors_in_pixels -- --nocapture`），因此位姿取快照时的关节值。
- 特征（crates/mview-stereo），在参考视点（离起始姿态最近的视点；其检测框每边扩大 25 % + 12 px）中提取：
  - Shi-Tomasi 角点：框内最多 200 个、框外最多 60 个，按强度排序，间距 5 px。
  - 用于无纹理物体的边缘点：在检测框扩大 25 % 的区域内取垂直于边缘方向的梯度极大值（≥ 6 灰度级/像素且 ≥ 区域最大值的 10 %），彼此间距 4 px，离角点 3 px 以上。一侧均匀的边缘（离边缘 5 px 处 7x7 标准差低于 5 灰度级，即纯色面的轮廓）优先，最多 120 个；两侧都有纹理的边缘最多 40 个，再减去框内角点数的五分之一。轮廓边缘（一侧均匀、另一侧有纹理）使用单侧图块：纹理一侧的像素随背景变化，权重为 0。
- 匹配：框内特征的扫描范围为 `table_z_m` 下方 0.02 m 到上方 0.25 m，框外特征（桌面）到上方 0.01 m。角点在所有其他视点中匹配；边缘点只在极线与边缘夹角大于 30° 的视点中匹配（沿边缘方向的极线无法定位边缘）。其中相距最远的 2 个视点参与扫描：
  - 粗：在 2 倍下采样图像上按逆深度扫描，5x5 图块，每 1.5 px 图像位移一个深度采样，平均 NCC ≥ 0.6，并与最佳的另一个峰做比值检验 `(1 − best) ≤ 0.7 (1 − second)`；
  - 精：全分辨率 9x9 图块（双线性），抛物线拟合。边缘图块按每个像素垂直于边缘方向的梯度加权（另加最大值的 5 %）。
  随后每个匹配视点在全分辨率下细化：角点在二维上细化，边缘点只沿该视点的极线方向细化；NCC ≥ 0.8。参与扫描的 2 个视点还须通过左右一致性检验（其图块沿自身射线反向扫描，落点距特征不超过 2 px）。对所有匹配视点做最小二乘中点三角化；任一视点重投影误差超过 2 px 的点被丢弃。
- 边缘点与轮廓：曲面物体的轮廓随视点变化（相机移动时轮廓线在表面上滑动）。只有当至少两个其他视点匹配到该边缘点，且参考视点分别与它们三角化得到的点在 max(4 mm, 较短基线下 3 px 视差对应的深度) 以内一致时，边缘点才参与顶部高度。未通过的边缘点仍计入占地范围，但不用于 `top_z_m`。盒子的轮廓由真实棱边构成，能通过该检验；曲面轮廓未做合成测试。
- 物体与桌面：高于 `table_z_m` 5 mm 以上、且参考像素位于检测框内的点为物体点，去掉孤立点（到第 3 近物体点的距离超过 max(3 × 中值, 4 mm)）；至少 8 个，其中至少 4 个角点或一致的边缘点，否则 `TOO_FEW_POINTS`。位于桌面下方 50 mm 到上方 5 mm 之间的点为桌面点。`top_z_m` 为角点和一致边缘点的高度经局部中值（x、y 上最近 9 个点的中值）后的 p90；`width_m` / `length_m` / `yaw_deg` 取全部物体点在 x、y 上沿主轴第 2 到第 98 百分位的范围（长边相对基座 x 轴的偏航，[−90, 90)）；`centroid_m` 为该范围的中心，z = (`top_z_m` + `table_z_m`) / 2。
- 计算：在监督器锁和控制周期之外（`spawn_blocking`）进行，与机械臂返回起始关节同时进行。`return_to_start`（默认 true）用同样的关节空间运动回到起始关节；机械臂移动后出现 `TARGET_LOST`、`TOO_FEW_POINTS`、`DETECTION_UNAVAILABLE`、`UNSUPPORTED` 或后续视点被拒绝时也会返回；其他失败（停止、急停、故障、碰撞、力矩限制、`NOT_SETTLED`、`MOVED`、租约丢失、看门狗）在机械臂当前位置结束动作，不返回。

- 计算：立体匹配位于工作区 crate `crates/mview-stereo`（以 `armd::mview_stereo` 重新导出），以 opt-level 3 编译，armd 其余部分保持 opt-level "z"（riscv64 armd 16,390,688 → 16,404,256 字节；整个 armd 用 opt-level 3 则为 34,482,936）。设备实测（rc21，真机香蕉测试，opt-level "z"，本次修改之前）：orbit xy5 共 993 ms（金字塔 61、特征 302、扫描 225、细化 338），orbit x3 共 1193 ms（31、316、341、454）。主机现在（Cortex-X925，合成有纹理盒子，3 个视点）：6.9 ms（之前 14.8 ms）。设备估算：每个阶段的设备耗时 × 该阶段在 `qemu-riscv64-static`（TCG 用户态）下新旧版本的比值，所用合成数据包与真机场景相近（22 cm 物体占图像高度 83 %，Z 0.47 m；用 `MVIEW_BUNDLE_OUT` 运行 `cargo test --release --test test_mview_stereo write_realistic_bundles -- --ignored`，再用 `mview-replay` 回放）：qemu 下 x3 386 → 139 ms（特征 96 → 31、扫描 191 → 86、细化 90 → 16），xy5 477 → 146 ms（95 → 31、179 → 73、191 → 33），因此 x3 ≈ 31 + 316 × 0.32 + 341 × 0.45 + 454 × 0.18 ≈ 370 ms，xy5 ≈ 61 + 302 × 0.33 + 225 × 0.41 + 338 × 0.17 ≈ 310 ms（金字塔按实测保留）。该估算假设各阶段在 qemu 下的比值可以套用到 C906；qemu 不模拟其缓存和流水线，且真实图像（反光、昏暗）的细化迭代可能比合成图像多。未在设备上测量。主机上 640x640 快照的 JPEG 解码每个视点 1.2–1.5 ms。额外内存：灰度帧（640x360 每帧 230 KB）及其半分辨率副本（58 KB）、每次一张快照的 JPEG 数据（`debug` 时保留全部）以及特征区域的梯度（< 3 MB）。
- 调试包（`debug: true`；该动作本身已需要操作员会话）：采集完成后 armd 写入 `$ARMD_MVIEW_DEBUG_DIR/<action_id>/`，默认 `/userdata/rebot-teleop/mview-debug/<action_id>/`（同 id 的已有目录被替换；保留最新 5 个）：`view_<k>.jpg`（收到的每张快照）和 `bundle.json` `{version, action_id, armd_version, created_at, request, intrinsics {fx, fy, cx, cy, size}, cam_mount {r_end_cam, offset_m}, table_z_m, reference, ref_box_px, region_px, views [{file, offset_m, frame_id, joints_rad, bracket_rad, snapshot_tries_mrad, tcp {xyz_m, r}, camera {r_base_cam, c_m}, detections}], stats, points [{x_m, h_mm, ref_px, in_box, edge, consistent, reproj_rms_px, views}], outcomes [{x, y, edge, outcome}], measurement}`。`measurement.debug` 给出写入位置或未写入的原因。在所有视点采集完成之前结束的运行不写调试包。主机回放：`cargo run --release --features mview-replay --bin mview-replay -- <调试包目录> [--points]` 用保存的 JPEG 和相机位姿重新计算，打印各阶段计数与耗时、框内高度、特征结果和测量值；同一程序可交叉编译到 riscv64（不在设备安装包中）。
- 阈值与真实场景（16:9 640x360 JPEG，Z ≈ 0.5 m，昏暗、反光）：合成研究（忽略测试 `thresholds_on_a_dim_glossy_scene`；灰度 20 + 0.35 x、各视点亮度增益最多相差 8 %、JPEG q75、物体占约 80 % 图像高度、orbit x3）中，有纹理物体误差在 0.23 mm 以内（156–166 个点）；纯色物体放在噪声纹理桌面上以 `TOO_FEW_POINTS` 结束，框内 20 个点中只有 4 个高于 5 mm（其余是框内可见的桌面）；放在周期性（类似标定板）桌面上时纯色物体读数偏低 5 mm（29 个点）。把 `ncc_min` 从 0.8 降到 0.7 时纯色物体得到 8 个点（−0.64 mm），但有纹理物体在 1 px 噪声下误差升到 2.07 mm，因此在真实调试包显示具体是哪个阶段拒绝这些点之前保持 0.8。

### Real-arm calibration (v8 mount) / 真机标定（v8 支架）

The defaults below are simulation values. Measure them on the v8 mount before relying on them:

| value | default | how to measure |
|---|---|---|
| `camera_mount.offset_m` | none (sim tests: [−0.0731, 0.0005, 0.066]) | lens centre in end_link (m): measure from the jaw tips (end_link origin) with a ruler or take it from the CAD of the arm and the printed holder; check by jogging so the lens is above a table mark and comparing FK + offset with the mark |
| `camera_mount.body_size_m` | 0.055 x 0.047 x 0.040 | measure the printed holder with the camera installed (width along x_cam, height along y_cam, depth behind the lens) and confirm the lens sits at the centre of the front face; set the field when the box does not contain the holder |
| table margin | 5 mm (`TABLE_CLEARANCE_M`, `src/grasp.rs`) | set `table_z_m` with `table_z_from_tcp` at several points of the work area; the margin must exceed the spread of those readings plus the TCP height error at the grasp height. The margin is a constant: a larger one needs a code change |
| `recheck_tol_px` | 40 | hold the arm still over a static target, record the box centre of 100 consecutive frames, take the jitter (largest distance from the mean centre); set `recheck_tol_px` ≥ 3 × that jitter + the model error (distance between the projected and the detected centre after a transition with the target in place) |
| gripper calibration | `offset_rad: 0.0`, nominal jaw points | Mechanical zero: run `/api/v1/action/gripper_zero_check` with an empty gripper to detect mechanical stall zero and persist `offset_rad`; opening curve: measure jaw opening with calipers at multiple J7 angles and submit via WS `/api/v1/gripper/calibration` |
| `height_probe_mode` `lateral` | off (`up`) | baseline error: with a static object under the camera run grasps with `height_probe_mode: "lateral"` (per-request override) at the approach heights in use and read `lateral_baseline_err_mm` and `object_height_m` against a caliper height; in MuJoCo the error was < 0.05 mm. Switch the default only when the baseline error is small against the 0.01 m height tolerance (an error δ in B changes D by D · δ / B) |

下表默认值来自仿真，在 v8 支架上使用前须实测：`camera_mount.offset_m`（默认未设置，仿真测试用 [−0.0731, 0.0005, 0.066]）为 end_link 坐标系下的镜头中心（米），从夹爪尖（end_link 原点）用尺量或取自机械臂与打印支架的 CAD，再点动使镜头位于桌面标记上方、比较 FK + 偏移与标记位置来验证；`camera_mount.body_size_m`（默认 0.055 x 0.047 x 0.040）量装好相机的打印支架（沿 x_cam 宽、沿 y_cam 高、镜头后方深度），确认镜头位于前面中心，方盒包不住支架时设置该字段；桌面余量 5 mm（`src/grasp.rs` 的 `TABLE_CLEARANCE_M`）须大于在工作区内多点用 `table_z_from_tcp` 测得的 `table_z_m` 差值加抓取高度处的 TCP 高度误差，余量是常量，改大需改代码；`recheck_tol_px`（默认 40）：机械臂静止对准静止目标，记录连续 100 帧的框中心，取抖动（到平均中心的最大距离），设 `recheck_tol_px` ≥ 3 × 抖动 + 模型误差（目标不动时转换后投影中心与检测中心的距离）；夹爪标定（默认 `offset_rad: 0.0` 及名义开度点）：空爪执行 `/api/v1/action/gripper_zero_check` 测定机械闭合零位并持久化 `offset_rad`，用游标卡尺测量多个 J7 角度下的实际爪间距并通过 WS `/api/v1/gripper/calibration` 写入校准曲线。横移高度探测（`height_probe_mode` `lateral`，默认关闭，即 `up`）：静止物体位于相机下方，在实际使用的接近高度下用单次请求覆盖 `height_probe_mode: "lateral"` 执行抓取，读取 `lateral_baseline_err_mm`，并将 `object_height_m` 与卡尺测得的高度比较；MuJoCo 中该误差 < 0.05 mm。仅当基线误差相对 0.01 m 高度容差足够小时再改默认值（B 的误差 δ 使 D 变化 D · δ / B）。

### Camera calibration (wizard) / 相机标定（向导）

Capability `calibration_apply` (same value as `grasp`). The cockpit's calibration wizard solves intrinsics, hand-eye mount and table height in the browser and writes them through armd; agents can call the same commands.

- `camera_mount.q_end_cam` `[w, x, y, z]`: calibrated R_end_cam as a unit quaternion (|q| = 1 within 1e-3, normalised on load). When set it replaces `flip` / `rot_deg` / `tilt_deg` for every consumer (grasp camera model, `move_relative` frame `camera`, the cockpit 3D view). `tilt_deg` (and the grasp setup's `camera_tilt_deg`) is then the derived tilt: `tilt = sgn · acos(z_cam · x_end)`, `sgn = sign(−z_cam · y0)` (+ when 0), with z_cam the quaternion's optical axis and y0 the second column of the legacy mount at rot 0 / tilt 0 (`cam_mount(flip, 0, 0)`). For a q built from (flip, rot_deg, tilt_deg) with |rot_deg| < 90 this gives tilt_deg back. It decides `acquire_camera_down: auto` (|tilt| > 5°).
- Grasp setup `cx_px` / `cy_px` (optional; absent = image centre): principal point of the grasp camera model. Lens distortion is not modelled in the grasp geometry.
- `calibration.json` (`ARMD_CALIBRATION`, default `/userdata/rebot-teleop/calibration.json`): `{"camera_mount": {flip, rot_deg, tilt_deg, offset_m, q_end_cam}, "intrinsics": {fx..k3, width, height, marker_size}, "table_z_m", "solved_at", "rms"}`. Startup loads the grasp setup, then this file; the file wins for `camera_mount` and `camera_tilt_deg` (logged). A malformed or invalid file is moved aside (`.bad-<ts>`), the profile mount stays and the grasp setup's camera model (`fx_px`, `fy_px`, `cx_px`, `cy_px`, `image_size_px`, `camera_tilt_deg`, `grip_pixel_norm`) is reset to the profile values, live and in `grasp_setup.json` (old file kept as `.pre-reset-<ts>`); `GET /api/v1/calibration` reports `load_error` until an apply or restore succeeds. Backups go to `ARMD_CALIBRATION_BACKUPS` (default `calibration-backups/` next to the file), one directory per transaction named by UTC time (`20261117T101530Z`): `vision_intrinsics.json` (rebot-vision's GET body), `calibration.json` and `grasp_setup.json` copies when they existed, `manifest.json` (`created_at`, `reason`, `files`, live `camera_mount`, `calibration`, `grasp_setup`).
- While calibrated (`q_end_cam` in effect): setup writes, stored task overrides and request overrides that change `camera_tilt_deg`, `fx_px`, `fy_px`, `cx_px`, `cy_px` or `image_size_px` are refused with `INVALID_COMMAND` naming the field (`...: camera mount is calibrated; restore or recalibrate`); a write of the unchanged value passes. `grip_pixel_norm` and `table_z_m` stay writable.
- `GET /api/v1/calibration`: `{"calibrated", "busy", "load_error": str|null, "path", "backup_dir", "calibration": <file>|null, "camera_mount": {flip, rot_deg, tilt_deg, offset_m, q_end_cam}, "grasp": {fx_px, fy_px, cx_px, cy_px, image_size_px, table_z_m, camera_tilt_deg, grip_pixel_norm}, "backups": [{"name", "created_at", "reason", "files"}]}` (newest first). Also `kinematics_correction`, `stale` (`{"reason", "at"}` after a zero change, else null), `stale_list`, `joint_zero`, `joint_zero_offsets`, `zero_reference`, `zero_convention` and `calibration_tools` (see [Calibration tools and motor zero](#calibration-tools-and-motor-zero--标定工具与电机零位)).
- WS command `/api/v1/calibration/apply` (lease, arm idle): body `{"intrinsics": {fx, fy, cx, cy, k1, k2, p1, p2, k3, width: 640, height: 360, marker_size?}, "camera_mount": {"offset_m": [x, y, z], "q_end_cam": [w, x, y, z]}, "table_z_m", "rms"?: {...}, "solved_at"?: str, "dry_run"?: bool, "kinematics"?: {...}|null}` (`kinematics`: [Kinematic fine calibration](#kinematic-fine-calibration--运动学精校)). Intrinsics follow rebot-vision's rules (fx, fy in [100, 5000], 0 < cx < 640, 0 < cy < 360, |k| ≤ 10, |p| ≤ 1, marker_size in (0, 1]); `offset_m` within 0.3 m; `table_z_m` in [−0.5, 0.5]. armd derives the grasp patch `fx_px`, `fy_px`, `cx_px`, `cy_px`, `image_size_px` [640, 360], `table_z_m`, `camera_tilt_deg` (derived) and `grip_pixel_norm`: the projection, with the new mount and intrinsics, of the point under the TCP on the grasp plane (`table_z_m + grasp_height_m`) seen from the look-down approach pose (TCP at `table_z_m + approach_height_m`), so the recentre calibration offset starts at 0. When that point is outside the image (a mount tilted toward the jaws, e.g. v8: v ≈ −0.35 at 0.15 m) `grip_pixel_norm` stays as it was and the reply's `grip_pixel_model` shows the computed value (camera-down acquisition does not use it).
  - `dry_run: true`: `{"dry_run": true, "before": V, "after": V}` with `V = {"vision_intrinsics", "camera_mount", "grasp", "grip_pixel_model"?}`; writes nothing (reads rebot-vision once).
  - Otherwise one transaction, in order: backup → `PUT /api/calibration/intrinsics` to rebot-vision through armd's detector URL (`ARMD_DETECTOR_URL`, `expected_revision` from the GET) → `calibration.json` + live `camera_mount` (workspace revision bump) → grasp setup (live, `grasp_setup.json` through the setup writer). Lease and epoch are re-checked before each write. A failing step reverts the earlier ones (rebot-vision gets the old values with the new revision, files and live state are restored) and the reject carries `step` (`vision`, `calibration_file`, `grasp_setup`, `backup`), `backup` and `reverted: true`. When a rebot-vision PUT reply fails (timeout, error status), armd reads the intrinsics back: a revision past the one before the PUT, or the new values in place, counts as written and is reverted with the current revision; the revert PUT is read back the same way. If the revert fails too: `CALIBRATION_INCONSISTENT` with `state` (per service: `reverted`, `revert failed: ...`, or `unknown` when the read-back after a failed PUT failed too; no revert PUT is sent then) and `backup`. A panic in the transaction task is answered with `INTERNAL`; the busy flag is released in every case. Success ack: `{"backup", "vision_intrinsics": <GET body read back>, "camera_mount", "calibration", "grasp", "grip_pixel_model"}`.
  - A provider without the route (404) fails before any write with `VISION_CALIBRATION_UNSUPPORTED` (also for `dry_run`). rebot-vision errors pass through as the reject code when they are upper-case codes (`REVISION_MISMATCH`, `CLI_OVERRIDE`), else `VISION_ERROR`; unreachable: `VISION_UNREACHABLE`.
  - While it runs: motion commands (`/api/v1/action/*`, `/api/v1/motion/*` except stop, `/api/v1/mode/*`, presets, servo frames: `servo_reject` `calibration_busy`) get `MOTION_BUSY`; configuration writes (grasp setup, poses, collision, keep-out, gripper calibration, another calibration command) get `CONFIG_BUSY`. Heartbeats, stop and e-stop go through; a stop or e-stop changes the epoch, so the next write step fails and the transaction reverts. An apply while the arm moves or a macro runs: `MOTION_BUSY`.
- WS command `/api/v1/calibration/restore` `{"backup": "<name>"}`: puts the backup's live state back (rebot-vision intrinsics from `vision_intrinsics.json`, `camera_mount` / `calibration.json` from the manifest; no calibration in the backup removes `calibration.json` and restores the profile mount; grasp setup from the manifest), with a new backup first and the same order, checks and revert. Unknown backup: `BACKUP_NOT_FOUND`. Ack as apply plus `restored`.

能力 `calibration_apply`（与 `grasp` 相同）。驾驶舱标定向导在浏览器中求解内参、手眼安装与桌面高度，再经 armd 写入；智能体可调用同样的指令。

- `camera_mount.q_end_cam` `[w, x, y, z]`：标定得到的 R_end_cam 单位四元数（|q| 与 1 相差不超过 1e-3，加载时归一化）。设置后所有使用者（抓取相机模型、`move_relative` 的 `camera` 坐标系、驾驶舱 3D 视图）以它代替 `flip` / `rot_deg` / `tilt_deg`。此时 `tilt_deg`（及抓取设置的 `camera_tilt_deg`）为推导出的倾角：`tilt = sgn · acos(z_cam · x_end)`，`sgn = sign(−z_cam · y0)`（为 0 时取 +），z_cam 为四元数的光轴，y0 为 rot 0 / tilt 0 时旧安装（`cam_mount(flip, 0, 0)`）的第二列。由 (flip, rot_deg, tilt_deg) 构造且 |rot_deg| < 90 的 q 推导结果等于 tilt_deg。它决定 `acquire_camera_down: auto`（|tilt| > 5°）。
- 抓取设置 `cx_px` / `cy_px`（可选，缺省为画面中心）：抓取相机模型的主点。抓取几何不建模镜头畸变。
- `calibration.json`（`ARMD_CALIBRATION`，默认 `/userdata/rebot-teleop/calibration.json`）：`{"camera_mount": {flip, rot_deg, tilt_deg, offset_m, q_end_cam}, "intrinsics": {fx..k3, width, height, marker_size}, "table_z_m", "solved_at", "rms"}`。启动时先加载抓取设置，再加载该文件；`camera_mount` 与 `camera_tilt_deg` 以该文件为准（写日志）。文件损坏或无效时改名为 `.bad-<ts>`，保留 profile 的安装，并把抓取设置的相机模型（`fx_px`、`fy_px`、`cx_px`、`cy_px`、`image_size_px`、`camera_tilt_deg`、`grip_pixel_norm`）重置为 profile 值（运行时及 `grasp_setup.json`，原文件保留为 `.pre-reset-<ts>`）；`GET /api/v1/calibration` 的 `load_error` 给出原因，直到 apply 或 restore 成功。备份位于 `ARMD_CALIBRATION_BACKUPS`（默认与该文件同目录的 `calibration-backups/`），每次事务一个以 UTC 时间命名的目录（`20261117T101530Z`）：`vision_intrinsics.json`（rebot-vision 的 GET 响应）、已存在时复制的 `calibration.json` 与 `grasp_setup.json`、`manifest.json`（`created_at`、`reason`、`files`、当时的 `camera_mount`、`calibration`、`grasp_setup`）。
- 已标定（`q_end_cam` 生效）期间：设置写入、已存任务覆盖项与请求覆盖项若修改 `camera_tilt_deg`、`fx_px`、`fy_px`、`cx_px`、`cy_px` 或 `image_size_px`，返回 `INVALID_COMMAND` 并指明字段（`...: camera mount is calibrated; restore or recalibrate`）；写入相同值可以通过。`grip_pixel_norm` 与 `table_z_m` 仍可写。
- `GET /api/v1/calibration`：`{"calibrated", "busy", "load_error": str|null, "path", "backup_dir", "calibration": <文件>|null, "camera_mount", "grasp": {fx_px, fy_px, cx_px, cy_px, image_size_px, table_z_m, camera_tilt_deg, grip_pixel_norm}, "backups": [{"name", "created_at", "reason", "files"}]}`（新的在前）。另含 `kinematics_correction`、`stale`（零位改动后为 `{"reason", "at"}`，否则为 null）、`stale_list`、`joint_zero`、`joint_zero_offsets`、`zero_reference`、`zero_convention` 与 `calibration_tools`（见[标定工具与电机零位](#calibration-tools-and-motor-zero--标定工具与电机零位)）。
- WS 指令 `/api/v1/calibration/apply`（需持有租约、机械臂空闲）：请求体 `{"intrinsics": {fx, fy, cx, cy, k1, k2, p1, p2, k3, width: 640, height: 360, marker_size?}, "camera_mount": {"offset_m": [x, y, z], "q_end_cam": [w, x, y, z]}, "table_z_m", "rms"?, "solved_at"?, "dry_run"?, "kinematics"?}`（`kinematics` 见[运动学精校](#kinematic-fine-calibration--运动学精校)）。内参校验同 rebot-vision（fx、fy ∈ [100, 5000]，0 < cx < 640，0 < cy < 360，|k| ≤ 10，|p| ≤ 1，marker_size ∈ (0, 1]）；`offset_m` 在 0.3 m 内；`table_z_m` ∈ [−0.5, 0.5]。armd 推导抓取设置补丁 `fx_px`、`fy_px`、`cx_px`、`cy_px`、`image_size_px` [640, 360]、`table_z_m`、`camera_tilt_deg`（推导值）和 `grip_pixel_norm`：用新的安装与内参，从俯视接近位姿（TCP 位于 `table_z_m + approach_height_m`）看 TCP 正下方抓取平面（`table_z_m + grasp_height_m`）上的点的投影，因此再对准的标定偏移从 0 开始。该点在画面外时（朝夹爪倾斜的安装，如 v8：0.15 m 时 v ≈ −0.35）`grip_pixel_norm` 保持不变，回复中的 `grip_pixel_model` 给出计算值（相机朝下采集不使用它）。
  - `dry_run: true`：返回 `{"dry_run": true, "before": V, "after": V}`，`V = {"vision_intrinsics", "camera_mount", "grasp", "grip_pixel_model"?}`；不写入（读取 rebot-vision 一次）。
  - 否则按顺序执行一次事务：备份 → 经 armd 的检测器地址（`ARMD_DETECTOR_URL`，`expected_revision` 取自 GET）向 rebot-vision `PUT /api/calibration/intrinsics` → `calibration.json` + 运行时 `camera_mount`（工作空间修订号递增）→ 抓取设置（运行时及经设置写入器保存的 `grasp_setup.json`）。每次写入前重新检查租约与 epoch。某步失败时回滚之前的步骤（向 rebot-vision 以新的修订号写回旧值，恢复文件与运行时状态），拒绝消息带 `step`（`vision`、`calibration_file`、`grasp_setup`、`backup`）、`backup` 与 `reverted: true`。rebot-vision 的 PUT 应答失败（超时、错误状态码）时，armd 读回内参：修订号超过 PUT 之前的值，或新值已生效，即视为已写入，并以当前修订号回滚；回滚 PUT 失败时同样读回确认。回滚也失败时返回 `CALIBRATION_INCONSISTENT`，带 `state`（各服务为 `reverted`、`revert failed: ...`，或 PUT 失败后读回也失败时为 `unknown`，此时不发送回滚 PUT）与 `backup`。事务任务 panic 时应答 `INTERNAL`；任何情况下都会清除忙碌标志。成功应答：`{"backup", "vision_intrinsics": <读回的 GET 响应>, "camera_mount", "calibration", "grasp", "grip_pixel_model"}`。
  - 提供端没有该路由（404）时在任何写入之前以 `VISION_CALIBRATION_UNSUPPORTED` 失败（`dry_run` 同样）。rebot-vision 的错误码为大写代码时原样作为拒绝码（`REVISION_MISMATCH`、`CLI_OVERRIDE`），否则为 `VISION_ERROR`；无法连接为 `VISION_UNREACHABLE`。
  - 事务进行中：运动指令（`/api/v1/action/*`、除 stop 外的 `/api/v1/motion/*`、`/api/v1/mode/*`、预设、servo 帧：`servo_reject` `calibration_busy`）返回 `MOTION_BUSY`；配置写入（抓取设置、命名姿态、碰撞、禁入盒、夹爪标定、另一条标定指令）返回 `CONFIG_BUSY`。心跳、stop 与急停照常；stop 或急停改变 epoch，下一写入步骤失败并回滚。机械臂运动或宏动作进行中发起 apply：`MOTION_BUSY`。
- WS 指令 `/api/v1/calibration/restore` `{"backup": "<名称>"}`：恢复备份时的状态（rebot-vision 内参取自 `vision_intrinsics.json`，`camera_mount` / `calibration.json` 取自 manifest；备份中没有标定时删除 `calibration.json` 并恢复 profile 安装；抓取设置取自 manifest），先做一次新备份，顺序、检查与回滚同 apply。备份不存在：`BACKUP_NOT_FOUND`。应答同 apply，另含 `restored`。

#### Kinematic fine calibration / 运动学精校

Capability `calibration_kinematics` (`calibration_apply` and the built-in RebotDevArm model). The correction makes armd's FK / IK match the real arm's geometry (joint zero, axis direction and link offsets differ from the URDF; measured on a B601-DM: hand-eye residual 4.4 / 5.9 mm uncorrected, 2.0 / 2.2 mm with the full model, two board placements, held-out).

- Model (one definition for armd, the cockpit and the Python SDK): model angles q as in `model_joint_map`; walking the built-in chain, joint i (J1..J6) is `F_i · [Rx(tilt_x) · Ry(tilt_y), (dx, dy, dz)] · Rot(axis_i, q_i · (1 + scale) + offset_rad)`, `F_i` the URDF origin of the joint, then the fixed `end_joint`. All zero = the URDF chain bit for bit.
- Per joint `{"offset_rad", "scale", "tilt_rad": [x, y], "origin_m": [dx, dy, dz]}` (missing fields are 0, unknown fields are refused). Bounds: |offset_rad| ≤ 10°, |scale| ≤ 0.08, |tilt_rad| ≤ 3° per axis, |origin_m| ≤ 0.03 m per component. Joints the solver does not identify are zeros (J1: absorbed by the board pose, J6: by the camera mount).
- `calibration.json` `"kinematics": {"joints": [6 × joint], "fit"?: {"level", "heldout_mm": [a, b], "heldout_uncorrected_mm", "train_mm", "views", "levels": [{"level", "heldout_mm", "chosen"}], "solved_at"}}` (`fit` passed through; the cockpit writes the chosen model level L1..L3 and the table of all four levels). Apply body field `kinematics`: the same object (validated as above, else `INVALID_COMMAND` naming the joint and field); absent = a stored correction stays; `null` = removes it. `dry_run` shows `kinematics` in `before` / `after`.
- A real apply with `kinematics` (also `null`), and a restore whose backup has another correction, need torque off and no action running; otherwise `KINEMATICS_ARMED` (409) before any write. Checked again when `calibration.json` is written; torque switched on during the transaction fails that step and reverts the earlier ones. Dry runs are allowed with torque on.
- Live: after the write, `config.arm_model` carries the correction for every FK / IK / workspace / keep-out / grasp / place path (workspace revision bump: plans made before fail `PLAN_STALE`; stored poses' TCPs are recomputed). Not corrected: gravity and power-budget dynamics, the legacy camera mount and the derived `tilt_deg`, the reach origin `max_reach_m` is measured from.
- `/api/v1/observation/schema` `kinematics_correction`: the joints array in effect, or null (absent in older armd). `GET /api/v1/calibration` and the apply / restore ack: `kinematics_correction`, and `calibration.kinematics`.
- Restore puts the backup's correction back (none in the backup = uncorrected).
- Startup: a correction outside the bounds or malformed rejects `calibration.json` like any invalid file (moved aside, `load_error`, uncorrected model, profile camera mount). Profiles with a URDF chain (`kinematics: "Urdf"`): apply with `kinematics` is `UNSUPPORTED`; a stored correction is ignored at startup with a `load_error` (the camera calibration still loads).

能力 `calibration_kinematics`（`calibration_apply` 且为内置 RebotDevArm 模型）。该修正使 armd 的 FK / IK 与真机几何一致（关节零位、轴线方向与连杆偏移与 URDF 不同；在一台 B601-DM 上实测，两个标定板位置互为留出集：手眼残差未修正 4.4 / 5.9 mm，完整模型 2.0 / 2.2 mm）。

- 模型（armd、驾驶舱与 Python SDK 共用同一定义）：模型角 q 同 `model_joint_map`；沿内置运动链，关节 i（J1..J6）为 `F_i · [Rx(tilt_x) · Ry(tilt_y), (dx, dy, dz)] · Rot(axis_i, q_i · (1 + scale) + offset_rad)`，`F_i` 为该关节的 URDF 原点，之后是固定的 `end_joint`。全为 0 时与 URDF 链逐位一致。
- 每个关节 `{"offset_rad", "scale", "tilt_rad": [x, y], "origin_m": [dx, dy, dz]}`（缺省字段为 0，未知字段被拒绝）。范围：|offset_rad| ≤ 10°，|scale| ≤ 0.08，|tilt_rad| 每轴 ≤ 3°，|origin_m| 每分量 ≤ 0.03 m。求解器不辨识的关节写 0（J1 由标定板位姿吸收，J6 由相机安装吸收）。
- `calibration.json` 的 `"kinematics": {"joints": [6 个关节], "fit"?: {"level", "heldout_mm": [a, b], "heldout_uncorrected_mm", "train_mm", "views", "levels": [{"level", "heldout_mm", "chosen"}], "solved_at"}}`（`fit` 原样保存；驾驶舱写入所选模型级别 L1..L3 与四个级别的表）。apply 请求体字段 `kinematics`：同一结构（按上述规则校验，否则 `INVALID_COMMAND` 并指明关节与字段）；缺省时保留已存的修正；`null` 删除修正。`dry_run` 的 `before` / `after` 含 `kinematics`。
- 带 `kinematics`（含 `null`）的正式 apply，以及备份中的修正与当前不同的 restore，要求扭矩关闭且没有动作在执行，否则在任何写入之前返回 `KINEMATICS_ARMED`（409）。写 `calibration.json` 时再次检查；事务期间打开扭矩会使该步骤失败并回滚之前的步骤。`dry_run` 在扭矩打开时也可执行。
- 即时生效：写入后 `config.arm_model` 带上修正，所有 FK / IK / 工作空间 / 禁入盒 / 抓取 / 放置路径使用它（工作空间修订号递增：之前做出的规划以 `PLAN_STALE` 失败；已存命名姿态的 TCP 重新计算）。不修正的部分：重力与功率预算动力学、旧式相机安装与推导的 `tilt_deg`、`max_reach_m` 的测量原点。
- `/api/v1/observation/schema` 的 `kinematics_correction`：当前生效的关节数组，或 null（旧版 armd 无此字段）。`GET /api/v1/calibration` 及 apply / restore 应答含 `kinematics_correction` 与 `calibration.kinematics`。
- restore 恢复备份中的修正（备份中没有修正则恢复为未修正）。
- 启动：超出范围或格式错误的修正按无效文件处理 `calibration.json`（改名移开、`load_error`、使用未修正模型与 profile 相机安装）。使用 URDF 链的 profile（`kinematics: "Urdf"`）：带 `kinematics` 的 apply 返回 `UNSUPPORTED`；启动时忽略已存的修正并给出 `load_error`（相机标定照常加载）。

#### Calibration sessions / 标定数据

The raw data of a calibration, kept on the device so a solve can be repeated without capturing (the cockpit wizard
uploads after each placement's capture and after each solve, and loads them back with "Load from device"). No lease;
nothing is applied. Cross-origin writes are refused like on every non-GET route.

- `POST /api/v1/calibration/sessions` body (JSON object, at most 8 MB, else 413): `{"id"?, "kind": "camera"|"fine", "created_at"?, "views": [...], ...}`; the wizard also sends `board`, `frame`, `intrinsics_K`, `X0`, `plan`, `solve`, `gates`, `levels`, `summary`. `id` (`^[A-Za-z0-9_-]{1,64}$`) overwrites that session; without it armd assigns a ULID. Reply: the list entry `{"id", "kind", "created_at", "stored_at", "views" (count), "size" (bytes), "summary"}`. `400 INVALID` for a bad `kind`, `views` not an array, a bad `id` or `created_at`.
- `GET /api/v1/calibration/sessions`: `{"sessions": [entries, newest store first], "keep": 10, "max_bytes"}`. `GET /api/v1/calibration/sessions/<id>`: the stored body with `id`, `created_at`, `stored_at` (404 `NOT_FOUND`). `DELETE /api/v1/calibration/sessions/<id>`: `{"deleted": id}` (404 when absent).
- Files: `<dir>/<id>.json` and `<dir>/<id>.meta.json` (the list entry), written with temp file + rename; after a store only the newest 10 are kept (an overwrite counts as new). `dir`: `ARMD_CALIBRATION_SESSIONS`, default `calibration-sessions/` next to `calibration.json` (`/userdata/rebot-teleop/calibration-sessions/`).
- Wizard views: `markers`, `q` (model angles, the solver input), `joints` (armd positions as captured), `T_base_end` (FK at capture), `ds` (placement 0 / 1, fine mode), `pose`, `frame`, `frame_id`, `ts`, `settled`. A loaded session needs a verify view before Apply (one capture at the current pose reprojected with the solved values onto the stored board placements, ≤ 3 mm).

标定的原始数据保存在设备上，以便不重新采集就能再次求解（驾驶舱向导在每个位置采集完成后和每次求解后上传，用「从设备加载」读回）。不需要租约，不写入任何标定。与其他非 GET 路由一样拒绝跨源写入。

- `POST /api/v1/calibration/sessions` 请求体（JSON 对象，最大 8 MB，超出返回 413）：`{"id"?, "kind": "camera"|"fine", "created_at"?, "views": [...], ...}`；向导另外发送 `board`、`frame`、`intrinsics_K`、`X0`、`plan`、`solve`、`gates`、`levels`、`summary`。带 `id`（`^[A-Za-z0-9_-]{1,64}$`）时覆盖该条；不带时 armd 分配 ULID。回复为列表项 `{"id", "kind", "created_at", "stored_at", "views"（数量）, "size"（字节）, "summary"}`。`kind` 不合法、`views` 不是数组、`id` 或 `created_at` 不合法时返回 `400 INVALID`。
- `GET /api/v1/calibration/sessions`：`{"sessions": [列表项，最近存入的在前], "keep": 10, "max_bytes"}`。`GET /api/v1/calibration/sessions/<id>`：保存的请求体，含 `id`、`created_at`、`stored_at`（不存在时 404 `NOT_FOUND`）。`DELETE /api/v1/calibration/sessions/<id>`：`{"deleted": id}`（不存在时 404）。
- 文件：`<dir>/<id>.json` 与 `<dir>/<id>.meta.json`（列表项），先写临时文件再改名；每次存入后只保留最新 10 条（覆盖也算新存入）。`dir`：`ARMD_CALIBRATION_SESSIONS`，默认在 `calibration.json` 同目录下的 `calibration-sessions/`（`/userdata/rebot-teleop/calibration-sessions/`）。
- 向导的视图字段：`markers`、`q`（模型角，求解输入）、`joints`（采集时 armd 的关节读数）、`T_base_end`（采集时的 FK）、`ds`（位置 0 / 1，精校模式）、`pose`、`frame`、`frame_id`、`ts`、`settled`。加载的数据在应用前需要一次验证视图（在当前位置采一张图，用求解结果重投影到已保存的标定板位置，≤ 3 mm）。

#### Calibration tools and motor zero / 标定工具与电机零位

**Joint zero convention.** Joint angles are calibrated against the profile's `zero_reference`, the physical reference pose (B601-DM: the folded rest pose, URDF angles 0 on J1..J6, gripper closed). `home_positions` and the park target are derived from it (a profile may omit `home_positions`; a conflicting value is rejected). The B601-DM model offsets are 0 (official convention, Seeed-Projects/reBotArm_control_py: URDF angle = joint angle), so an arm zeroed in the rest pose reads 0 on every joint there. `calibration.json` `joint_zero` `{"joints": [{"offset_rad"}] x dof, "method": "software"|"motor", "set_at", "reference": "rest"}` holds the per-joint offset (motor - joint); armd applies it at one place, the driver boundary (readings joint = motor - offset, commands motor = joint + offset, driver position limits shifted into joint space; profile limits are joint space), so park, limits, poses, FK / IK, the cockpit and the SDK see calibrated joint angles. Without `joint_zero` the offsets are 0 and every value passes through unchanged. The schema publishes `zero_reference`, `joint_zero` and `zero_convention`.

**Legacy zero detection.** At startup and each time torque goes off, armd checks the readings against the reference: an arm in the rest pose (J1..J5 within `resting_pose.position_tolerances`) with |J6 - reference| within 10° of 90° is reported as `zero_convention: {"status": "legacy_j6", "message", "j6_rad"}` in `GET /api/v1/calibration` and the schema (else `ok`, or `unchecked` before a check at the rest pose; null without a `zero_reference`). Such a unit was zeroed with the wrist rolled 90°: park rolls the wrist 90° and the 3D view / camera orientation is off by 90° until J6 is zeroed in the rest pose. armd never moves the arm because of it; the verdict stays until a zero of J6. The cockpit shows it in **Settings > Tools** with a button to the zero tool.

`capabilities.calibration_tools` (capabilities version 10; also in `GET /api/v1/calibration`) lists the calibration tools of this arm, built from the profile and the driver; a client shows only tools with `supported: true`, an unsupported tool carries `reason`:

```json
{"camera": {"supported": true},
 "kinematics": {"supported": true, "joints": [2, 3, 4, 5]},
 "motor_zero": {"supported": true, "method": "set_current", "persist": "motor_flash", "persist_verified": false, "notes": ["..."],
                "joints": [1, 2, 3, 4, 5, 6, 7], "requires": ["lease", "torque_off", "no_action", "no_fault"],
                "max_offset_deg": 45, "verify_mrad": 10, "invalidates": ["kinematics", "camera", "poses", "gripper_calibration"],
                "motor": true, "software": true, "methods": ["software", "motor"],
                "zero_pose": {"description": "...", "joints": ["J1 ...", "..."], "gripper": "Gripper fully closed", "source": "..."}},
 "gripper": {"supported": true, "zero_check": true, "calibration": true}}
```

`motor`: the driver's set-zero is available; `software`: the profile has a `zero_reference` (every driver). `supported` is true when either is.

| Follower | `motor` | `persist` of the motor zero |
|---|---|---|
| `rebot-dm` (Damiao) | yes | `motor_flash`, `persist_verified: false` |
| `sim` | yes | `simulator` (offset in armd's simulated encoder, lost when armd restarts) |
| `mock` | yes | `process` (the readings of the zeroed joints become the reference) |
| `rebot-rs` (RobStride) | no (reason in `notes`) | — (`TYPE_SET_ZERO` exists in the protocol module; motorbridge lists RobStride zero calibration as unresolved; whether type 6 persists without type 22 is not checked) |
| `so-arm101` (Feetech), `fashionstar` | no | — (Feetech zero = the profile's `feetech.joints` calibration) |

`zero_pose` comes from the profile field `zero_pose` (B601-DM: the rest pose, every joint 0, gripper fully closed).

WS command `/api/v1/calibration/motor_zero` `{"joints": [1-based joint numbers], "dry_run"?: bool, "force"?: bool, "method"?: "software"|"motor"}` makes the current position of each listed joint read its reference (`zero_reference`, 0 on the B601-DM). `method` absent: `motor` when the driver supports it, else `software`. Checks under the lock, in order: the tool is supported (`UNSUPPORTED`), the method is available (`UNSUPPORTED`), every joint is in `motor_zero.joints` (`JOINT_UNSUPPORTED`), no calibration transaction runs (`CONFIG_BUSY`), the arm is not in Fault / EStop (`MOTOR_ZERO_FAULT`), torque off, no action, trajectory, servo stream or gravity compensation, safety state Idle (`MOTOR_ZERO_ARMED`), fresh feedback (`MOTOR_ZERO_NO_FEEDBACK`), and without `force` no listed joint reads more than 45° from its reference (`MOTOR_ZERO_FAR`, reply `joints` with the readings).

- `dry_run: true` (same checks except the 45° rule): `{"dry_run": true, "joints": [{"joint", "name", "reading_rad", "reading_deg", "reference_rad", "after_rad", "change_rad", "far"}], "needs_force", "far_joints", "invalidates": {"kinematics": bool, "camera": bool, "poses": [names], "gripper_calibration": bool}, "zero_method", "method", "persist", "persist_verified", "max_offset_deg"}`; changes nothing.
- `method: "motor"` (own task; meanwhile motion, torque, clear_fault, calibration and configuration commands are refused with `MOTION_BUSY` / `CONFIG_BUSY`; lease and epoch are re-checked before each step): disable every motor (as reBotArm_control_py `RebotArm.set_zero`), wait up to 1 s for feedback newer than the disable that reports each listed motor disabled (`MOTOR_ZERO_NOT_DISABLED`, nothing changed), send the set-zero command per joint 0.1 s apart (Damiao: `FF FF FF FF FF FF FF FE` on the motor's CAN ID) and set that joint's `joint_zero` offset to -reference (0 on the B601-DM), then wait up to 1 s until every zeroed joint reads within 10 mrad of its reference in feedback newer than its command. Ack: `{"joints": [{"joint", "before_rad", "after_rad", "reference_rad", "sent", "fresh", "verified"}], "invalidated", "log", "zero_method": "motor", "method", "persist", "persist_verified", "torque": "off"}`. A joint that does not verify: `MOTOR_ZERO_UNVERIFIED` (500) with the same `joints`, `invalidated` and `log`. A motor zero cannot be restored: the motors hold the new zero.
- `method: "software"` (same task rules): the readings are averaged over 0.5 s (a joint moving more than 0.01 rad: `ZERO_MOVING` (409), nothing changed), `calibration.json` is backed up (`<backup_dir>/<time>/`, manifest `reason: "software_zero"`), the new offsets (offset += mean reading - reference) are installed and stored in `calibration.json` `joint_zero` (`method: "software"`; all offsets 0 remove it), and the readings are verified as for the motor zero. No flash write; works with every driver. Ack as above plus `"backup"`, `"offsets_before"`, `"offsets_after"`, `"restore": {"path", "backup"}`.
- WS command `/api/v1/calibration/joint_zero/restore` `{"backup": name}` puts back the `joint_zero` a software zero backup holds (none in it = offsets 0), with a new backup first (`reason: "joint_zero_restore"`); same checks as the zero (torque off, lease, no fault) and the same invalidation. Ack: `{"restored", "backup", "offsets_before", "offsets_after", "invalidated"}`. A camera restore (`/api/v1/calibration/restore`) keeps the live `joint_zero`.
- Every run is appended to `motor_zero.jsonl` in the calibration backup directory: `{"time", "joints", "readings_before", "force", "result": "verified"|"unverified"|"partial", "rows", "invalidated"}`.
- Invalidation (after any zero change): the kinematic correction is removed, live and from `calibration.json` (its values are in `invalidated.removed_kinematics` and the log), and the camera calibration is marked stale (`calibration.json` `"stale": {"reason", "at"}`). For joints whose reading moved by more than 0.5°, the saved poses are marked stale (each pose in `poses.json` and `GET /api/v1/poses` gets `"stale": {"reason", "at"}`; saving a pose again clears it) and, when the gripper joint moved and a gripper calibration exists, the gripper calibration (`gripper_calib.json` and `GET /api/v1/gripper/calibration` `stale`; a new calibration clears it). Nothing is deleted. `GET /api/v1/calibration` `stale_list`: `[{"item": "camera"|"poses"|"gripper_calibration", "reason", "at", "names"?}]`. `invalidated`: `{"kinematics_removed", "camera_stale", "poses_stale": [names], "gripper_calibration_stale", "removed_kinematics", "at", "error"}` (`error`: a file write failed; the live state is changed).
- Recorded episodes and datasets are joint-space data: they do not follow a zero change. Data recorded before a zero change replays and trains against the old zero.

**关节零位约定。** 关节角以 profile 的 `zero_reference`（物理参考姿态，B601-DM：折叠收纳姿态，J1..J6 的 URDF 角均为 0，夹爪闭合）为基准标定。`home_positions` 与收纳目标由它推出（profile 可以不写 `home_positions`；写了且不一致时拒绝加载）。B601-DM 的模型偏移为 0（官方约定，Seeed-Projects/reBotArm_control_py：URDF 角 = 关节角），在收纳姿态置零的机械臂在该姿态每个关节读 0。`calibration.json` 的 `joint_zero` `{"joints": [{"offset_rad"}] × dof, "method": "software"|"motor", "set_at", "reference": "rest"}` 保存每个关节的偏移（电机角 - 关节角）；armd 只在驱动边界一处应用：读数 关节 = 电机 - 偏移，指令 电机 = 关节 + 偏移，驱动的位置限位换算到关节空间（profile 限位是关节空间）。因此收纳、限位、点位、FK / IK、驾驶舱和 SDK 看到的都是标定后的关节角。没有 `joint_zero` 时偏移为 0，所有数值原样通过。schema 中发布 `zero_reference`、`joint_zero` 与 `zero_convention`。

**旧零位检测。** 启动时以及每次关闭使能后，armd 把读数与参考姿态比较：机械臂处于收纳姿态（J1..J5 在 `resting_pose.position_tolerances` 内）且 |J6 - 参考| 与 90° 相差不超过 10° 时，`GET /api/v1/calibration` 与 schema 中报告 `zero_convention: {"status": "legacy_j6", "message", "j6_rad"}`（否则为 `ok`；尚未在收纳姿态检查过为 `unchecked`；没有 `zero_reference` 时为 null）。这类机械臂的 J6 是在手腕转了 90° 的位置置零的：在收纳姿态重新设置 J6 零位之前，收纳会把手腕转 90°，3D 视图与相机方向差 90°。armd 不会因此移动机械臂；该结论保持到 J6 重新置零。驾驶舱在 **设置 > 工具** 中显示提示，并提供打开零位标定的按钮。

`capabilities.calibration_tools`（capabilities 版本 10，`GET /api/v1/calibration` 中同样提供）按 profile 与驱动列出本机支持的标定工具；客户端只显示 `supported: true` 的工具，不支持的工具带 `reason`。`motor_zero.motor`：驱动支持电机置零；`motor_zero.software`：profile 有 `zero_reference`（任何驱动）；两者有一个即 `supported`。电机置零：`rebot-dm`（达妙）支持，`persist` 为 `motor_flash`，掉电后是否保留未在实机验证（`persist_verified: false`）；`sim` 支持，偏移保存在 armd 的仿真编码器中，armd 重启后丢失；`mock` 支持，被置零关节的读数变为参考值；`rebot-rs`（RobStride）不支持（原因见 `notes`）；`so-arm101`（飞特）与 `fashionstar` 不支持。`zero_pose` 取自 profile 字段 `zero_pose`（B601-DM：收纳姿态，每个关节为 0，夹爪完全闭合）。

WS 指令 `/api/v1/calibration/motor_zero` `{"joints": [关节编号，从 1 开始], "dry_run"?: bool, "force"?: bool, "method"?: "software"|"motor"}` 让所列关节在当前位置读出参考值（`zero_reference`，B601-DM 为 0）。不写 `method` 时：驱动支持电机置零则为 `motor`，否则为 `software`。在锁内依次检查：工具与方法可用（`UNSUPPORTED`）、关节都在 `motor_zero.joints` 中（`JOINT_UNSUPPORTED`）、没有标定事务在执行（`CONFIG_BUSY`）、不处于 Fault / EStop（`MOTOR_ZERO_FAULT`）、扭矩关闭且没有动作、轨迹、servo 流或重力补偿、安全状态为 Idle（`MOTOR_ZERO_ARMED`）、反馈新鲜（`MOTOR_ZERO_NO_FEEDBACK`）；不带 `force` 时所列关节读数都不能偏离参考值超过 45°（`MOTOR_ZERO_FAR`）。

- `dry_run: true`（检查同上，不含 45° 规则）：返回各关节读数、参考值、预计变化、`needs_force`、`far_joints`、`zero_method` 与将被作废或标为过期的内容（`invalidates`：`kinematics`、`camera`、`poses` 名称列表、`gripper_calibration`），不做任何修改。
- `method: "motor"`（独立任务；期间运动、扭矩、清除故障、标定与配置指令返回 `MOTION_BUSY` / `CONFIG_BUSY`；每步之前重新检查租约与 epoch）：先失能所有电机，1 s 内等到确认已失能的新鲜反馈（否则 `MOTOR_ZERO_NOT_DISABLED`，不做修改），逐个关节发送置零命令（间隔 0.1 s，达妙：`FF FF FF FF FF FF FF FE`），并把该关节的 `joint_zero` 偏移设为 -参考值（B601-DM 为 0），再在 1 s 内等到每个置零关节读数在参考值的 10 mrad 以内。有关节未通过校验时返回 `MOTOR_ZERO_UNVERIFIED`（500）。电机零位无法恢复：电机保存的是新零点。
- `method: "software"`（任务规则同上）：在 0.5 s 内取读数平均（有关节移动超过 0.01 rad 时返回 `ZERO_MOVING`（409），不做修改），先备份 `calibration.json`（`<backup_dir>/<时间>/`，manifest `reason: "software_zero"`），安装新偏移（偏移 += 平均读数 - 参考值）并写入 `calibration.json` 的 `joint_zero`（`method: "software"`；偏移全为 0 时删除该字段），再按电机置零的方式校验读数。不写电机 flash，任何驱动都可用。应答另含 `backup`、`offsets_before`、`offsets_after`、`restore: {"path", "backup"}`。
- WS 指令 `/api/v1/calibration/joint_zero/restore` `{"backup": 名称}`：恢复软件零位备份中的 `joint_zero`（备份中没有则偏移为 0），恢复前先做新备份（`reason: "joint_zero_restore"`）；检查与作废同置零。相机标定恢复（`/api/v1/calibration/restore`）保留当前的 `joint_zero`。
- 每次执行追加一行到标定备份目录下的 `motor_zero.jsonl`（时间、关节、置零前读数、`force`、结果、各关节行、作废情况）。
- 作废（任何零位改动之后）：删除运动学修正（运行时及 `calibration.json`），相机标定标为过期（`calibration.json` 的 `"stale": {"reason", "at"}`）。对读数变化超过 0.5° 的关节：已存点位标为过期（`poses.json` 与 `GET /api/v1/poses` 中每个点位带 `"stale": {"reason", "at"}`，重新记录该点位即清除）；夹爪关节变化且已有夹爪标定时，夹爪标定标为过期（`gripper_calib.json` 与 `GET /api/v1/gripper/calibration` 的 `stale`，新的标定清除）。不删除任何数据。`GET /api/v1/calibration` 的 `stale_list`：`[{"item": "camera"|"poses"|"gripper_calibration", "reason", "at", "names"?}]`。
- 已录制的 episode 与数据集是关节空间数据，不随零位改动变化：零位改动之前录制的数据按旧零位回放与训练。

## Place / 放置

`/api/v1/action/place` puts a held object down at a named pose or at a base-frame position. Needs a 7-DOF profile with `kinematics` and `gripper_policy` (`capabilities.place`); otherwise `UNSUPPORTED`. No camera or grasp setup is involved.

`/api/v1/action/place` 把夹持的物体放到命名姿态或基座坐标系下的指定位置。需要 7 轴且设置了 `kinematics` 和 `gripper_policy`（`capabilities.place`），否则返回 `UNSUPPORTED`。不使用相机和抓取设置。

| field | default | meaning |
|---|---|---|
| `pose` | — | named pose; its stored TCP (`tcp.position`, `tcp.rpy`) is the place point and orientation. A pose saved without a TCP uses FK of its positions |
| `position` | — | place point `[x,y,z]` (end_link origin, base frame, m). Exactly one of `pose` / `position` |
| `orientation` | null | `{"rpy":[r,p,y]}` or `{"quat":[w,x,y,z]}`; null = the pose's orientation (`pose`) or the current one (`position`) |
| `yaw` | null | `"outward"`: the orientation's yaw becomes atan2(y, x) of the place point, approach and descent keep the yaw outward ([Outward yaw](#outward-yaw--朝外偏航)) |
| `approach_height_m` | 0.08 | 0.02..0.30; height above the place point for the approach and the retreat |
| `release` | true | open the gripper at the place point |
| `retreat` | true | move straight up by `approach_height_m` after the release |
| `speed_scale` | 1.0 | 0.1..1.0; every phase runs at 0.05 m/s × scale linear and 0.5 rad/s × scale angular (the `move_to` defaults), then the profile `speed_cap` |
| `tag` | null | string ≤ 64 bytes |

Phases (`action.phase`, `action.progress`):

| phase | progress | what happens |
|---|---|---|
| `lift` | 0.05 | straight up, orientation kept, to max(current z, target z + `approach_height_m`); no motion when the TCP is already within 1 mm of that height |
| `approach` | 0.2 | straight line to target + `approach_height_m` in z, rotating to the place orientation |
| `descend` | 0.55 | straight down to the place point |
| `open` | 0.75 | gripper `open` (only with `release`) |
| `retreat` | 0.85 | straight up by `approach_height_m` (only with `retreat`) |
| `done` | 1.0 | `state:"done"`; `holding:false` after a release, null otherwise |

Before the ack, outside the lock, lift, approach, descend and retreat are planned in sequence from the commanded state (each from the end of the previous one, retreat with the jaws open when `release`). When the arm holds a spill-safe container (matching `spill_safe_labels`, e.g. cup, bottle, bowl) and the place orientation's tilt from vertical exceeds `spill_max_tilt_deg` (default 8.0°), the orientation is automatically levelled to point straight down (`look_down`), keeping yaw, and the action status records `orientation: "levelled"`. A failure is a `command_reject` with the planner code (`IK_UNREACHABLE`, `IK_BRANCH_FLIP`, `WORKSPACE_VIOLATION` incl. keep-out boxes with `keepout '<name>'` in the message, 422); an unknown `pose` is `POSE_NOT_FOUND` (404); bad fields are `INVALID_COMMAND`. Each phase is planned again from the commanded state when it runs. Place does not use the grasp setup's `table_z_m` or the [table clearance](#table-clearance--桌面间隙): its paths are checked against `workspace.floor_z_m` and the keep-out boxes only, so a place point (or a camera reaching below it) at the table is not rejected.

Execution uses the same orchestration as `grasp` (`src/macro_action.rs`): every motion is a sub-motion of the one `place` record, installed under the lock only while the action is still running, and the cancellation table of [Grasp](#phases--阶段) applies unchanged (`/motion/stop` → `cancelled` / `STOPPED`, new motion → `SUPERSEDED`, lease → `LEASE_LOST`, E-stop / Fault / watchdog → `failed`). Servo frames are rejected with `MOTION_BUSY` for the whole action. A sub-motion longer than its planned duration × 2 + 5 s (gripper: expected duration + 10 s), capped at 60 s, or the whole action longer than 2 × `expected_duration_s` + 20 s, stops the motion and ends as `PLACE_TIMEOUT`. Sub-motion failures (`TRACKING_STALL`, `GRIPPER_TIMEOUT`, planner codes) end the action with that code.

应答前在锁外按顺序规划抬升、接近、下降和撤离（每段从上一段终点开始；`release` 时撤离段按夹爪张开规划）。当机械臂夹持防倾洒容器（匹配 `spill_safe_labels`，如杯子、瓶子、碗）且放置姿态相对竖直方向的倾角超出 `spill_max_tilt_deg`（默认 8.0°）时，自动将放置姿态调平为竖直向下（`look_down`，保持偏航），并在动作状态记录 `orientation: "levelled"`。规划失败直接 `command_reject`（`IK_UNREACHABLE` / `IK_BRANCH_FLIP` / `WORKSPACE_VIOLATION`，含禁入盒，消息中带 `keepout '<name>'`，422）；`pose` 不存在返回 `POSE_NOT_FOUND`（404）；参数错误返回 `INVALID_COMMAND`。执行时每个阶段从当前指令位置重新规划。放置不使用抓取设置的 `table_z_m`，也不做[桌面间隙](#table-clearance--桌面间隙)检查：路径只按 `workspace.floor_z_m` 和禁入盒检查，放置点（或低于放置点的相机）贴近桌面时不会被拒绝。

阶段：`lift` 沿竖直方向抬升到 max(当前 z, 目标 z + `approach_height_m`)，已在该高度 1 mm 内则不运动；`approach` 直线移动到目标上方 `approach_height_m` 处并转到放置姿态（指定姿态、命名姿态的姿态或当前姿态）；`descend` 竖直下降到放置点；`open` 张开夹爪（仅 `release`）；`retreat` 竖直上升 `approach_height_m`（仅 `retreat`）；`done`。速度为 `move_to` 默认值（0.05 m/s、0.5 rad/s）乘以 `speed_scale`，再受 profile `speed_cap` 限制。执行与 `grasp` 共用编排模块（`src/macro_action.rs`），取消规则相同：`/motion/stop` 为 `cancelled` / `STOPPED`，新运动为 `SUPERSEDED`，租约丢失为 `LEASE_LOST`，急停 / 故障 / 看门狗为 `failed`。单个子运动超过规划时长 × 2 + 5 s（夹爪为预计时长 + 10 s，上限 60 s），或整个动作超过 2 × `expected_duration_s` + 20 s，停止运动并以 `PLACE_TIMEOUT` 结束。`release:false` 时夹爪保持原指令位置，`holding` 为 null。

Example / 示例:

```json
{"type":"command", "request_id":52, "generation":7, "epoch_id":3, "path":"/api/v1/action/place",
 "body":{"pose":"bin_a", "approach_height_m":0.06, "tag":"drop"}}
```

```json
"action": {"id":10, "kind":"place", "tag":"drop", "state":"running", "phase":"descend", "progress":0.55,
           "code":null, "holding":null, "iteration":null, "error_px":null, ...}
```

## Replay / 回放

Replays a saved episode (see the README, "Episode recording"). Episode files are managed over REST without a lease, like the other `/api/v1/dataset/*` routes; they move nothing. Browser requests must be same-origin (`DELETE` included).

| Route | Returns |
|---|---|
| `GET /api/v1/dataset/episodes` | `{"enabled", "dir", "episodes":[{"id", "frames", "duration_s", "size_bytes", "created_ms", "dof", "joint_min":[dof], "joint_max":[dof], "error"?, "dataset", "task", "source", "stale"}], "total_bytes", "max_bytes", "max_files"}`, newest first: the episodes of the store. `created_ms` is the start of the recording (Unix ms). `error` is set for a file that cannot be read. |
| `DELETE /api/v1/dataset/episodes/{id}` | `{"status":"deleted", "episode_id"}`; `404 EPISODE_NOT_FOUND`, `400 INVALID_EPISODE_ID`, `409 IN_USE` (referenced by a sequence) |

WS command (lease, epoch, `request_id` as for every action):

```json
{"type":"command", "request_id":9, "generation":1, "epoch_id":3,
 "path":"/api/v1/action/replay", "body":{"episode":"teleop_20261112_101500", "speed":0.5, "gripper":true, "tag":"demo"}}
```

- `episode` (required): episode id, `^[A-Za-z0-9_-]{1,64}$` (an id of the [episode store](#teach-v1-episodes-recording-sequences--示教-v1片段录制序列)). `speed`: `0.5` (default) or `1.0`, a fraction of the recorded speed. `gripper` (default true): replay J7; false holds J7 at its current command. `allow_stale` (default false): replay an episode recorded with another joint zero (else `409 DATA_STALE`). `tag` as for other actions.
- The ack carries `action_id` and `expected_duration_s` (approach + recorded duration / speed + 0.5 s).
- The episode file is read and checked on a blocking thread without the supervisor lock. Then, under the lock, epoch, workspace revision, busy rules and the commanded positions (< 1e-4 rad) are checked again (`PLAN_STALE` / the busy codes), the approach is planned and the action starts.

Checks before any motion (rejection, no motion):

| Check | Code (status) |
|---|---|
| fewer than 2 frames, or no time span | `REPLAY_EMPTY` (422) |
| a frame's `observation.state` length differs from the profile's joint count | `REPLAY_JOINT_COUNT` (422) |
| non-finite angle, timestamps not finite and non-decreasing, unreadable file | `REPLAY_INVALID_EPISODE` (422) |
| recorded duration over 600 s | `REPLAY_TOO_LONG` (422) |
| any frame outside the joint soft limits (J7 only with `gripper`) | `SOFT_LIMIT_EXCEEDED` (400) |
| per-joint speed of the resampled recording × `speed` above the planned-motion limit (`planning_limits()`: `planned_max_velocity` × `speed_cap.joint_velocity_scale`, 0.45 rad/s on rebot-dm; the J7 joint limit for the gripper). The message names the joint, the speed, the time and the highest playback speed that passes. The recording is not clipped. | `REPLAY_TOO_FAST` (422) |
| any resampled frame against the workspace rule of planned motions (baseline = the commanded pose at the request), and the keep-out sweep over the frames (at most 4000 added FK evaluations) | `WORKSPACE_VIOLATION` (422) |
| file missing; storage off | `EPISODE_NOT_FOUND` (404); `EPISODES_DISABLED` (409) |
| recorded with another joint zero (sidecar `joint_zero`), without `allow_stale` | `DATA_STALE` (409) |
| a recording is running or saving; gravity compensation; another trajectory, servo stream or motion | `MOTION_BUSY` (409) |
| collision hold; E-stop; fault; not armed | `COLLISION_HOLD` (409); `ESTOP_ACTIVE`; `FAULT_ACTIVE`; `NOT_ARMED` |

Execution:

1. `observation.state` is resampled by timestamp to the control rate (`control_frequency_hz`, linear between frames).
2. Approach: a joint-space quintic from the commanded pose to frame 0 at the planned-motion limits, checked like a jog (joint limits, 21 workspace samples, keep-out sweep).
3. Replay: each tick advances the recording time by dt × `speed` × rate, with the lag-aware rate of planned paths (full speed below 0.38 rad lag on J1–J6, stop at 0.45 rad). A rate at or below 0.1 for 1 s ends the action `failed` / `TRACKING_STALL` with commanded = measured (no Fault).
4. Settle at the last frame, as for other actions (`settled`).

Gripper with `gripper: true`: J7 follows the recording; while the stall latch holds the jaw (|τ7| high, jaw still), a recorded command further into the stall is held and a command in the opposite direction releases the latch (the servo / jog rule).

Action record: `kind` `replay`, `episode`, `phase` (`approach` → `replay` → `settle`), `t_s` (recording time reached, s; 0 during the approach), `progress` (`t_s` / recorded duration). Stop, E-stop, collision trip, fault, watchdog and lease loss end it with the codes of the table in [Action status](#action-status--动作状态); on lease loss (release, preemption, closed connection) armd also stops the replay reference, so the arm brakes and holds.

保存的录制片段可回放（录制见 README「示教片段录制」）。片段文件通过 REST 管理，与其他 `/api/v1/dataset/*` 路由一样无需租约（不产生运动）；浏览器请求（含 `DELETE`）须同源。`GET /api/v1/dataset/episodes` 按时间倒序返回片段（帧数、时长、大小、保存时间、各关节范围；无法读取的文件带 `error`）；`DELETE /api/v1/dataset/episodes/{id}` 删除片段，不存在返回 `404 EPISODE_NOT_FOUND`，id 不合法返回 `400 INVALID_EPISODE_ID`。

WS 指令 `/api/v1/action/replay`（需租约与 epoch）：`episode` 必填（`^[A-Za-z0-9_-]{1,64}$`，片段存储中的 id）；用其他关节零位录制的片段返回 `409 DATA_STALE`，除非 `allow_stale: true`；`speed` 为 `0.5`（默认）或 `1.0`，相对录制速度；`gripper`（默认 true）回放 J7，false 时 J7 保持当前指令。ack 带 `action_id` 与 `expected_duration_s`。片段在阻塞线程中读取与检查，不持有监督器锁；安装前在锁内再次检查 epoch、工作空间版本、忙碌条件和指令位置（`PLAN_STALE` 或对应忙碌码）。

运动前的检查（不通过则拒绝，不运动）：帧数少于 2 或没有时长 `REPLAY_EMPTY`；关节数与 profile 不符 `REPLAY_JOINT_COUNT`；非有限值、时间戳非有限或递减、文件无法读取 `REPLAY_INVALID_EPISODE`；时长超过 600 s `REPLAY_TOO_LONG`；任一帧超出关节软限位（J7 仅在 `gripper` 时检查）`SOFT_LIMIT_EXCEEDED`；重采样后各关节速度 × `speed` 超过规划运动限速（`planning_limits()`，rebot-dm 为 0.45 rad/s；夹爪用 J7 关节限位）`REPLAY_TOO_FAST`，消息给出关节、速度、时刻与可通过的最高回放速度，不对录制做削峰；每个重采样帧按规划运动的工作空间规则检查（基准为请求时的指令位姿），并对禁入盒做扫掠检查（最多追加 4000 次 FK）`WORKSPACE_VIOLATION`；文件不存在 `EPISODE_NOT_FOUND`；存储关闭 `EPISODES_DISABLED`；录制进行或保存中、重力补偿中、其他轨迹 / servo 流 / 运动进行中 `MOTION_BUSY`；碰撞保护中 `COLLISION_HOLD`；急停、故障、未使能为对应错误码。

执行：按时间戳把 `observation.state` 线性重采样到控制频率；先以规划运动限速用关节空间五次多项式移动到第 0 帧（与 jog 相同的检查）；之后每个周期按 dt × `speed` × rate 推进录制时间，rate 与规划路径相同（J1–J6 滞后低于 0.38 rad 全速，0.45 rad 停止），rate ≤ 0.1 持续 1 s 结束为 `failed` / `TRACKING_STALL`，指令设为实测位置，不进入 Fault；最后在末帧做到位确认。`gripper: true` 时 J7 跟随录制；夹爪卡滞锁存期间，继续向卡滞方向的指令保持不动，反向指令解除锁存（与 servo / jog 规则相同）。动作记录：`kind` 为 `replay`，带 `episode`、`phase`（`approach` → `replay` → `settle`）、`t_s`（已回放到的录制时间，接近阶段为 0）与 `progress`。停止、急停、碰撞、故障、看门狗和租约丢失按“动作状态”一节的错误码结束；租约丢失（释放、被接管、连接关闭）时 armd 同时停止回放参考轨迹，机械臂制动并保持。

## Teach v1: episodes, recording, sequences / 示教 v1：片段、录制、序列

`capabilities.teach` = `{"version": 1, "episodes": true, "sequences": true}` (capabilities version 11; absent on older armd). `GET` routes need no lease; WS commands use the [message](#message--消息) format with `request_id`. Tests: `tests/test_teach_episodes.rs`, `tests/test_teach_sequences.rs` (mock follower); not yet run on the arm.

### Episode store / 片段存储

- One immutable episode = `<dir>/<id>.parquet` + `<dir>/<id>.json` (sidecar) in the episode directory (`--episodes-dir`, default `/userdata/rebot-teleop/episodes`). New ids are ULIDs (26 characters, Crockford base32); episodes recorded before teach v1 keep their id.
- Parquet columns: `timestamp` (float64, armd monotonic s), `observation.state` (list<float32>, measured joint angles, rad), `action` (list<float32>, commanded, rad). The frames are the measured control-tick samples, not resampled. The footer also carries the sidecar (key `rebot.episode`).
- Sidecar: `{id, dataset, task, source, sequence_id?, repeat_index?, outcome, recorded_at, duration_s, frames, joint_names, units: "rad", joint_zero: {offsets_rad, rev}, profile_id, armd_version, fps_nominal}` plus `truncated` (stopped at 600 s), `stopped_by` (`max_duration` | `low_space`), `arm_dof`, `gripper_joint`, `first_state`, `last_state`, `recovered`. `source` is one of `hand_guide`, `jog`, `servo`, `replay`, `sequence`, `import`, `sdk`; `outcome` `ok` | `aborted`. `joint_zero.rev` is a fingerprint of the offsets (FNV-1a 64 over the f32 bits, 16 hex digits).
- `stale` (in listings): a joint zero offset differs by more than 0.5 deg from the one at capture. Replay and sequence steps refuse stale episodes with `DATA_STALE` unless `allow_stale: true`.
- Write order: `<id>.parquet.tmp`, fsync, rename; then the sidecar (temp + rename); the control tick only appends frames to memory and the files are written on a blocking thread.
- Boot recovery (rule per file): a name containing `.tmp` is deleted; `<id>.parquet` with a readable sidecar is listed; without a sidecar, a parquet whose footer carries one gets it back (`recovered: "sidecar"`); otherwise a readable parquet with a legacy id is adopted (`recovered: "legacy"`, dataset `default`, joint zero of the boot); an unreadable ULID file is deleted when older than 1 h and kept (not listed) otherwise; any other unreadable file is kept and not listed; a sidecar without its parquet is deleted.
- `datasets.json` = `{"datasets": {<name>: {created_at, description}}}`; each episode belongs to one dataset (sidecar `dataset`), default `default`. Dataset names: `^[A-Za-z0-9_\- \p{Han}]{1,64}$`.

| Route | Returns |
|---|---|
| `GET /api/v1/episodes?dataset=&limit=&before=` | `{"enabled", "episodes": [sidecar + "stale" + "bytes"], "recording": {recording_id, owner, dataset, task, started_at, source, frames, elapsed_s, owner_connected} \| null}`, newest first; `before` = an episode id (the page after it) |
| `GET /api/v1/episodes/{id}` | sidecar + `stale` + `bytes`; `404 EPISODE_NOT_FOUND` |
| `GET /api/v1/episodes/{id}/data` | the parquet file (`application/vnd.apache.parquet`) |
| `GET /api/v1/datasets` | `{"enabled", "datasets": [{name, episodes, duration_s, bytes, created_at, description}]}` |
| `POST /api/v1/episodes/import` | multipart `parquet` + `sidecar` -> `{id, stale, episode}` \| `422 IMPORT_INVALID {reason}` |

WS commands without a lease (`request_id` required, no `generation` / `epoch_id`):

| Path | Body | Ack fields / errors |
|---|---|---|
| `/api/v1/episodes/update` | `{id, task?, dataset?}` | `episode`; `EPISODE_NOT_FOUND`, `DATASET_NOT_FOUND` |
| `/api/v1/episodes/delete` | `{id}` | `deleted`; `IN_USE {sequences}` when a sequence references it |
| `/api/v1/datasets/create` | `{name, description?}` | `dataset`; `DATASET_EXISTS` |
| `/api/v1/datasets/delete` | `{name, force?}` | `deleted_episodes`; `DATASET_NOT_EMPTY` without `force`; `IN_USE` when one of its episodes is referenced |

Import checks (`reason`): `multipart`, `sidecar`, `schema` (columns / types), `units` (only `rad`; convert `deg` / `so101_norm` first), `joint_names` / `joint_order` (must equal the profile's joints in order), `profile`, `dof`, `empty`, `timestamps`, `too_long` (> 600 s), `non_finite`, `soft_limit` (every `observation.state` and `action` value within the joint soft limits). A different joint zero is not refused: the episode is stored with `stale: true`; a sidecar without `joint_zero` counts as stale. The stored copy gets a new id and `source: "import"`; an unknown dataset is created. Body limit 64 MB.

### Recording ownership / 录制归属

Recording has an owner that is separate from the motion lease, so a page can record next to a teleop lease holder.

- WS `/api/v1/record/start {dataset?, task?, source?}` (no lease) -> `{recording_id, owner}`. `owner` = the connection's `client_id` (message field `client_id`, else the label of the lease this connection holds; `INVALID_COMMAND` without one). One recording at a time: `RECORDER_BUSY {owner}`.
- WS `/api/v1/record/stop {save: bool, outcome?}` -> `{episode}` | `{discarded: true}`; only the owner (`RECORDER_NOT_OWNER {owner}`).
- The owner's connection closes: the recording is discarded after 5 s, unless a connection with the same `client_id` sends `record/stop` within those 5 s (it takes the recording back).
- Legacy REST `POST /api/v1/dataset/record/start|save|discard`, `GET /api/v1/dataset/episodes`, `DELETE /api/v1/dataset/episodes/{id}` use the same store with owner `legacy-rest`; `episode_id` / `output_path` still set a legacy id, without them the id is a ULID.
- Disk guard: `507 RECORD_NO_SPACE` when the episode file system has less than 200 MB free at the start; a running recording is stopped and saved (`stopped_by: "low_space"`) below 100 MB. Length cap 600 s: the tick stops appending at the cap and the recording is saved with `truncated: true`. Both checks run in a monitor task (every 200 ms, free space every 1 s), not in the control loop.

### Sequences / 序列

`sequences.json` (`ARMD_SEQUENCES`, default `/userdata/rebot-teleop/sequences.json`) holds `{"sequences": [{id (ULID), name, description, steps, created_at, updated_at, rev}]}`. Steps (at most 200):

| Step | Fields |
|---|---|
| `pose` | `pose_id`, `speed_scale` 0.1..1.0 (default 1.0), `gripper` `keep` (default) \| `pose` |
| `gripper` | `action` `open` \| `close` \| `move`, `fraction` 0..1 (move only) |
| `wait` | `s` 0..60 |
| `replay` | `episode_id`, `speed` 0.5 (default) \| 1.0, `gripper` (default true) |

Poses carry an `id` (ULID; assigned on load to poses saved before ids and written back; stable across a rename with `poses/save {id, name}`). Deleting a pose or an episode that a sequence references is `409 IN_USE {sequences}`.

- `GET /api/v1/sequences`, `GET /api/v1/sequences/{id}`: the stored fields plus `stale_steps`, `missing_steps` (indices) and `running`.
- WS `/api/v1/sequences/save {id?, name, description?, steps, rev?}` (lease, like `poses/save`) -> `{sequence}`. Without `id` a new sequence; with `id` an update, `rev` (if given) must equal the stored one (`SEQUENCE_CONFLICT {rev}`). Names `^[A-Za-z0-9_\- \p{Han}]{1,64}$`, unique (`SEQUENCE_EXISTS`). A missing pose / episode: `422 SEQUENCE_REF_MISSING {step}`; other step errors `INVALID_COMMAND {step}`.
- WS `/api/v1/sequences/delete {id}` (lease); `SEQUENCE_RUNNING` while it runs.

Action `/api/v1/action/run_sequence {id, from_step?: 0, single_step?: false, repeat?: 1 (1..100), record?: {dataset, task?}, allow_stale?: false, tag?}` -> ack `{action_id, expected_duration_s}`. One parent action of kind `sequence` with `sequence_id`, `step_index` (0-based index in the sequence), `step_type`, `repeat_index` (0-based), `repeats`, `phase` (the step type; replay steps show `approach` / `replay` / `settle`), `progress` (steps done / steps × repeats), with `record` `episodes` (ids saved so far), and `failed_step` (the step that was running) when the run ended without finishing. The action's `id` is the action id; the sequence id is `sequence_id`.

- At the start the poses are copied and the episodes pinned: a pose saved during the run does not change it; pinned items cannot be deleted. Refused at the start: `SEQUENCE_NOT_FOUND`, `SEQUENCE_REF_MISSING {step}`, `DATA_STALE {steps}` (a pose marked stale by a joint zero change, an episode recorded with another joint zero) unless `allow_stale`, `RECORDER_BUSY` with `record`, and the usual action preconditions.
- Before every motion step (pose, gripper, replay): epoch, workspace revision, calibration revision (joint zero, kinematic correction) and lease are compared with the start: `PLAN_STALE`, `CALIBRATION_CHANGED`, `LEASE_LOST`.
- Stop, lease loss, collision, fault, e-stop and any step failure, planning refusals included (`IK_*`, `WORKSPACE_VIOLATION`, `REPLAY_TOO_FAST`, ...), end the parent with that code, also during a wait (checked every 20 ms). No step is skipped.
- Pose step: joint-space quintic at the planned-motion limits × `speed_scale` (gripper kept unless `gripper: pose`), done once settled. Gripper steps as the gripper action (`close` detects holding). Replay steps as `/api/v1/action/replay`, checked without the lock.
- `record`: the run owns the recorder; one episode per repeat (`source: "sequence"`, `sequence_id`, `repeat_index`, task = `record.task` or the sequence name), started before the repeat's first step and saved after its last step. The episode of an aborted repeat is discarded; finished repeats are kept.
- `expected_duration_s` is an upper bound without power-budget slowdowns: per pose step the quintic from the previous target plus the 2 s settle limit, gripper steps their expected duration + 1 s, waits, replays the approach to the first recorded frame + recorded duration / speed + 0.5 s, 1 s per recorded repeat, + 1 s. The run fails `SEQUENCE_TIMEOUT` after twice the bound + 30 s.

`capabilities.teach` = `{"version": 1, "episodes": true, "sequences": true}`（capabilities 版本 11；旧版 armd 没有该字段）。`GET` 路由无需租约；WS 指令沿用[消息](#message--消息)格式并带 `request_id`。测试见 `tests/test_teach_episodes.rs`、`tests/test_teach_sequences.rs`（mock follower），尚未在机械臂上运行。

**片段存储。** 每个片段不可修改，由片段目录下的 `<id>.parquet` 与 `<id>.json`（sidecar）组成；新片段 id 为 ULID（26 个 Crockford base32 字符），teach v1 之前录制的片段保留原 id。Parquet 列：`timestamp`（float64，armd 单调时钟秒）、`observation.state`（list<float32>，实测关节角，rad）、`action`（list<float32>，指令，rad），保存的是控制周期的实测采样，不重采样；文件尾部的元数据也带一份 sidecar（键 `rebot.episode`）。sidecar 字段：`id, dataset, task, source, sequence_id?, repeat_index?, outcome, recorded_at, duration_s, frames, joint_names, units: "rad", joint_zero: {offsets_rad, rev}, profile_id, armd_version, fps_nominal`，另有 `truncated`、`stopped_by`、`arm_dof`、`gripper_joint`、`first_state`、`last_state`、`recovered`。`source` 取 `hand_guide`、`jog`、`servo`、`replay`、`sequence`、`import`、`sdk`；`joint_zero.rev` 为零位偏置的指纹（f32 位模式的 FNV-1a 64，16 位十六进制）。列表中的 `stale` 表示某关节零位偏置与录制时相差超过 0.5°；回放与序列步骤遇到过期片段返回 `DATA_STALE`，除非传 `allow_stale: true`。写入顺序：`<id>.parquet.tmp` → fsync → 重命名，再写 sidecar（临时文件 + 重命名）；控制周期只把帧追加到内存，文件在阻塞线程中写。启动恢复规则（逐个文件）：名称含 `.tmp` 的删除；有可读 sidecar 的 `<id>.parquet` 列出；没有 sidecar 时，尾部带 sidecar 的 parquet 恢复 sidecar（`recovered: "sidecar"`）；否则可读的旧 id 片段被收编（`recovered: "legacy"`，数据集 `default`，零位取启动时的值）；无法读取的 ULID 文件超过 1 小时删除，否则保留且不列出；其他无法读取的文件保留且不列出；没有 parquet 的 sidecar 删除。`datasets.json` 为 `{"datasets": {<名称>: {created_at, description}}}`，每个片段属于一个数据集，默认 `default`；数据集名称须匹配 `^[A-Za-z0-9_\- \p{Han}]{1,64}$`。REST：`GET /api/v1/episodes?dataset=&limit=&before=`（倒序，含 `stale`、`bytes` 与当前录制 `recording`）、`GET /api/v1/episodes/{id}`、`GET /api/v1/episodes/{id}/data`（parquet 文件）、`GET /api/v1/datasets`、`POST /api/v1/episodes/import`。无需租约的 WS 指令：`/api/v1/episodes/update {id, task?, dataset?}`、`/api/v1/episodes/delete {id}`（被序列引用时 `IN_USE {sequences}`）、`/api/v1/datasets/create {name, description?}`、`/api/v1/datasets/delete {name, force?}`（非空且无 `force` 时 `DATASET_NOT_EMPTY`）。

**导入检查**（`IMPORT_INVALID` 的 `reason`）：`multipart`、`sidecar`、`schema`（列与类型）、`units`（只接受 `rad`，`deg` / `so101_norm` 须先转换）、`joint_names` / `joint_order`（须与 profile 关节及顺序一致）、`profile`、`dof`、`empty`、`timestamps`、`too_long`（超过 600 s）、`non_finite`、`soft_limit`（每个 `observation.state` 与 `action` 值都须在关节软限位内）。零位不同不拒绝，片段以 `stale: true` 保存；sidecar 没有 `joint_zero` 时视为过期。保存的副本使用新 id 与 `source: "import"`，未知数据集自动创建；请求体上限 64 MB。

**录制归属。** 录制的归属与运动租约分开，网页可以在遥操作持有租约时录制。WS `/api/v1/record/start {dataset?, task?, source?}`（无需租约）返回 `{recording_id, owner}`（`GET /api/v1/episodes` 的 `recording` 另带 `dataset`、`task`、`started_at`），`owner` 为该连接的 `client_id`（消息中的 `client_id`，否则为该连接所持租约的标签；都没有时 `INVALID_COMMAND`）；同一时间只有一个录制，`RECORDER_BUSY {owner}`。`/api/v1/record/stop {save, outcome?}` 返回 `{episode}` 或 `{discarded: true}`，只有归属者可以停止（`RECORDER_NOT_OWNER {owner}`）。归属者的连接断开 5 s 后丢弃录制，除非 5 s 内同一 `client_id` 的连接发出 `record/stop`（取回录制）。旧 REST 路由 `/api/v1/dataset/record/start|save|discard`、`GET/DELETE /api/v1/dataset/episodes` 使用同一存储，归属者为 `legacy-rest`；给出 `episode_id` / `output_path` 时仍使用旧 id，否则为 ULID。磁盘保护：开始时空闲空间少于 200 MB 返回 `507 RECORD_NO_SPACE`；录制中低于 100 MB 时停止并保存（`stopped_by: "low_space"`）。长度上限 600 s：到达上限时控制周期停止追加，录制以 `truncated: true` 保存。这两项检查在监控任务中运行（每 200 ms，空闲空间每 1 s），不在控制循环中。

**序列。** `sequences.json`（`ARMD_SEQUENCES`，默认 `/userdata/rebot-teleop/sequences.json`）保存 `{"sequences": [{id, name, description, steps, created_at, updated_at, rev}]}`，最多 200 步：`pose {pose_id, speed_scale 0.1..1.0, gripper keep|pose}`、`gripper {action open|close|move, fraction}`、`wait {s 0..60}`、`replay {episode_id, speed 0.5|1.0, gripper}`。姿态带 `id`（ULID，旧文件加载时分配并写回，用 `poses/save {id, name}` 改名时不变）；删除被序列引用的姿态或片段返回 `409 IN_USE {sequences}`。`GET /api/v1/sequences`、`GET /api/v1/sequences/{id}` 另带 `stale_steps`、`missing_steps` 与 `running`。WS `/api/v1/sequences/save {id?, name, description?, steps, rev?}`（需租约）：带 `id` 时为更新，给出的 `rev` 与存储不一致返回 `SEQUENCE_CONFLICT {rev}`；名称唯一（`SEQUENCE_EXISTS`）；引用不存在 `422 SEQUENCE_REF_MISSING {step}`。`/api/v1/sequences/delete {id}` 运行中返回 `SEQUENCE_RUNNING`。

动作 `/api/v1/action/run_sequence {id, from_step?, single_step?, repeat? 1..100, record?: {dataset, task?}, allow_stale?, tag?}` 的 ack 带 `action_id` 与 `expected_duration_s`。一个类型为 `sequence` 的父动作，带 `sequence_id`、`step_index`（序列中从 0 开始的下标）、`step_type`、`repeat_index`（从 0 开始）、`repeats`、`phase`、`progress`、（录制时）`episodes`，未完成结束时带 `failed_step`（当时运行的步骤）；动作的 `id` 是动作 id，序列 id 在 `sequence_id`。开始时复制姿态并固定片段：运行中保存的姿态不影响本次运行，固定的条目不能删除。开始时拒绝：`SEQUENCE_NOT_FOUND`、`SEQUENCE_REF_MISSING`、`DATA_STALE {steps}`（零位变更后标记过期的姿态、用其他零位录制的片段；`allow_stale` 时放行）、录制时的 `RECORDER_BUSY` 以及常规动作前置条件。每个运动步骤（pose、gripper、replay）前比较 epoch、工作空间版本、标定版本（关节零位、运动学修正）与租约：`PLAN_STALE`、`CALIBRATION_CHANGED`、`LEASE_LOST`。停止、租约丢失、碰撞、故障、急停以及任一步骤失败（包括规划拒绝，如 `IK_*`、`WORKSPACE_VIOLATION`、`REPLAY_TOO_FAST`）都以对应错误码结束父动作，等待期间同样生效（每 20 ms 检查）；不跳过步骤。带 `record` 时序列独占录制器，每次重复一个片段（`source: "sequence"`、`sequence_id`、`repeat_index`，task 为 `record.task` 或序列名），在该次重复第一步前开始、最后一步后保存；中止的那次重复的片段被丢弃，已完成的保留。`expected_duration_s` 为上界（不含功率预算降速）：pose 步骤为自上一目标的五次多项式时长 + 2 s 到位上限，gripper 步骤为预计时长 + 1 s，等待时间，replay 为到首帧的接近 + 录制时长 / 速度 + 0.5 s，每次录制的重复 + 1 s，最后 + 1 s；超过两倍上界 + 30 s 以 `SEQUENCE_TIMEOUT` 结束。

## Gripper zero check and calibration / 夹爪零位检查与标定

The gripper zero check measures the mechanical stall position of the gripper jaws to determine zero offset, and the calibration endpoint configures runtime opening-to-angle mapping.

### Gripper zero check / 零位检查动作

The action `/api/v1/action/gripper_zero_check` never runs automatically. It requires an active control lease and an armed/torqued robot. It is refused with `409 OBJECT_HELD` if the supervisor reports an object is held (`holding`).

- **Command body**: `{"store_offset": bool? (default false), "threshold_rad": float? (default 0.10), "tag": str?}`.
- **Execution**: Closes J7 at 0.3 rad/s toward `closed_rad + 0.6` (bounded inside J7 limits). J7 stops upon latching the stall detector (`GRIPPER_STALL_LATCH_NM` = 0.444 N·m for 6 consecutive ticks). Timeout is 10 s (`GRIPPER_TIMEOUT`).
- **Action status**: Reports `stop_rad` (measured position at stall), `offset_rad` (`stop_rad - base_closed_rad`), and `pass: bool` (`|offset_rad| <= threshold_rad`).
- **Offset persistence**: If `store_offset: true`, `pass: true`, and `|offset_rad| <= 0.5`, the offset is persisted to `gripper_calib.json` (env `ARMD_GRIPPER_CALIB`, default `/userdata/rebot-teleop/gripper_calib.json`) via atomic write, shifting `closed_rad`, `open_rad`, and `jaw_opening` curve points in the active policy. If `|offset_rad| > 0.5`, storing is refused.

零位检查动作 `/api/v1/action/gripper_zero_check` 不会自动运行，需要有效控制租约且机械臂处于使能状态。若机械臂当前处于抓持状态（`holding`），拒绝执行并返回 `409 OBJECT_HELD`。

- **请求体**：`{"store_offset": bool?（默认 false）, "threshold_rad": float?（默认 0.10）, "tag": str?}`。
- **执行过程**：J7 以 0.3 rad/s 向 `closed_rad + 0.6`（受 J7 限位约束）闭合，触发卡滞锁存（连续 6 周期 |τ7| ≥ 0.444 N·m）时停止。超时时间 10 s。
- **动作状态**：报告 `stop_rad`（停止时的实测角度）、`offset_rad`（相对基准闭合角的偏差）以及 `pass: bool`（`|offset_rad| <= threshold_rad`）。
- **偏差持久化**：若 `store_offset: true`、`pass: true` 且 `|offset_rad| <= 0.5`，偏差原子写入 `gripper_calib.json`（环境变量 `ARMD_GRIPPER_CALIB`，默认 `/userdata/rebot-teleop/gripper_calib.json`），并同步平移当前策略中的 `closed_rad`、`open_rad` 和 `jaw_opening` 各点。若 `|offset_rad| > 0.5` 则拒绝保存。

### Observation field / 观测字段

7-DOF profiles with a gripper policy publish `observation.gripper_zero`:
```json
"gripper_zero": {
  "state": "ok",
  "j7": -0.02,
  "offset_rad": 0.0
}
```
- `state`:
  - `"ok"`: passive boot check passed (J7 is within `[open_rad - 0.3, closed_rad + 0.3]`).
  - `"out_of_range"`: J7 is outside the valid range during passive boot check.
  - `"checked"`: an active zero check action completed successfully.
  - `"calib_invalid"`: startup load detected a corrupt or invalid `gripper_calib.json` (the file is ignored and runtime policy remains unshifted).
- `j7`: current measured J7 angle (rad).
- `offset_rad`: currently active calibration offset (from persisted file or latest zero check).

带有夹爪策略的 7 轴机械臂发布 `observation.gripper_zero`：
- `state`：`"ok"`（被动开机检查通过，J7 处于 `[open_rad - 0.3, closed_rad + 0.3]` 范围内）；`"out_of_range"`（开机位置超出合理范围）；`"checked"`（已完成主动零位检查）；`"calib_invalid"`（启动时读取到损坏或无效的标定文件，忽略该文件并保持基准策略）。
- `j7`：当前 J7 实测关节角（rad）。
- `offset_rad`：当前生效的标定偏差。

### Runtime calibration endpoint / 运行时标定接口

- **WS command** `/api/v1/gripper/calibration` (lease required):
  ```json
  {"type":"command", "request_id":12, "generation":1, "epoch_id":1,
   "path":"/api/v1/gripper/calibration",
   "body":{"offset_rad":0.02, "jaw_opening":{"points":[[0.0,0.0],[-5.0,0.08]], "calibrated":true}}}
  ```
  Validates that `jaw_opening` is monotonic, has ≥ 2 points, J7 angles lie within joint limits, and openings are in [0, 0.2] m. Validates `|offset_rad| <= 0.5`. Invalid input is rejected with `400 INVALID_COMMAND`. On success, atomically saves to `gripper_calib.json` and replies with `command_ack` carrying the effective policy (`closed_rad`, `open_rad`, `jaw_opening`, `persisted: true`).
- **REST** `GET /api/v1/gripper/calibration` (no lease required):
  Returns `{"offset_rad": float?, "jaw_opening": {...}?, "calibrated": bool, "policy": {...}?, "ts": float?}` allowing inspection tools to read current calibration without acquiring control.

- **WS 指令** `/api/v1/gripper/calibration`（需租约）：验证 `jaw_opening` 单调递增、至少 2 个点、角度在 J7 限位内、开度在 [0, 0.2] m 范围内；验证 `|offset_rad| <= 0.5`。不合法输入返回 `400 INVALID_COMMAND`。成功后原子写入 `gripper_calib.json` 并在 `command_ack` 中返回生效的完整策略。
- **REST** `GET /api/v1/gripper/calibration`（无需租约）：返回当前生效的标定配置与策略，供工具读取。

## Gravity compensation mode / 重力补偿模式

Verified on the reBot B601-DM (see the README). Full contract: [control_safety_contract.md](control_safety_contract.md#gravity-compensation-hand-guiding--重力补偿拖动示教).

```json
{"type":"command","request_id":7,"generation":1,"epoch_id":42,"path":"/api/v1/mode/gravity_comp","body":{"enable":true,"scale":1.0,"damping_kd":0.5}}
{"type":"command_ack","request_id":7,"status":"accepted","control_mode":"gravity_comp", ...}
{"type":"command","request_id":8,"generation":1,"epoch_id":42,"path":"/api/v1/mode/gravity_comp","body":{"enable":false}}
```

- `enable` (bool, required). `scale` (optional, within the profile's `scale_range`, rebot-dm 0.5–1.2) multiplies the model torque. `damping_kd` (optional) is one number for J1–J6 or six numbers, each 0 ≤ kd ≤ `damping_kd_max` (2.0). Out-of-range values: `400 INVALID_COMMAND`.
- `enable: true` while the mode is on is accepted without change; `enable: false` while it is off is accepted and does nothing.
- The ack does not mean the arm floats yet: follow `observation.gravity_comp.phase` (`ramp_in` → `active`). After `enable: false`, `control_mode` returns to `position` once the switch back to POS_VEL is confirmed (about 100 ms).
- Before sending, `observation.gravity_comp.blocker` gives the code the entry would be refused with (null when it would be accepted).
- While the mode is on: servo frames, `motion/jog`, `motion/home`, presets, `motion/unload`, `torque`, `move_to`, `move_relative` and `grasp` return `409 MOTION_BUSY`; `motion/stop` and E-stop end the mode; `action/gripper` works; recording (REST) works.
- `POST /api/v1/mode/gravity_comp` over REST returns `409 LEASE_REQUIRED` / `LEASE_ACTIVE` and does nothing.
- Why the mode ended: `observation.gravity_comp.last_exit.code` (see the contract for the list).

已在 reBot B601-DM 上实机验证（见 README）。完整契约见 [control_safety_contract.md](control_safety_contract.md#gravity-compensation-hand-guiding--重力补偿拖动示教)。`enable` 必填；`scale` 可选，须在 profile 的 `scale_range` 内（rebot-dm 为 0.5–1.2）；`damping_kd` 可选，一个数（J1–J6 共用）或六个数，每个 0 ≤ kd ≤ `damping_kd_max`（2.0），越界返回 `400 INVALID_COMMAND`。应答不代表已经漂浮，请看 `observation.gravity_comp.phase`（`ramp_in` → `active`）；`enable: false` 后切回 POS_VEL 确认（约 100 ms）时 `control_mode` 变回 `position`。发送前可读 `observation.gravity_comp.blocker`，得到会被拒绝的错误码（可进入时为 null）。模式开启时 servo 帧、`motion/jog`、`motion/home`、预设、`motion/unload`、`torque`、`move_to`、`move_relative`、`grasp` 返回 `409 MOTION_BUSY`；`motion/stop` 与急停结束本模式；`action/gripper` 与录制（REST）可用。REST 的 `POST /api/v1/mode/gravity_comp` 返回 `409 LEASE_REQUIRED` / `LEASE_ACTIVE`，不执行。模式结束原因见 `observation.gravity_comp.last_exit.code`。

## Diagnostics / 诊断

Read-only, no lease, `GET` only. They read the files armd writes under `--blackbox-dir`
(default `/userdata/rebot-teleop/blackbox`), which survive a reboot or power cut. Responses are
JSON, at most 2 MB (older lines are cut first, `truncated: true`). Without a black-box
directory both return `enabled: false` and empty lists.

| Path | Returns |
|---|---|
| `/api/v1/diagnostics/boots` | `{"enabled", "boot", "truncated", "boots": [...]}`: one entry per armd start, oldest first |
| `/api/v1/diagnostics/blackbox?seconds=N` | `{"enabled", "boot", "current_boot", "seconds", "truncated", "records": [...]}`: this start's records of the last N seconds (default 60, max 3600), oldest first |
| `/api/v1/diagnostics/blackbox?seconds=N&prev=1` | the same for the previous start: the seconds before the last reset or restart |
| `/api/v1/diagnostics/tick` | `{"window", "tick_us": {"p50","p99","max"}, "lock_us": {...}, "late_count", "since_boot_ticks"}` over the last 1000 control ticks (in memory, works without a black-box directory) |
| `/api/v1/diagnostics/power` | supply-current estimate, 5 s / 60 s peaks and governor state (in memory, see [Power budget](#power-budget--电源功率预算)) |

Boot entry (`boots.log`): `boot` (start counter, persisted in `boot_count`), `uptime_s` (kernel
uptime at armd start), `kernel_boot_id`, `same_kernel_boot` (false: the kernel booted since the
previous armd start; true: armd restarted without a reboot; null: unknown), `reset_reason` (SG2002
`cvi-base` power-on reason: `cold_boot`, `watchdog`, `suspend`, `warm_reset`; null when not
available; the driver reports unknown causes as `cold_boot`), `armd_version`, `prev_last` (the
last black-box record of the previous start, or null).

Black-box record (`bb.jsonl`): `boot`, `t_ms` (monotonic ms since armd start), `safety_state`,
`is_torqued`, `enable_state`, `lease_holder`, `control_mode`, `positions`,
`commanded_positions`, `velocities`, `torques`, `temperatures` (3 decimals), `feedback_valid`,
`feedback_age_ms`, `motor_errors`, `motion_limit`, `residual_torques` (3 decimals or null), `collision` (the observation field; omitted while null), `power` (`{"a": estimated supply current, "pk": its 5 s peak (A, 2 decimals), "s": governor scale, "hold": true only during a power hold}`; omitted without an estimate), `action` (latest action as `kind:state`),
`dropped` (samples dropped so far because the writer was busy). Rate: 5 Hz while torqued or a
joint moves faster than 0.05 rad/s, otherwise one line every 5 s. Each line is `fdatasync`ed
while torqued. Files: `bb.jsonl` rotated at 2 MiB, six old files kept (`.1` … `.6`); about 75 min
at 5 Hz (about 656 B per line, measured on the arm), about 30 h idle. The 2 MB response cap
holds about 10 min of 5 Hz records; request a shorter window to get it untruncated. armd has no CAN error counters, so the record carries none.

Tick timing: `tick_us` is the whole `ArmSupervisor::tick` call (waiting for the supervisor lock, the tick body and the telemetry broadcast), `lock_us` the time the tick holds the supervisor write lock, both in µs (nearest-rank percentiles). `late_count` counts ticks since start whose `dt` exceeded two control periods.

只读，无需租约，仅 `GET`。读取 armd 写在 `--blackbox-dir`（默认
`/userdata/rebot-teleop/blackbox`）下的文件，重启或断电后仍在。响应为 JSON，最大 2 MB（超出时先丢
最旧的行，`truncated: true`）。没有黑匣子目录时两者都返回 `enabled: false` 和空列表。`boots` 每次
armd 启动一条（含上一次启动的最后一条记录 `prev_last`、内核 `uptime_s`、`same_kernel_boot`、
SG2002 上电原因 `reset_reason`）；`blackbox?seconds=N` 返回本次启动最近 N 秒（默认 60，最大
3600）的记录，`&prev=1` 返回上一次启动的记录，即复位或重启前的那几秒。记录字段与采样率见上文英文部分。`/api/v1/diagnostics/tick` 返回最近 1000 个控制周期的耗时（`tick_us` 为整个周期调用，`lock_us` 为持有监督器写锁的时间，单位 µs）以及启动以来 `dt` 超过两个控制周期的次数 `late_count`。`/api/v1/diagnostics/power` 返回电源电流估算、5 s / 60 s 峰值与调速器状态（内存数据，见「电源功率预算」）；黑匣子记录的 `power` 字段为 `{"a": 估算电源电流, "pk": 5 s 峰值（A，2 位小数）, "s": 调速比例, "hold": 仅功率保持期间为 true}`，无估算时省略。
