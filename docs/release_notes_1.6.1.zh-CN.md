# rebot-armd 1.6.1 发布说明

[English](release_notes_1.6.1.md)

`rebot-armd`，用于 Seeed reCamera（SG2002）与 reBot B601-DM 机械臂。接续 1.6.0。

1.6.1 即 `v1.6.1` 标签，由 `arch/1.6.1` 构建。除标注“真机实测”的内容外，下文结果为主机或仿真结果。本版本的真机检查项见“尚未在真机验证”。

## 新功能

### 驾驶舱

- 连接断开后，租约状态行（手机专家布局下为顶部徽标）显示常驻的“连接已断开 · 正在重连”提示。重试间隔 1、2、4、8 s，之后每 15 s 一次，并显示倒计时和“立即重连”按钮。新连接收到有效观测后，重试计时复位。
- 重连后，驾驶舱显示释放通知和来自最新遥测的机械臂状态。仅当服务端报告机械臂未上电时才显示“已停靠”。不会自动重新接管控制：重新接管是显式操作。
- 已由 Playwright 测试覆盖（长时间断线、反复失败、恢复、看门狗停靠；显式接管前 0 个租约申请帧）。平板在目标浏览器中休眠和唤醒：待真机 / 平板验证（G7）。

### 热点设置

- 新设置 `network.hotspot`（`on` | `off`，默认 `on`），位于 reCamera 控制台的 rebot-teleop 设置。设为 `off` 时，服务不启动设备自身的接入点及其守护进程。服务启动时如果 rebot AP 已在运行，则保持运行，并在日志中说明该设置在重启后生效。设置在服务启动时生效，即重启设备或重启服务之后；运行中的 AP 不会在运行时被停止。固件自带的 AP 不受影响。
- `start` 发现 armd 已在运行时，服务会在日志中说明热点设置在重启后生效。
- 设备上未验证：Wi-Fi station 断开且热点关闭时，通过 USB（`192.168.42.1`）进行 SSH 和访问驾驶舱，包括 USB DHCP（G4）。验证完成前请保留另一种访问设备的方式。

### 拒绝记录

- 通过 WebSocket 发出的命令、预设和伺服拒绝回复会写入 armd 日志。按连接和拒绝代码计：第一次立即记录，之后同一代码最多每 5 s 记录一次，下一行带上被抑制的次数。`STOPPED` 记 DEBUG，其他代码记 WARN。一行包含连接 ID、回复类型、代码、状态和请求 ID（为有效数字时）。线上回复不变。同一连接上超过 64 个不同代码时，共用一个 `OTHER` 桶。

### 抓取

- 自适应策略的 `-top` 候选现在走与旧版 top-down 抓取相同的路径。`-top` 的自适应预检失败不再导致抓取被拒绝，而是作为 `selection.top_advisory {code, phase}` 报告（没有时省略）。只有当 `-top` 的预检通过且弦候选得分更高，或 `-top` 为 deferred 且弦候选已检查时，才选弦候选。`-top` 的构建没有 1.5 s 的期限。
- 夹爪余量按两侧分别检查。准入时计算物体在闭合轴方向上的带符号区间（偏心的轮廓算在其突出的一侧），要求扣除硬误差后每侧至少 3 mm 余量。适用于旧版 top-down 路径、`-top` 和弦候选的规划准入，以及自适应路径用实际位姿重新校验时。物体居中时结果与 1.6.0 的标量规则相同。
- 自适应弦抓取用手腕的实际位姿重新检查夹爪余量，并在插入动作所用的位姿上再检查一次。
- 仿真验证：规划一致性扫描、强制 `-top` 的派发一致性（相同阶段序列）、合并分支上抓取测试 135/135。真机抓取验证（宽、窄物体，两种策略）待做（G6，在桌面与手眼标定 E4 之后）。

### 工作空间返回规则

两种 owner 上行为一致。

- 地面、命名的禁区盒和自碰撞在所有运动中不允许加深，包括 Park（Park 的 1 mm 容差不再作用于这些限制）。
- 最大伸展限制（末端原点和 TCP）获得与外层工作空间面相同的 5 mm 临时容差，各限制单独跟踪。
- 起点已有任一限制被违反的运动，结束时每个限制都不得深于起点，且至少一个限制改善超过 0.1 mm；否则以 `WORKSPACE_VIOLATION` 拒绝（没有新错误码）。覆盖点动、Home、`move_joints`、已存姿态、关节路径与直线 `move_to`、相对移动，以及序列中的每个运动。对于伺服/遥操作/策略流，每一步不得重新进入或新增侵入，并跨帧保留已达到的最浅深度；静止和制动步允许。
- 评估从实测位姿开始；指令起点与实测不同时，也检查这段过渡。已准备好的运动在安装前，会用当前实测起点再检查一次规则；任一手臂关节漂移超过 20 mrad 时返回 `PLAN_STALE`（B601-DM 编码器噪声约 0.3 mrad）。
- Park 的平滑退出会加深地面、禁区盒或自碰撞侵入时，机械臂停在最后一个检查过的目标并带力矩保持，不锁存故障。Park 以 `WORKSPACE_VIOLATION` 失败，驾驶舱提示挡住的部件：先点动离开，再重新 Park。
- `WORKSPACE_VIOLATION` 回复只有在约束、部件和阶段属于该请求时才附带这些信息；否则只带错误码，驾驶舱显示通用提示。
- 仿真验证：两种 owner 上，从休息位姿点动、Home、Park、`move_to` 均被接受；B601-DM 与 SO-ARM101 的休息、home、park、inspect 位姿均在工作空间内；alloc 与 lock 测试 147/147。真机检查待做（G10）。

### 配置读锁

- legacy owner 的已发布配置快照分三步构建：在 supervisor 锁内采集（驱动能力用非阻塞借用），在锁外完成，仅当代数更新时才发布。主机测试中 supervisor 读锁最长持有 20 µs。驱动持续忙时，请求最多重试 50 ms，然后返回 `503 CONFIG_UNAVAILABLE`。延迟的采集不会覆盖更新的快照，也不会发布到 executor 的纪元中。
- 针对 1.6.0 浸泡测试中的 28.97 ms legacy 释放（`PublishedConfig::from_inner` 内 28.4 ms 的读锁持有）。真机默认使用 executor owner，本版本未在真机上测量 legacy owner 的读锁持有时间。

### 有人值守的测试开关

- `armd --test-fail-executor-startup` 强制触发可恢复的 executor 到 legacy 回退，用于测试 1.6.0 清单中的 D2。默认关闭，仅接受 `rebot-dm` follower 且 owner 为 executor 的组合，在打开硬件前校验，启用期间输出 ERROR 日志。init 脚本不能通过已保存的配置值启用它。仅在有人在机械臂旁时使用，之后去掉该开关重启。主机测试检查：所有权回到 legacy、tick 持续推进、未发送任何下电命令。真机上不掉落的保持和驾驶舱回退横幅：待做（G5）。

## 可能出乎意料的行为变化

- **预开口变宽。** 夹爪预开口现在至少为夹爪检查所需的开口：`max(原预开口, 准入最小开口)`。40 mm 物体的预开口由约 55 mm 增至约 66.5 mm，每侧与相邻物体的间隙减少约 5.7 mm。
- **旧版准入更严格。** 任一侧扣除硬误差后余量不足 3 mm 的 top-down 抓取会以 `OPENING` 拒绝，包括 1.6.0 会规划通过的情况。在重新做桌面和手眼标定（E4）之前，测试用香蕉这类宽物体可能被两种策略同时拒绝。
- **自适应在规划阶段不再拒绝 top-down 能接受的目标。** 1.6.0 中自适应可能拒绝 top-down 能规划的目标；现在 `-top` 走旧路径，回退到该路径。执行中的实时宽度检查与 1.6.0 相同。
- **起点在工作空间外的运动必须有净进展**（见“工作空间返回规则”）。深度不变或更深的侧向点动以 `WORKSPACE_VIOLATION` 拒绝。
- **Park 会加深**地面、禁区盒或自碰撞侵入时被拒绝。
- **deb 不再带独立驾驶舱页面。** 包内不再有 `/usr/share/rebot-teleop/index.html`。请在 `http://<设备>:8765` 打开驾驶舱。
- **关闭热点**在重启设备或重启服务后生效，不是立即生效。
- **legacy owner 上读取配置**在驱动持续忙超过 50 ms 时可能返回 `503 CONFIG_UNAVAILABLE`。
- **`rebot-teleop.config.json` 中的数值**（端口等）在传给 armd 之前会去掉首尾空白。

## 内部改动

- 驱动拆分，行为不变：`src/driver.rs` 从 30,709 行降到 2,054 行。legacy CAN 伺服和总线伺服的移动、Feetech 的 engine、poll、torque 模块，以及 Damiao 的 emitter、commissioning、modes、registers、MIT、torque、RX/TX 代码移入 `driver/` 子模块，并保留门面；`driver::*` 与 `protocol::*` 的再导出不变。公共提取（rest gate、反馈年龄、stop 检查）不在本版本。
- Supervisor 拆分，行为不变：`src/supervisor.rs` 从 24,077 行降到 6,769 行；驱动过渡、流、动作和终态捕获被拆分；工作空间评估移到 `supervisor/workspace.rs`，配置发布移到 `supervisor/config/published.rs`。RT 释放路径的提取和 executor 拆分不在本版本。
- 抓取模块在本线早期已拆分（planning、orchestrator、selection）。
- 驾驶舱页面源码拆成多个文件，在构建时组装（armd 用 Rust 组装器，测试用 Node 组装器）；deb 的各种变体使用各自独立的 cargo 输出目录。
- CI 用 `cargo nextest` 运行 Rust 测试，doctest 作为单独步骤；修复了测试中的时序竞争（断线测试、感知路由测试）。
- 源文件行数上限（约 1,500 行）在 CI 中检查，带棘轮式白名单；RT 与下电规则的扫描测试已更新以跟随移动后的代码。
- 发布线上的主机检查（`4dfe5908`；发布提交在其上增加了一处空白修复和版本号）：clippy 0 警告，nextest 2,902 / 2,902，doctest 29/29，WebSocket 回放 0 差异，alloc/lock 测试通过，riscv64（含与不含 `xthead-ncc`）和 wasm32 构建通过，源文件行数检查通过，7 个驾驶舱浏览器测试通过。

## 真机实测

B601-DM，reCamera SG2002，1.6.1-rc1（除版本号外与发布代码相同），executor owner，视觉运行中，无人在机械臂旁：

| 运行 | 释放耗时 | 跳过的截止 | 控制线程申请锁 | MIT 看门狗预算 | 故障 |
|---|---|---|---|---|---|
| J1 ±0.15 rad，speed scale 0.3，4 个来回，同时有观测、WebSocket、blackbox 和批量 HTTP 负载 | 最大 14.42 ms，p99 10.28 ms | 0 | 0 | 38.8 ms（上限 45 ms） | 0 |
| 10 分钟空闲浸泡（已 Park、力矩关闭），负载相同 | 最大 5.96 ms，p99 5.03 ms | 0 | 0 | 33.6 ms | 0 |

1.6.0 浸泡测试中在视觉运行时出现过 20.22 ms 的释放；以上运行均低于 20 ms。

## 已知限制

除特别说明外，沿用 1.6.0。

- **SO-ARM101 / Feetech 在 executor 上**本版本不可用。`auto` 仍把 SO-ARM101 放在 `legacy`；对它指定 `--owner executor` 会被拒绝。推迟到 1.6.2。
- **抓取实时证据。** legacy 抓取执行中的实时宽度检查沿用 1.6.0 的行为（未测得宽度时跳过）。把宽度、轴向和中心绑定到相机下转和重新居中之后的新观测的模型，推迟到 1.6.2。
- **指垫接触。** 两种策略共用的指垫接触规则（约 8 mm）推迟到 1.6.2，待测量 G8。
- **工作空间返回中本版本不含的部分。** 整条路径的区间认证、驾驶舱“返回路径无法验证”提示及较短点动建议、离线程的整体计划认证，推迟到 1.6.2。在此之前，无法检查的返回路径沿用 1.6.0 的措辞拒绝。
- **驾驶舱重连提示中的“armd 已重启”** 推迟到 1.6.2（观测数据中没有 boot id）。
- **释放路径与 executor 拆分。** 移动 RT 释放路径代码和拆分 `executor.rs` 推迟到 1.6.2。
- **Executor 释放预算。** 每次释放的硬截止和“先发保持帧”的排序仍不在本版本（1.6.0 已说明）。
- **拖动示教进入时的下沉**（约 1°，持续片刻）未修复。诊断：POS_VEL 切换到 MIT 时有一个采样周期的 J3 力矩空缺；先做 J2 `KP_APR` 试验（G2），进入时的修复计划在 1.6.2。
- **带电状态下停止服务**仍会锁存急停（1.6.0 已说明）。停止服务前先 Park。
- **运动中被拒的 Park。** 机械臂仍在运动时 Park 被拒，且没有一个制动步能留在工作空间内时，共用的制动回退会锁存 `ServoNoBrake`；需在驾驶舱清除。
- **掉电后的电机 TIMEOUT。** 机械臂电机掉电后 TIMEOUT 寄存器读回 0，armd 拒绝使能（`ENABLE_FAILED`，“TIMEOUT readback mismatch”）。rc1 测试中，这次失败的使能让 J1–J6 在休息位带力矩，且下电被拒。在休息位的恢复方法：断开电机、重启 armd，再用 `/api/v1/calibration/mit_timeout` 重写 TIMEOUT。重写时按每关节 0.05 rad 检查休息位，而配置文件的休息位允许 0.08 rad，手腕滚转落在两者之间时会被挡住。修复计划在 1.6.2。
- **关闭热点**后仅通过 USB 访问的情况未验证（G4）。
- **单视图 `measure`** 和测试机上的部分抓取，在重新做桌面和手眼标定（E4）之前仍会被拒绝。
- **部分向下运动时 USB 链路复位**（硬件问题，调查中）。
- 双臂和多臂支持不在本版本。

## 升级说明

- 用 `opkg install` 安装 deb（同 1.6.0）。owner 默认值不变（`auto` 对 `rebot-dm` 选择 executor）。
- 在 `:8765` 打开驾驶舱；读取设备上 `/usr/share/rebot-teleop/index.html` 的书签或脚本需要修改。
- 关闭设备热点：在 rebot-teleop 设置中把 `network.hotspot` 设为 `off` 并重启。先确保有另一种访问设备的方式（G4 待验证）。
- 依赖“每侧余量小于 3 mm 的 top-down 抓取可通过”或“40 mm 物体预开口约 55 mm”的脚本，需要在真机上重新检查（speed scale 0.3，用户在停止按钮旁）。
- 机械臂在工作空间外时，点动或运行运动的程序，除非该运动带来向内的净进展，否则会收到 `WORKSPACE_VIOLATION`；可使用 Park（但不能从会被其加深的禁区内 Park）或向内点动。
- 读取抓取 dry-run 的客户端可能看到新的可选字段 `selection.top_advisory`。
- `--test-fail-executor-startup` 仅用于有人值守的测试，不要写入服务配置。
